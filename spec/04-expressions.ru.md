# 04. Выражения

Этот файл описывает, чем выражения Anlang отличаются от выражений Go: убранные операции, адресуемость, переполнение целых, циклические и другие известные компилятору типы, сравнения, `nil`, вызовы, аргументы `...any`, замыкания, составные литералы и построение вариантов `enum`.

Там, где этот файл молчит, выражения ведут себя как в спецификации Go (см. [README](README.ru.md)).

**expr.go** — Выражение, не изменённое этим файлом, имеет синтаксис, правила типизации и смысл из спецификации Go. Программа, нарушающая правило типизации выражений спецификации Go, ДОЛЖНА быть отвергнута.

## 1. Убранные операции

**expr.removed.address** — Унарной операции взятия адреса `&` нет. Программа НЕ ДОЛЖНА содержать унарное выражение `&`.

**expr.removed.deref** — Унарной операции разыменования `*` нет. Программа НЕ ДОЛЖНА содержать унарное выражение `*`.

```
unary_op = "+" | "-" | "!" | "^" | "<-" .    (replaces Go)
```

**Примечание** — Типов указателей вне пакета `an/unsafe` нет ([02-types](02-types.ru.md), [06-memory](06-memory.ru.md)). Поэтому селекторы и вызовы методов никогда не разыменовывают неявно.

## 2. Адресуемость

Адресуемость определяет, какие операнды могут получить `inout`-доступ ([06-memory](06-memory.ru.md), **mem.inout.access**). Она заменяет понятие из Go, которое определено через указатели.

**expr.addr.def** — Операнд *адресуем* тогда и только тогда, когда он одно из следующего:

1. переменная, объявленная в теле функции, включая параметр и результат;
2. `inout`-параметр или `inout`-получатель;
3. `inout`-переменная цикла ([05-statements](05-statements.ru.md), **stmt.range.inout**);
4. селектор поля `x.f`, где `x` — адресуемый операнд-структура;
5. индексное выражение `a[i]`, где `a` — адресуемый операнд-массив;
6. индексное выражение `s[i]`, где `s` — адресуемый операнд-срез;
7. выражение среза `s[lo:hi]` или `s[lo:hi:max]`, где `s` — адресуемый срез или массив; как `inout`-аргумент оно обозначает поддиапазон `s` ([06-memory](06-memory.ru.md), **mem.inout.subslice**);
8. отображение железа уровня пакета в профиле `core` ([06-memory](06-memory.ru.md), **mem.unsafe.map**).

Переменные уровня пакета с типами синхронизации не адресуемы: ими пользуются только через их операции ([06-memory](06-memory.ru.md), **mem.global.kinds**).

**expr.addr.map** — Индексное выражение словаря `m[k]` не адресуемо. Программа НЕ ДОЛЖНА передавать его как `inout`-аргумент, вызывать у него метод с `inout`-получателем или присваивать его полям и элементам. Присваивание самому `m[k]` разрешено, как в Go.

**Примечание** — В Go индексное выражение среза всегда адресуемо, потому что срез ссылается на общую память. В Anlang срез — значение ([06-memory](06-memory.ru.md), **mem.cow.slice**), поэтому его элементы адресуемы только через адресуемый срез.

## 3. Целочисленная арифметика

### 3.1 Проверяемая арифметика

Целые типы перечислены в [02-types](02-types.ru.md). В этом разделе *проверяемый целый тип* — любой целый тип, кроме типов пакета `an/wrap`.

**expr.int.checked** — Для операндов проверяемого целого типа бинарные операции `+`, `-`, `*`, унарный `-`, операторы `++`, `--` и соответствующие присваивания (`+=`, `-=`, `*=`) дают математический результат. Если математический результат не представим в типе операнда, операция *переполняется*.

**expr.int.div** — Для проверяемых целых типов `x / y` и `x % y` ведут себя как в Go, но `x / -1` и `x % -1`, где `x` — минимальное значение знакового типа, переполняются. Деление на ноль вызывает панику, как в Go.

**expr.int.overflow** — Переполнившаяся операция НЕ ДОЛЖНА давать значение. Реализация ДОЛЖНА либо доказать при компиляции, что переполнения не будет, либо вставить проверку во время выполнения, которая при переполнении вызывает панику. Функция с такой проверкой получает эффект `Panic` ([07-effects](07-effects.ru.md)).

**expr.int.overflow-forbidden** — Там, где эффект `Panic` запрещён (например, в обработчиках `interrupt` и `trap` или ограничением профиля либо `anlang.mod`), операция, отсутствие переполнения в которой не доказано, — ошибка компиляции. Диагностика ДОЛЖНА назвать операцию.

**expr.int.shift** — Сдвиги проверяемых целых типов ведут себя как в Go: выдвинутые биты отбрасываются, и операция не переполняется.

**expr.int.const** — Константные выражения вычисляются точно, как в Go. Типизированная константа, значение которой не представимо в её типе, — ошибка компиляции.

**Примечание** — Действие паники задаёт цель (`OnPanic`, [13-targets](13-targets.ru.md)).

### 3.2 Границы индексов и срезов

**expr.bounds.check** — Индексные выражения и выражения срезов для массивов, срезов и строк требуют, чтобы индексы были в диапазоне, как в Go. Правило **expr.int.overflow** применяется к ним так же: реализация ДОЛЖНА либо доказать, что индексы в диапазоне, либо вставить проверку с паникой, и тогда содержащая функция получает эффект `Panic`.

### 3.3 Явный перенос, насыщение и проверка

**expr.bits.functions** — Обобщённые функции пакета `an/bits` принимают операнды любого проверяемого целого типа `T` и возвращают:

| Функция | Результат |
| --- | --- |
| `bits.WrappingAdd(a, b T) T`, `WrappingSub`, `WrappingMul` | математический результат по модулю 2ⁿ, где n — разрядность `T`, интерпретированный в `T` |
| `bits.SaturatingAdd(a, b T) T`, `SaturatingSub`, `SaturatingMul` | математический результат, ограниченный диапазоном `T` |
| `bits.CheckedAdd(a, b T) (T, bool)`, `CheckedSub`, `CheckedMul` | математический результат и `true`, если он представим; иначе нулевое значение и `false` |

Эти функции никогда не вызывают панику и не имеют эффектов.

### 3.4 Циклические типы

**expr.wrap.ops** — Для операндов типов пакета `an/wrap` (`wrap.U8` … `wrap.U64`, `wrap.I8` … `wrap.I64`) операции `+`, `-`, `*`, унарный `-` и `<<`, соответствующие присваивания и `++`, `--` дают математический результат по модулю 2ⁿ, интерпретированный в типе операнда. Эти операции никогда не вызывают панику.

**expr.wrap.other-ops** — Операции `&`, `|`, `^`, `&^`, `>>`, `/`, `%` и сравнения на циклических типах ведут себя как на целом типе того же размера и знаковости. Деление на ноль вызывает панику.

**expr.wrap.mixing** — Оба операнда бинарной операции над циклическим типом ДОЛЖНЫ иметь один и тот же циклический тип. Нетипизированная константа приводится к этому типу и ДОЛЖНА быть представима в целом типе того же размера и знаковости. Смешение циклического типа с любым другим целым типом требует явного преобразования.

**expr.wrap.convert** — Циклический тип и целый тип того же размера и знаковости явно преобразуются друг в друга без проверки диапазона; битовое представление сохраняется.

```go
var h wrap.U64 = 0xcbf29ce484222325
h = (h ^ wrap.U64(b)) * 0x100000001b3   // переносит, никогда не паникует
return u64(h)
```

## 4. Арифметика с плавающей точкой

**expr.float.ieee** — Операции над `f32` и `f64` следуют IEEE 754 binary32 и binary64 с округлением к ближайшему чётному, как в Go.

**expr.float.target** — Если цель объявляет `Floats: none`, программа НЕ ДОЛЖНА содержать выражений типа `f32` или `f64`. Если цель объявляет `Floats: soft`, реализация ДОЛЖНА эмулировать операции с результатами, совпадающими с **expr.float.ieee** ([13-targets](13-targets.ru.md)).

**expr.float.to-int** — Преобразование значения с плавающей точкой в целый тип отбрасывает дробную часть (округление к нулю). Если значение — NaN или результат не представим в целевом типе, преобразование переполняется и применяется **expr.int.overflow**.

## 5. Известные компилятору типы с операциями

**expr.known.closed** — Операции определены только для предопределённых типов, как в Go, и для типов, перечисленных в этом разделе. Программа не может определить операции для своих типов.

**expr.known.simd** — Векторные типы пакета `an/simd` (`simd.F32x4`, `simd.U8x16` и другие) поддерживают арифметические операции своего типа элемента, применяемые поэлементно к операндам одного векторного типа. Реализация отображает их на векторные команды цели или на скалярный код; результат ДОЛЖЕН совпадать.

**expr.known.fixed** — Типы с фиксированной точкой пакета `an/fixed` (`fixed.Q16`, `fixed.Q8` и другие) поддерживают `+`, `-`, `*`, `/`, унарный `-` и сравнения. `+`, `-` и унарный `-` следуют **expr.int.checked** на внутреннем представлении; `*` и `/` дают точный результат, усечённый к нулю до точности типа, и переполняются, если он вне диапазона.

**expr.known.wrap** — Циклические типы описаны в §3.4.

## 6. Сравнения

**expr.cmp.go** — Операции сравнения и сравнимость следуют Go с дополнениями из этого раздела.

**expr.cmp.enum** — Значение типа `enum` сравнимо, если сравнимы типы данных всех его вариантов. Два значения равны, если в них один и тот же вариант и данные равны поле за полем.

**expr.cmp.secret** — Значения типа `Secret[T]` несравнимы; см. **safe.secret.no-eq** в [11-data-safety](11-data-safety.ru.md).

**expr.cmp.sync** — Значения типов синхронизации ([02-types](02-types.ru.md)) несравнимы, за исключением того, что канал можно сравнивать с `nil`.

**expr.cmp.nil** — Значение можно сравнивать с `nil`, если его тип — интерфейс, срез, словарь, канал или функция.

**expr.cmp.nil-empty** — Для среза или словаря `x == nil` истинно тогда и только тогда, когда `len(x) == 0`.

**Примечание** — В Anlang `nil` для среза или словаря — просто пустое значение ([02-types](02-types.ru.md)), поэтому различия Go между нулевым и пустым срезом нет.

## 7. Идентификатор `nil`

**expr.nil.context** — Предопределённый идентификатор `nil` МОЖЕТ встречаться только там, где из контекста определяется его тип — интерфейс, срез, словарь, канал или функция. Он обозначает нулевое значение этого типа.

**expr.nil.call** — Вызов метода у операнда-интерфейса или вызов операнда функционального типа требует доказать, что операнд не `nil`; см. **mem.nil.call** в [06-memory](06-memory.ru.md).

## 8. Селекторы и значения-методы

**expr.sel.no-deref** — Селектор `x.f` выбирает поле или метод самого `x`. Неявного разыменования нет.

**expr.method.inout-call** — Метод с `inout`-получателем МОЖЕТ вызываться только у адресуемого операнда ([§2](#2-адресуемость)). Вызов `x.M(args)` равносилен `T.M(x, args)`, где `x` передаётся как `inout`-получатель.

**expr.method.inout-value** — Значение-метод `x.M` или выражение-метод `T.M` с `inout`-получателем МОЖЕТ использоваться только как вызываемое в немедленном вызове. Программа НЕ ДОЛЖНА сохранять, передавать, возвращать или преобразовывать такое значение-метод.

**expr.method.interface-inout** — Метод с `inout`-получателем входит в набор методов типа получателя `T`. Его вызов через значение-интерфейс требует, чтобы операнд-интерфейс был адресуем; вызов изменяет копию, которую хранит значение-интерфейс.

## 9. Вызовы

### 9.1 Аргументы

**expr.call.value-arg** — Аргумент для параметра-значения — логическая копия значения аргумента ([06-memory](06-memory.ru.md), **mem.value.copy**).

**expr.call.inout-arg** — Аргумент для `inout`-параметра ДОЛЖЕН быть адресуемым операндом. В точке вызова никакой пометки не пишется. `inout`-доступ к аргументу начинается в начале вызова и заканчивается при возврате ([06-memory](06-memory.ru.md), **mem.inout.access**).

**expr.call.inout-overlap** — Два `inout`-аргумента одного вызова НЕ ДОЛЖНЫ пересекаться ([06-memory](06-memory.ru.md), **mem.inout.overlap**). Операнд, переданный в одном вызове и как `inout`-аргумент, и как аргумент-значение, допустим: аргумент-значение копируется до начала вызова.

**expr.call.order** — Аргументы вычисляются в порядке, заданном в Go. Путь операнда `inout`-аргумента (например, индекс в `xs[i]`) вычисляется в том же порядке.

### 9.2 Аргументы `...any`

**expr.call.any-variadic** — Последний параметр вида `args ...any` — *кортеж, известный при компиляции*. В каждой точке вызова кортеж состоит из оставшихся аргументов с их статическими типами. Функция с таким параметром инстанцируется отдельно для каждой различной последовательности типов аргументов, как для параметров-типов. Механика инстанцирования и обхода кортежа описана в [10-compile-time](10-compile-time.ru.md).

**expr.call.any-forward** — Внутри функции с параметром `args ...any` этот параметр МОЖЕТ использоваться только:

1. как выражение диапазона в операторе `for const` ([10-compile-time](10-compile-time.ru.md));
2. как операнд `len`, результат которого тогда константа;
3. как последний аргумент `args...` вызова другой функции, последний параметр которой — `...any`; кортеж передаётся без изменений.

**expr.call.any-spread** — Срез НЕ ДОЛЖЕН передаваться как `xs...` в параметр `...any`.

**expr.call.variadic** — Последний параметр `...T`, где `T` — не `any`, ведёт себя как в Go.

### 9.3 Результаты

**expr.call.error-result** — На вызов, среди результатов которого есть значение `error`, распространяется **stmt.error.unused** ([05-statements](05-statements.ru.md)).

**expr.call.type-assert** — Однозначная форма приведения типа `x.(T)` при неудаче вызывает панику, как в Go, и даёт содержащей функции эффект `Panic`. Форма «значение, ok» `v, ok := x.(T)` никогда не вызывает панику.

## 10. Замыкания

**expr.closure.capture-copy** — Функциональный литерал захватывает каждую используемую им переменную объемлющей функции по значению в момент вычисления литерала. Последующие присваивания этой переменной в объемлющей функции замыканию не видны.

**expr.closure.captured-readonly** — Функциональный литерал НЕ ДОЛЖЕН присваивать захваченной переменной, применять к ней `++` или `--`, брать к ней `inout`-доступ или вызывать у неё метод с `inout`-получателем.

**expr.closure.loop** — Каждая итерация цикла `for` объявляет новые переменные цикла, как в Go 1.22 и позже; замыкание, созданное на итерации, захватывает значения этой итерации.

**expr.closure.sync** — Захваченное значение типа синхронизации — дескриптор того же объекта ([06-memory](06-memory.ru.md), **mem.sync.handle**). Операции над ним через замыкание действуют на общий объект.

**expr.closure.capture-inout** — Функциональный литерал, использующий `inout`-параметр, `inout`-получатель или `inout`-переменную цикла объемлющей функции, захватывает их по ссылке, а не копией, и МОЖЕТ их изменять. Такое функциональное значение — *второго класса* ([06-memory](06-memory.ru.md), **mem.ref.second-class**): его МОЖНО только вызывать напрямую в функции, где оно создано, и программа НЕ ДОЛЖНА его сохранять, передавать, возвращать, отправлять или преобразовывать.

```go
func Count(n inout int, xs []i32) {
    add := func(v i32) { n += int(v) }   // захватывает n по ссылке
    for _, x := range xs {
        add(x)                           // разрешено: прямой вызов
    }
    // go add(1)                         // ошибка: замыкание второго класса
}
```

## 11. Составные литералы и варианты `enum`

**expr.lit.go** — Составные литералы ведут себя как в Go, кроме описанного ниже.

**expr.lit.no-zero** — Если литерал структуры пропускает поле, тип которого не имеет нулевого значения ([02-types](02-types.ru.md)), литерал — ошибка компиляции.

**expr.lit.type-invariant** — Литерал структуры типа с инвариантом типа — граница, на которой проверяется инвариант ([08-contracts](08-contracts.ru.md)).

**expr.variant.scope** — Имена вариантов типа `enum` объявляются в том блоке, где объявлен тип. К варианту `enum` из другого пакета обращаются через квалифицированный идентификатор (`shapes.Circle`).

**expr.variant.construct** — Значение варианта записывается так:

1. именем варианта — для варианта без данных: `Inc`, `None`;
2. составным литералом с именем варианта в роли типа — для варианта с данными: `Circle{r: 1.0}` или `Circle{1.0}`. Формы с ключами и позиционная следуют правилам литералов структур;
3. записью вида преобразования `V(x)` — для варианта, данные которого состоят ровно из одного поля: `Some(root)` равносильно `Some{root}`.

Тип значения варианта — тип `enum`, а не отдельный тип.

```
VariantLit = VariantName | VariantName LiteralValue | VariantName "(" Expression [ "," ] ")" .   (new)
VariantName = identifier | QualifiedIdent .                                                       (new)
```

**Примечание** — Синтаксически каждая форма `VariantLit` — это также `Operand`, `CompositeLit` или `Conversion` грамматики Go. Парсер принимает её как таковую; при проверке типов, когда имя разрешается в вариант, она интерпретируется как литерал варианта.

**expr.variant.infer** — Для обобщённого типа `enum` аргументы-типы значения варианта выводятся из данных, а если у варианта данных нет — из типа, требуемого контекстом. Если вывести их нельзя, выражение — ошибка компиляции.

```go
var p Option[arena.Ref[Node]] = None       // выведено из контекста
child := Node{parent: Some(root)}           // выведено из root
```
