# 12. Взаимодействие с внешним кодом

Область: `ffi`.

Kern вызывает внешний код в стиле purego из Go: без компилятора C, без разбора заголовков и без генераторов привязок. Внешняя функция объявляется обычной сигнатурой Kern и связывается с символом из динамической библиотеки при запуске программы, из объектного файла при сборке или с фиксированным адресом. Инструментарий остаётся одним исполняемым файлом `kern`, и кросс-компиляция не требует других инструментов.

## 12.1 Объявления внешних функций

Форма объявления `func` *FunctionName* *Signature* `=` *Expression* — функция без тела, связанная с символом, — определена в [03-declarations](03-declarations.ru.md). Этот раздел определяет выражение связывания и правила для таких функций.

**ffi.decl.binding** — Выражение после `=` ДОЛЖНО быть вызовом, вычислимым при компиляции (см. [10-compile-time](10-compile-time.ru.md)), одного из:

| Связывание | Источник символа |
| --- | --- |
| `lib.Symbol(name [, effects])`, где `lib` — константа `ffi.Library` | динамическая библиотека, загружаемая при старте программы |
| `obj.Symbol(name [, effects])`, где `obj` — константа `ffi.Static` | объектный файл, компонуемый в программу при сборке |
| `ffi.At(address [, effects])` | фиксированный адрес в ПЗУ, BIOS или отдельно прошитом стеке |
| `js.Import(module, name [, effects])` | импорт WebAssembly на платформе `web` |

`name` и `module` — строковые константы; `effects` — константа `ffi.Effects`.

**ffi.decl.no-generics** — Внешняя функция НЕ ДОЛЖНА иметь параметров-типов, НЕ ДОЛЖНА быть методом и НЕ ДОЛЖНА иметь вариадического параметра.

**ffi.decl.package-local** — Внешнюю функцию МОЖНО вызывать и использовать как функциональное значение только внутри объявившего её пакета. Вызов из другого пакета — ошибка компиляции независимо от имени функции. Наружу пакет отдаёт обычные обёртки на Kern.

**ffi.decl.variadic-c** — Функция C с переменным числом аргументов объявляется отдельно для каждого списка аргументов, который использует программа; у каждого объявления своё имя в Kern и фиксированная сигнатура.

```go
package sqlite

import "kern/ffi"

const lib = ffi.Library{
    Linux:   "libsqlite3.so.0",
    MacOS:   "/usr/lib/libsqlite3.dylib",
    Windows: "sqlite3.dll",
    Android: "libsqlite3.so",
}

func sqlite3_open(path cstring, db inout ffi.Handle) i32 = lib.Symbol("sqlite3_open", ffi.Effects{File})
func sqlite3_close(db ffi.Handle) i32                    = lib.Symbol("sqlite3_close", ffi.Effects{File})
```

## 12.2 Эффекты внешних функций

**ffi.effects.declared** — Эффекты внешней функции — эффекты, перечисленные в аргументе `ffi.Effects` её связывания. Компилятор не может их проверить.

**ffi.effects.foreign** — Если у связывания нет аргумента `ffi.Effects`, функция имеет единственный эффект `Foreign`.

**ffi.effects.foreign-deny** — `Foreign` означает «может всё». Граница, запрещающая хотя бы один эффект, — профиль, цель, ограничение в `kern.mod`, `effect.Without(...)`, обработчик `interrupt` или `trap` — отвергает и `Foreign` (см. [07-effects](07-effects.ru.md)).

**ffi.effects.unverified** — Реализации ДОЛЖНЫ отмечать объявленные эффекты внешних функций как непроверенные в отчётах об эффектах, в ответах `kern query` и в выводе `kern diff` и ДОЛЖНЫ сообщать об их изменениях отдельно от выведенных эффектов (см. [20-toolchain](20-toolchain.ru.md)).

**ffi.effects.callback** — Когда значение `ffi.Callback(f)` передаётся во внешнюю функцию, эффекты `f` добавляются к эффектам этого вызова и засчитываются вызывающему, как для любой функции, переданной аргументом (см. [07-effects](07-effects.ru.md)).

## 12.3 Источники символов

### 12.3.1 `ffi.Library`: динамические библиотеки

**ffi.lib.desc** — `ffi.Library` — структурный тип с одним полем `string` на каждую платформу с динамической загрузкой — `Linux`, `MacOS`, `IOS`, `Windows`, `Android` — и полем `Optional` типа `bool`. Поле содержит имя или путь библиотеки на этой платформе. Описатель библиотеки ДОЛЖЕН быть объявлен константой.

**ffi.lib.platforms** — Связывания `ffi.Library` доступны на Linux, Android, macOS, iOS и Windows. Если функция, связанная с библиотекой, достижима в сборке под платформу, поле которой пусто или у которой нет динамической загрузки, сборка завершается ошибкой.

**ffi.lib.load** — Каждая обязательная библиотека (без `Optional: true`), у которой есть достижимая связанная функция, ДОЛЖНА быть загружена, а каждый такой символ — найден до запуска `main`. Если библиотеки или символа нет, программа НЕ ДОЛЖНА запускаться: она сообщает обо всех отсутствующих библиотеках и символах и завершается с ненулевым кодом.

**ffi.lib.optional** — Для библиотеки с `Optional: true` отсутствие библиотеки или символов не мешает запуску. `lib.Available() bool` сообщает, загружены ли библиотека и все её достижимые символы. Вызов функции недоступной необязательной библиотеки вызывает панику; у таких функций, помимо объявленных эффектов, есть эффект `Panic`.

### 12.3.2 `ffi.Static`: объектные файлы

**ffi.static.desc** — `ffi.Static` — структурный тип с одним полем `string` на каждую архитектуру, названным как константа архитектуры (`I8086`, `ARMv7M`, `X86_64`, `ARM64`, `RISCV32`, …; см. [13-targets](13-targets.ru.md)). Поле содержит путь к объектному файлу или архиву для этой архитектуры относительно корня модуля. Описатель ДОЛЖЕН быть объявлен константой.

**ffi.static.availability** — Связывания `ffi.Static` доступны на всех целях, включая DOS, микроконтроллеры и ядра. Если функция, связанная с описателем `ffi.Static`, достижима в сборке под архитектуру, поле которой пусто, сборка завершается ошибкой.

**ffi.static.formats** — Инструментарий `kern` ДОЛЖЕН содержать компоновщик перемещаемых объектных файлов и архивов в форматах ELF, Mach-O и COFF. Компилятор C и внешний компоновщик не используются.

**ffi.static.abi-check** — Инструментарий ДОЛЖЕН проверять при сборке, что каждый объектный файл соответствует архитектуре и C ABI цели (тип машины, размер слова, порядок байтов, ABI дробных чисел). Несоответствие — ошибка сборки.

**ffi.static.unresolved** — Неопределённые символы компонуемого объектного файла разрешаются по другим объектам `ffi.Static` программы. Каждый оставшийся неразрешённым символ — ошибка сборки с указанием объектного файла и символа.

**ffi.static.location** — Объектные файлы — часть проекта. Их код нельзя прочитать, поэтому добавление или замена такого файла — решение человека, проверяющего изменения; инструментарий не отслеживает их происхождение и лицензию.

### 12.3.3 `ffi.At`: фиксированные адреса

**ffi.at.platforms** — Связывания `ffi.At` доступны только на платформах без динамической загрузки: `dos` и `bare` (см. [13-targets](13-targets.ru.md)). На других платформах они — ошибка компиляции.

**ffi.at.address** — Адрес ДОЛЖЕН быть константой в форме адреса кода целевой архитектуры: `usize` на архитектурах с плоской адресацией, дальний адрес вроде `i8086.Far(segment, offset)` на сегментных.

### 12.3.4 `js.Import`: импорты WebAssembly

**ffi.js.platform** — Связывания `js.Import` доступны только на платформе `web`. Каждое становится импортом создаваемого модуля WebAssembly с заданными именами модуля и поля.

### 12.3.5 Сводка по платформам *(справочный)*

| Платформа | Источник символа |
| --- | --- |
| Linux, Android | `dlopen` / `dlsym` |
| macOS, iOS | `dlopen` / `dlsym`; системные фреймворки; рантайм Objective-C через `objc_msgSend`, объявляемый для каждой сигнатуры |
| Windows | `LoadLibrary` / `GetProcAddress` |
| Android, Java-API | указатели на функции из таблицы функций JNI |
| web | импорты WebAssembly: `= js.Import("console", "log")` |
| DOS, микроконтроллеры, ядра | динамической загрузки нет: `ffi.Static`, `ffi.At` для ПЗУ и таблиц загрузчика; программные прерывания через `asm` или пакет команд архитектуры |

## 12.4 Соглашение о вызовах

**ffi.abi.c** — Внешние функции и колбэки используют C ABI цели, взятый из описаний архитектуры и платформы (см. [13-targets](13-targets.ru.md)). Внутренний ABI Kern МОЖЕТ отличаться.

**ffi.abi.blocking** — Вызов внешней функции может блокировать выполнение. Как планировщик обращается с долгими блокирующими вызовами, определено в [09-concurrency](09-concurrency.ru.md).

## 12.5 Передаваемые типы

**ffi.types.params** — Параметр внешней функции ДОЛЖЕН иметь один из следующих типов:

| Тип Kern | На стороне внешнего кода |
| --- | --- |
| `i8` … `i64`, `u8` … `u64`, `int`, `uint`, `usize` | целый тип той же ширины и знаковости |
| `f32`, `f64` | `float`, `double` |
| `bool` | `_Bool` в C |
| `ffi.Handle` | непрозрачный указатель на объект библиотеки; нулевое значение — нулевой указатель |
| `cstring` | `const char*` с завершающим NUL |
| структура с `layout c`, все поля которой передаваемы | структура по значению |
| `[]T`, где `T` передаваем и не является срезом | указатель на первый элемент, только для чтения |
| `inout T`, где `T` — передаваемый тип, не срез | указатель на значение на время вызова |
| `inout []T` | указатель на первый элемент, доступный для записи |
| `ffi.Callback` | указатель на функцию |

**ffi.types.results** — Результат внешней функции ДОЛЖЕН быть числовым типом, `bool`, `ffi.Handle` или структурой с `layout c`, поля которой числовые, `bool` или `ffi.Handle`. Внешняя функция МОЖЕТ не иметь результата. Несколько результатов не допускаются.

**ffi.types.no-pointers** — В объявлениях внешних функций и при их вызове нет типов указателей `*T` и операции взятия адреса `&x`.

**ffi.types.no-wrappers** — `Secret[T]`, `Untrusted[T]`, типы синхронизации, интерфейсы, словари, строки (кроме `cstring`), функциональные значения (кроме `ffi.Callback`) и типы `enum` не передаваемы.

### 12.5.1 Память во время вызова

**ffi.mem.pinned** — Память, переданная через параметр-срез, `inout` или `cstring`, ДОЛЖНА оставаться по тому же адресу на время вызова.

**ffi.mem.readonly** — Внешний код НЕ ДОЛЖЕН писать через указатель, полученный из параметра `[]T` или `cstring`. От этого зависит семантика значений; компилятор не может это проверить.

**ffi.mem.unique** — Перед вызовом с аргументом `inout []T` реализация ДОЛЖНА сделать буфер среза уникальным (копирование при записи, см. [06-memory](06-memory.ru.md)), чтобы запись внешним кодом не была видна через другие копии.

**ffi.mem.no-retain** — Внешний код НЕ ДОЛЖЕН сохранять указатель, полученный из параметра, после возврата из вызова. Компилятор не может проверить и это.

**ffi.mem.empty-slice** — Для пустого среза значение указателя не определено, и внешний код НЕ ДОЛЖЕН его разыменовывать; длину программа передаёт отдельно.

**ffi.mem.cstring** — `ffi.CString(s string) cstring` создаёт копию `s` с завершающим NUL; у неё эффект `Alloc`, и она паникует, если `s` содержит байт NUL. `ffi.GoString(h ffi.Handle) string` копирует строку с завершающим NUL из внешней памяти.

### 12.5.2 Колбэки

**ffi.callback.make** — `ffi.Callback(f)` создаёт указатель на функцию, который может вызывать внешний код. `f` ДОЛЖНА быть необобщённой функцией верхнего уровня с передаваемыми типами параметров и результатов.

**ffi.callback.lifetime** — Колбэк остаётся действительным до завершения программы. Число создаваемых колбэков ограничено константой, определяемой реализацией, не меньше 1024; создание сверх неё вызывает панику.

**ffi.callback.context** — Когда внешний код вызывает колбэк из потока, созданного не рантаймом Kern, рантайм ДОЛЖЕН выполнить колбэк как задачу с приоритетом `Normal` и вернуть результат вызывающему.

```go
type DB struct {
    h ffi.Handle
}

func Open(path string) (DB, error) {
    var h ffi.Handle
    rc := sqlite3_open(ffi.CString(path), h)        // inout: адрес передаётся на время вызова
    if rc != 0 {
        return DB{}, sqliteError(rc)
    }
    return DB{h}, nil
}
```

## 12.6 Что не поддерживается

**ffi.unsupported** — В Kern не входят:

- разбор C-заголовков — объявления пишутся вручную, обычно ИИ по документации библиотеки;
- макросы и `inline`-функции C — их логика переписывается на Kern;
- компиляция исходников на C — в проекте лежат только код на Kern и готовые объектные файлы;
- экспорт кода Kern как C-библиотеки — на первом этапе достаточно колбэков.

**Примечание** — В инструментарии нет компилятора C, внешнего компоновщика и SDK других языков. Исключение — подпись приложений iOS инструментами Apple (см. [17-ui](17-ui.ru.md)).

## Открытые вопросы

1. **Вызов функции недоступной необязательной библиотеки.** *Предварительно:* паника и эффект `Panic` (**ffi.lib.optional**).
2. **Неразрешённые символы объектных файлов, которым нужна библиотека C** (например, `memcpy`). *Предварительно:* ошибка сборки, если их не предоставляет другой объект `ffi.Static` (**ffi.static.unresolved**).
3. **Строки, возвращаемые внешним кодом.** *Предварительно:* возвращаются как `ffi.Handle` и копируются через `ffi.GoString`.
4. **Связывание элементов таблицы функций JNI и селекторов Objective-C.** `kern.md` говорит «те же объявления», но не даёт формы связывания. *Предварительно:* `objc_msgSend` объявляется для каждой сигнатуры через `lib.Symbol`; форма связывания для элементов таблицы JNI открыта.
5. **Предел колбэков и потоки.** `kern.md` говорит только, что число живых колбэков ограничено, как в purego. *Предварительно:* не меньше 1024, никогда не освобождаются, чужие потоки выполняют колбэки как задачи (**ffi.callback.lifetime**, **ffi.callback.context**).
