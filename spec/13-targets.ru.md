# 13. Цели

Область: `target`.

Цель сборки сочетает три независимых описания: **архитектуру**, **платформу** и один или несколько **форматов бинарника**. Все три — декларативные данные в виде констант на Anlang, в стандартной библиотеке или в проекте. Добавление архитектуры не требует изменения компилятора.

| Слой | Описывает | Примеры |
| --- | --- | --- |
| Архитектура | команды, регистры, размер слова, виды указателей, соглашения о вызовах, время выполнения | `i8086`, `x86_64`, `armv6m`, `armv7m`, `avr`, `msp430`, `riscv32`, `riscv64`, `arm64`, `wasm32` |
| Платформа | что даёт окружение: эффекты, ABI, точку входа, динамическую загрузку | `dos`, `bare`, `linux`, `windows`, `macos`, `ios`, `android`, `web` |
| Формат | структуру выходного файла | `flat` (.COM), `mz` (.EXE), ELF, PE, Mach-O, wasm, BIN, Intel HEX, UF2 |

Шейдерные цели для функций GPU (`spirv`, `wgsl`, `msl`) определены в [16-gpu](16-gpu.ru.md).

## 13.1 Пакеты целей

**target.pkg.description** — *Пакет цели* — пакет, объявляющий экспортируемую константу `Description` типа `target.Desc` (пакет `an/target`). Константа вычисляется при компиляции (см. [10-compile-time](10-compile-time.ru.md)); опечатка в имени поля или значение неверного типа — обычная ошибка компиляции.

**target.pkg.name** — *Имя цели* — последний элемент пути каталога пакета цели. Имя каталога МОЖЕТ содержать дефисы, например `an/target/dos-com` с объявлением `package doscom`.

**target.pkg.location** — Стандартные цели — пакеты под `an/target/`. Проект МОЖЕТ объявлять свои пакеты целей в любом месте модуля, например `myprogram/boards/myboard`.

**target.pkg.pure** — Пакет цели НЕ ДОЛЖЕН иметь эффектов, кроме допустимых при вычислении во время компиляции (**ct.eval.evaluable**). Он МОЖЕТ читать файлы в своём каталоге, например SVD-файл (**ct.eval.read-input**).

```go
package doscom

import (
    "an/arch"
    "an/effect"
    "an/platform"
    "an/target"
)

const Description = target.Desc{
    Arch:     arch.I8086,
    Platform: platform.DOS,
    Word:     16,
    Pointers: target.Pointers{Near: 16, Far: 32},
    Formats:  []target.Format{target.Flat{Origin: 0x100, MaxSize: 65280}},
    Floats:   target.SoftFloat,
    Provides: []effect.Effect{effect.Console, effect.Video, effect.File, effect.Keyboard, effect.Clock, effect.StaticAlloc},
    Lacks:    []effect.Effect{effect.Network},
    OnPanic:  target.PrintAndExit,
}
```

## 13.2 Схема `target.Desc`

| Поле | Тип | Обязательно | Смысл |
| --- | --- | --- | --- |
| `Arch` | `arch.Arch` | да | описание архитектуры (13.5) |
| `Platform` | `platform.Platform` | да | описание платформы (13.4) |
| `Word` | `int` | нет; по умолчанию из `Arch` | ширина `int` и `uint` в битах: 16, 32 или 64 |
| `Pointers` | `target.Pointers` | нет; по умолчанию из `Arch` | ширины видов указателей (13.6) |
| `Formats` | `[]target.Format` | да, хотя бы один | выходные форматы (13.9) |
| `Floats` | `target.FloatSupport` | нет; по умолчанию из `Arch` | `target.HardFloat`, `target.SoftFloat` или `target.NoFloat` (13.7) |
| `Memory` | `[]target.Region` | да на `bare`; иначе нет | области памяти (13.8) |
| `Stack` | размер в байтах | да на `bare`; иначе нет | размер стека `main` (13.8) |
| `Device` | `target.Device` | нет | периферия, регистры и прерывания, обычно `svd.Load(file)` (см. [14-embedded](14-embedded.ru.md), **emb.device.schema**) |
| `Provides` | `[]Effect` | да | эффекты окружения, доступные на цели (13.3) |
| `Lacks` | `[]Effect` | нет | эффекты окружения, явно отсутствующие (13.3) |
| `OnPanic` | `target.PanicAction` | нет; по умолчанию из `Platform` | что делает паника (13.10) |
| `Clock` | частота в Гц | нет; обязательно для `wcet.Within` | тактовая частота процессора, которая вместе с моделью времени архитектуры используется для WCET (см. [14-embedded](14-embedded.ru.md), **emb.wcet.model**) |

**target.desc.types** — Пакет `an/target` объявляет `Desc` и типы его полей. `target.Pointers` — это `arch.Pointers`, а `target.PanicAction` — `platform.PanicAction` (13.4.1). Поле с нулевым значением получает значение по умолчанию: `Word` и `Pointers` — из `Arch`, `Floats` (нулевое значение `target.DefaultFloats`) — из `Arch`, `OnPanic` (нулевое значение `target.DefaultPanic`) — из `Platform`. Эффекты окружения — константы пакета `an/effect`. Тип поля `Device` — `target.Device` (**emb.device.schema**). Пакет цели, который вызывает `svd.Load`, — в профиле `app`, потому что `an/svd` выделяет память; пакеты целей читает только инструментарий.

**target.desc.valid** — Реализация ДОЛЖНА отвергать описание цели, нарушающее схему: отсутствует обязательное поле, `Word` вне {16, 32, 64}, значение `Word` или `Pointers`, которое архитектура не поддерживает, пересекающиеся `Provides` и `Lacks`, перекрывающиеся области памяти или формат, который платформа не поддерживает.

## 13.3 Эффекты, которые даёт цель

**target.effects.environment** — *Эффекты окружения* — эффекты, которые может сделать реальными только цель: выделение памяти (`Alloc`, `StaticAlloc`), ввод-вывод (`Console`, `File`, `Network`, `Video`, `Keyboard`, `ReadInput`, `WriteOutput`), исполнение (`Tasks`, `Interrupts`), эффекты железа из описания устройства, недетерминизм (`Clock`, `Random`), `Privileged`, `GPU` и эффекты возможностей устройства профиля `ui` (`Camera`, `Location`, …). Эта классификация нормативна; смысл каждого эффекта задан в [07-effects](07-effects.ru.md) (**eff.base.set**), который передаёт проверку по цели этому разделу (**eff.target.check**).

**target.effects.provides** — Каждый эффект окружения, достижимый из точек входа программы в сборке под цель, ДОЛЖЕН быть перечислен в `Provides` цели. Достижимый эффект окружения, которого там нет, — ошибка компиляции с цепочкой вызовов до его источника.

**target.effects.lacks** — `Lacks` перечисляет эффекты окружения, которых у цели явно нет. Достижимый эффект из `Lacks` — ошибка компиляции с диагностикой о том, что у платформы его нет. `Lacks` не меняет того, какие программы компилируются; он меняет диагностику и ответы `anlang query`.

**target.effects.foreign** — `Foreign` считается всеми эффектами сразу (**eff.model.foreign**), а ни одна цель не предоставляет всех эффектов окружения, поэтому достижимый `Foreign` отвергается на любой цели (**ffi.effects.foreign-deny** в [12-ffi](12-ffi.ru.md)). `Lacks` меняет только диагностику (**target.effects.lacks**).

**target.effects.computational** — Эффекты, не являющиеся эффектами окружения, — `Panic`, `Global`, `Block` и свои эффекты, объявленные через `effect.Declare`, кроме эффектов стандартной библиотеки, которые перечисляет **target.effects.environment** (`Privileged`, `GPU`, `ReadInput`, `WriteOutput` и эффекты устройств `ui`), — перечислять не нужно. Эффекты окружения, лежащие под своим эффектом, проверяются как обычно.

## 13.4 Платформы

**target.platform.desc** — Платформа описывается константой типа `platform.Platform` в пакете на Anlang. Описание указывает:

1. эффекты окружения, которые платформа может дать;
2. есть ли динамическая загрузка (`ffi.Library`, см. [12-ffi](12-ffi.ru.md));
3. механизм системных вызовов, если он есть, и вариант C ABI;
4. точку входа и последовательность запуска (см. [19-runtime](19-runtime.ru.md));
5. допустимые форматы бинарников;
6. профили, допустимые для пакета `main`;
7. действие `OnPanic` по умолчанию;
8. ограничения фонового исполнения для платформ, которые его ограничивают (см. [17-ui](17-ui.ru.md));
9. для платформы, написанной на Anlang, — её таблицу системных вызовов (`abi.Table`, см. [15-os](15-os.ru.md)).

**target.platform.profile** — Профиль пакета `main` ДОЛЖЕН быть одним из профилей, допустимых на платформе. Пакеты в более строгих профилях можно вызывать из любого профиля (см. [07-effects](07-effects.ru.md)).

| Платформа | Динамическая загрузка | Профили `main` | `OnPanic` по умолчанию |
| --- | --- | --- | --- |
| `bare` | нет | `core` | `Halt` |
| `dos` | нет | `core` | `PrintAndExit` |
| `linux`, `windows`, `macos` | да | `core`, `app`, `ui` | `PrintAndExit` |
| `ios`, `android` | да | `ui` | `PrintAndExit` |
| `web` | нет (импорты WebAssembly) | `core`, `app`, `ui` | `PrintAndExit` |

### 13.4.1 Схема `platform.Platform`

**target.platform.schema** — Описание платформы — константа типа `platform.Platform` пакета `an/platform`. Её поля:

| Поле | Тип | Смысл (пункт **target.platform.desc**) |
| --- | --- | --- |
| `Name` | `string` | имя платформы в целях и суффиксах файлов |
| `Provides` | `[]effect.Effect` | эффекты окружения, которые платформа может предоставить (1); цель этой платформы НЕ ДОЛЖНА предоставлять другие |
| `Dynamic` | `bool` | есть ли на платформе динамическая загрузка (2) |
| `Rules` | `[]arch.Rule` | операции платформы `start`, `exit`, `halt`, `write`, `read`, `vectors` и `vector` в виде правил выбора команд (13.5.7): механизм системных вызовов (3) и последовательность запуска (4) |
| `Imports` | `[]platform.Import` | функции окружения, которые импортирует образ и вызывают правила (3) (**target.platform.imports**) |
| `Formats` | `[]string` | виды форматов бинарников, которые принимает платформа (5), например `"flat"` |
| `Profiles` | `[]string` | профили, допустимые для пакета `main` (6) |
| `OnPanic` | `platform.PanicAction` | действие при панике по умолчанию (7): `platform.PrintAndExit`, `platform.Reset` или `platform.Halt` |

Поля для варианта C ABI (3), фонового выполнения (8) и таблицы системных вызовов (9) объявляются на шагах плана, которые вводят внешние функции в операционных системах, платформы `ui` и платформы, реализованные на Anlang.

**target.platform.entry** — Точка входа программы — код, порождённый из правил платформы: команды правила `start`, резервирование кадра входного кода, обнуление изменяемых данных у цели с областями памяти (**target.memory.placement**), вызов `main` и команды правила `exit` с кодом 0. Правило `start` получает начальный указатель стека как `{sp}` и наименьший адрес стека как `{sb}`: у цели с областями памяти — конец первой области без `Exec` и этот адрес минус `Stack`; у цели без областей памяти, но с размером `Stack`, — конец и начало стека, который следует за изменяемыми данными (**target.memory.stack**). Паника выполняет действие цели при панике, записав сообщение (**rt.panic.actions**): `PrintAndExit` и `Reset` выполняют правило `exit` с кодом 2, а `Halt` — правило `halt`, которое останавливается без возврата, или правило `exit` на платформе без него.

**target.platform.bare** — На платформе `bare` (`platform.Bare`) образ начинается с таблицы векторов, которую на `armv7m` записывают правила `vectors` и `vector` (**emb.irq.vectors**): начальный указатель стека, вектор сброса `{f}` и векторы системных исключений, получающие обработчик по умолчанию `{d}`, затем вектор каждого прерывания устройства. Правило `start` запрещает прерывания (`CPSID`); `interrupts.Enable` их разрешает ([14-embedded](14-embedded.ru.md), **emb.init.start**). Стандартный вывод, стандартный поток ошибок и код завершения доходят до отладчика через семихостинг (`BKPT 0xAB`): правило `write` открывает консоль `:tt` на запись (стандартный вывод) или дозапись (стандартный поток ошибок), пишет и закрывает её; правило `read` открывает её на чтение (стандартный ввод), читает и закрывает; правило `exit` вызывает `SYS_EXIT_EXTENDED`, а затем запрашивает сброс системы, который срабатывает, если отладчик не остановил программу, — это действие при панике `Reset`; правило `halt` запрещает прерывания и ждёт в цикле `WFI` — действие при панике `Halt`. Цель этой платформы предоставляет `Console` через семихостинг.

**target.platform.imports** — У `platform.Import` есть поля `Module` и `Name` — имена импортируемой функции — и `Params` и `Results` — ширины её параметров и результатов в битах. Образ архитектуры со структурным потоком управления (**target.arch.structured**) импортирует функции `Imports` в их порядке; правило вызывает импорт `i` как функцию с индексом `i`.

**target.platform.web** — На платформе `web` (`platform.Web`) образ — модуль WebAssembly (**target.format.wasm**), который импортирует функции `fd_write`, `proc_exit` и `fd_read` модуля `wasi_snapshot_preview1` системного интерфейса WebAssembly (WASI) в этом порядке и экспортирует код входа как `_start`. Стандартный ввод, стандартный вывод и стандартный поток ошибок — дескрипторы файлов 0, 1 и 2: правило `write` вызывает `fd_write`, правило `read` — `fd_read`, правило `exit` — `proc_exit`; байты памяти с 0 по 15 — рабочая область этих правил. Модуль выполняется средами WASI, интерпретатором WebAssembly инструментария (**tool.emu.wasm**) и, через страницу **target.format.html**, браузером. Цель этой платформы предоставляет `Console`.

## 13.5 Архитектуры

### 13.5.1 Описания архитектур

*Описание архитектуры* состоит из трёх частей, все — данные на Anlang:

1. **Модель машины** — регистры и классы регистров, размер слова, порядок байтов, выравнивание, виды указателей и адресные пространства, направление роста стека, соглашения о вызовах (внутренний ABI Anlang и C ABI), вход в прерывания и ловушки, имена и сигнатуры обработчиков исключений, доступных `trap` (см. [15-os](15-os.ru.md)), какие команды привилегированные (эффект `Privileged`, см. [15-os](15-os.ru.md)), и модель времени каждой команды для оценки WCET (см. [14-embedded](14-embedded.ru.md)).
2. **Правила выбора команд** — декларативные правила, отображающие шаблоны операций IR в последовательности команд с ограничениями на операнды. Пример: сложение двух 16-битных значений → `ADD r16, r/m16`.
3. **Формальная семантика команд** — действие каждой команды на состояние машины, в стиле Sail.

**target.arch.value** — Архитектура идентифицируется константой типа `arch.Arch` в пакете `an/arch` (например, `arch.I8086`, `arch.ARMv7M`, `arch.X86_64`) или в пакете проекта. Константа ссылается на все три части.

**target.arch.no-compiler-change** — Реализация ДОЛЖНА выводить генератор кода для архитектуры из её правил выбора команд. Добавление архитектуры НЕ ДОЛЖНО требовать изменения компилятора.

**target.arch.rules-checked** — Реализация ДОЛЖНА проверять каждое правило выбора команд по формальной семантике: последовательность команд должна вычислять то же, что шаблон IR, для всех значений операндов, допускаемых ограничениями правила. Проверка использует решатель или полный перебор там, где пространство операндов это позволяет (см. [22-compiler](22-compiler.ru.md), [23-conformance](23-conformance.ru.md)).

**target.arch.generated** — Из формальной семантики реализация ДОЛЖНА генерировать:

1. ассемблер и дизассемблер архитектуры;
2. пакет команд `an/arch/<name>` (13.5.2);
3. интерпретатор, который используют встроенные эмуляторы (см. [20-toolchain](20-toolchain.ru.md)).

Исключение — архитектура со структурным потоком управления: в её описании есть кодировки и синтаксис ассемблера, но нет семантики, а её интерпретатор — встроенный интерпретатор, проверяемый независимым набором тестов (**target.arch.structured**).

**target.arch.structured** — У архитектуры *структурный поток управления*, если её `ABI.Structured.End` не пуст, как у `wasm32`: переход не идёт по адресу, а выходит из объемлющего блока, продолжаясь после его конца, или повторяет объемлющий цикл, а модуль состоит из функций, а не из образа команд по адресам. Генератор кода размещает код каждой подпрограммы в блоках и циклах операций `block`, `loop` и `end` (**comp.gen.structured**); подстановка метки в шаблоне (**target.arch.template**) становится числом блоков между командой и целью, в котором учтены блоки, которые сам шаблон открывает мнемониками `ABI.Structured.Open` и закрывает мнемоникой `ABI.Structured.End`. Адрес функции — её индекс; константные и изменяемые данные размещаются с начального адреса первого формата. У команд такого описания нет семантики: интерпретатор архитектуры — встроенный интерпретатор, для `wasm32` — интерпретатор WebAssembly (**tool.emu.wasm**), оракул которого — официальный набор тестов архитектуры (**conf.oracle.use**).

### 13.5.2 Пакеты команд

**target.arch.instr-package** — Пакет команд `an/arch/<name>` представляет команды и регистры архитектуры как обычные функции и типы Anlang, например `i8086.Int(0x21, i8086.Regs{AX: 0x0900})`, `armv7m.Wfi(armv7m.Regs{})`, `x86_64.ReadCR2()`. Именованные операнды передаются структурой, потому что именованных аргументов в Anlang нет. Имя функции — её мнемоника с первой буквой в верхнем регистре и остальными в нижнем, а у мнемоники с несколькими такими формами за ней следуют имена видов операндов. Функция формы команды, операнды которой — непосредственные значения, константы и фиксированные регистры, принимает непосредственные значения и структуру `Regs` с целыми регистрами классов регистров и регистром флагов ABI и возвращает регистры после команды; у команд, которые меняют счётчик команд напрямую, функций нет. Непосредственные значения в вызове ДОЛЖНЫ быть константами. Вызов загружает регистры из `Regs`, кроме зарезервированных регистров и регистра флагов ABI (**target.arch.abi**), выполняет команду и возвращает `Regs` с регистрами после неё; зарезервированные регистры сохраняют значения из аргумента. У архитектуры с дальними указателями есть функция `Far(segment, offset)`, возвращающая значение типа `unsafe.Far` (**mem.unsafe.api**).

**target.arch.instr-effects** — Эффекты каждой функции-команды выводятся из формальной семантики: команда, меняющая состояние прерываний, имеет `Interrupts`, привилегированная команда — `Privileged` и так далее. Компилятор знает, какие регистры портит каждая команда.

**target.arch.import-suffix** — Файл МОЖЕТ импортировать `an/arch/<name>`, только если его имя несёт суффикс архитектуры `_<name>` (например, `print_i8086.an`), как определено в [03-declarations](03-declarations.ru.md). Пакеты описаний архитектур от этого правила освобождены.

**target.arch.asm** — Ассемблер для блоков `asm` (см. [05-statements](05-statements.ru.md)) — тот, что сгенерирован из того же описания.

### 13.5.3 Схема `arch.Arch`

**target.arch.schema** — Описание архитектуры — константа типа `arch.Arch`. Её поля:

| Поле | Тип | Значение |
| --- | --- | --- |
| `Name` | `string` | имя архитектуры, используемое в целях и суффиксах файлов |
| `Word` | `int` | разрядность `int` по умолчанию в битах (13.6) |
| `Endian` | `arch.Endian` | `arch.Little` или `arch.Big`: порядок байтов памяти и единиц кодирования |
| `Unit` | `int` | разрядность в битах единиц, в которых хранятся кодировки |
| `AddressBits` | `int` | разрядность физического адреса |
| `Pointers` | `arch.Pointers` | разрядности видов указателей (13.6) |
| `Address` | `string` | физический адрес операнда в памяти со значением сегмента `seg` и смещением `off` в нотации семантики; `"off"` на архитектурах без сегментов |
| `PC` | `string` | регистр счётчика команд |
| `PCRead` | `int` | если не 0 — чему равен счётчик команд при чтении в семантике команды и база её относительных операндов: адрес команды плюс `PCRead` (**target.arch.execution**) |
| `Fetch` | `string` | физический адрес следующей команды в нотации семантики |
| `Registers` | `[]arch.Register` | регистры и именованные части регистров |
| `Operands` | `[]arch.Operand` | виды операндов команд |
| `Fragments` | `[]arch.Fragment` | части кодировок с альтернативами |
| `Prefixes` | `[]arch.Prefix` | префиксы команд |
| `Instructions` | `[]arch.Instruction` | формы команд |
| `Semantics` | `string` | функции, общие для семантики команд, в нотации семантики |
| `ABI` | `arch.ABI` | машинная модель генератора кода: регистр кадра, область аргументов и выравнивание (13.5.7) |
| `Rules` | `[]arch.Rule` | правила выбора команд (13.5.7) |

- **Регистр** имеет `Name`, разрядность `Width` в битах и, возможно, класс `Class`, родителя `Parent` со смещением `Offset`, маску `Fixed` битов, которые читаются как 1, и маску `Zero` битов, которые читаются как 0, например бита 0 счётчика команд для команд из полуслов. Часть регистра (флаг, младший байт) называет своего родителя и битовое смещение; запись части меняет родителя. Регистры класса нумеруются в порядке `Registers`; операнд класса кодируется номером. Регистры класса `"prefix"` хранят состояние, которое задают префиксы; они сбрасываются после каждой команды.
- **Вид операнда** — ровно одно из: фиксированный регистр `Register`; регистр класса `Class`; операнд в памяти `Memory` заданной разрядности (`-1` для операнда, у которого используется только адрес), кодируемый фрагментом `Fragment`, — вместе с `Class` он даёт операнд «регистр или память»; непосредственное значение из `Imm` битов, возможно `Signed` (расширяется со знаком до `Width`) и `Relative` (смещение от конца команды или от адреса команды плюс `PCRead`, которое семантика видит как адрес перехода); или константа `Constant` со значением `Value`, которая есть только в синтаксисе ассемблера. Регистровый операнд с `Registers` называет один из первых `Registers` регистров своего класса меньшим числом битов. У непосредственного значения со `Scale` ниже поля столько нулевых битов; с `Transform`, выражением над полем `v`, обратным самому себе, его биты — преобразованное поле; с `Syntax`, выражением над полем `v` не более 16 битов, ассемблер пишет это число, например непосредственное значение, развёрнутое из компактной кодировки, а семантика видит само поле. `List` класса `Class` — список регистров: маска, бит `i` которой выбирает регистр номер `i`.
- **Фрагмент** имеет альтернативы `Alternatives`; каждая — кодировка `Encoding`, поля которой — поля фрагмента, и либо поле `Register` с номером регистра операнда, либо `Address` и `Segment` в нотации семантики над полями, с тактами `Cycles`, которые добавляет вычисление адреса.
- **Префикс** имеет кодировку `Encoding` и семантику `Semantics`, присваивающую состояние префиксов.
- **Форма команды** имеет мнемонику `Mnemonic`, виды операндов `Operands` в порядке ассемблера, кодировку `Encoding`, семантику `Semantics`, такты `Cycles` формы с регистрами и эффекты `Effects` помимо регистров и памяти (**target.arch.instr-effects**). У команды не больше четырёх операндов; в семантике они называются `a`, `b`, `c` и `d`.

**target.arch.check** — Реализация ДОЛЖНА отвергать описание, в котором имя не определено, часть регистра выходит за пределы родителя, биты регистра одновременно входят в `Fixed` и `Zero`, регистры класса различаются разрядностью, вид операнда не является ровно одним видом, вид операнда с `Syntax` не является непосредственным значением не более 16 битов без `Signed`, `Relative`, `Scale` и `Transform`, у формы команды больше четырёх операндов, кодировка не кодирует операнд, которому это нужно, или кодирует его в поле неверной ширины, шаблон не состоит из целого числа единиц или семантика нарушает **target.arch.widths**.

### 13.5.4 Нотация кодировок

**target.arch.encoding** — Кодировка — последовательность элементов через пробел:

| Элемент | Значение |
| --- | --- |
| `HH` | байт в шестнадцатеричной записи, 8 фиксированных битов |
| `%0101` | фиксированные биты в двоичной записи |
| `name:width` | поле: операнд `a`, `b`, `c` или `d` (номер регистра, непосредственное значение или список регистров) либо поле фрагмента |
| `name[hi:lo]`, `name[i]` | биты с `hi` по `lo` или бит `i` операнда; диапазоны битов операнда вместе покрывают его биты, но список регистров может пропускать регистры, которые его кодировка не может перечислить |
| `<frag op field=value …>` | фрагмент `frag`, кодирующий операнд `op`; каждое `field=value` связывает поле фрагмента с операндом или константой |

Биты заполняют каждую единицу из `Unit` битов начиная со старшего бита; единицы хранятся в порядке байтов `Endian`. Поле из целого числа единиц, начинающееся на границе единицы, хранится в порядке байтов `Endian`, как непосредственное значение в памяти. Поле может встречаться в кодировке дважды; кодировка подходит, только если в обоих местах одно значение. При единицах шире байта фрагмент может занимать часть единицы; формы команд, которые его используют, состоят из целых единиц.

**target.arch.specific** — Если кодировке соответствуют несколько форм команд, применяется самая конкретная: та, у которой больше всего фиксированных битов, причём связывание с константой считается за один бит. Описание, в котором одной кодировке соответствуют две формы с одинаковым числом фиксированных битов, неоднозначно и ДОЛЖНО отвергаться для этой кодировки.

```go
{Mnemonic: "ADD", Operands: []string{"r/m16", "imm16"}, Encoding: "81 <rm a reg=0> b:16", Semantics: "a = add(a, b, 0);", Cycles: 4},
{Mnemonic: "INC", Operands: []string{"r16"}, Encoding: "%01000 a:3", Semantics: "a = inc(a);", Cycles: 2},
```

### 13.5.5 Нотация семантики

**target.arch.semantics** — Семантика команды — последовательность операторов над битовыми векторами в стиле Sail:

```
Stmt   = "let" name "=" Expr ";" | Target "=" Expr ";" | Call ";"
       | "if" Expr Block [ "else" ( Block | IfStmt ) ] | "while" Expr Block
       | "break" ";" | "return" [ Expr ] ";" .
Block  = "{" { Stmt } "}" .
Target = name | "mem8" "[" Expr "]" | "mem16" "[" Expr "]" | "mem32" "[" Expr "]" .
Def    = "fn" name "(" [ name { "," name } ] ")" Block .
```

Имя обозначает локальную переменную, параметр, регистр или операнд (`a`, `b`, `c`); присваивание части регистра меняет родителя; присваивание операнду записывает его регистр или память. `memN[addr]` — N-битное значение по физическому адресу `addr` в порядке байтов `Endian`. Выражения используют операторы Go с приоритетами Go: `|| && == != < <= > >= + - | ^ * & << >>`, а также `>>>` для арифметического сдвига вправо; сравнения беззнаковые. `x[i]` — бит `i`, `x[hi:lo]` — биты с `hi` по `lo`. Встроенные функции: `zx`, `sx` и `tr` (расширение нулями, расширение знаком и усечение до константной разрядности), `width`, `msb`, `lts`, `les`, `gts`, `ges` (знаковые сравнения), `divu`, `remu`, `divs`, `rems`, `in8`, `in16`, `out8`, `out16` (порты ввода-вывода), `halt`, `ea` (смещение операнда в памяти) и `segof` (значение его сегмента). Поле `Semantics` в `arch.Arch` определяет дополнительные функции через `fn`; они не рекурсивны.

**target.arch.widths** — Каждое значение имеет разрядность от 1 до 64 битов. Операнды арифметического, побитового оператора и сравнения имеют одинаковую разрядность; литерал или значение, вычисленное из литералов и `width`, не имеет разрядности и принимает разрядность другого операнда. Сравнение, `!`, `&&`, `||` и бит имеют разрядность 1; условия имеют разрядность 1. Функции, определённые через `fn`, не объявляют разрядностей: каждый вызов проверяется с разрядностями аргументов, и все значения, которые возвращает функция, имеют одну разрядность. Присваивание сохраняет разрядность цели. Арифметика выполняется по модулю 2ⁿ разрядности.

**target.arch.execution** — Команда выполняется, когда `IP` (или счётчик команд архитектуры) уже указывает за неё; относительный операнд обозначает адрес перехода. При `PCRead` счётчик команд в семантике команды, как операнд и в адресах её операндов в памяти читается как адрес команды плюс `PCRead`, и относительные операнды отсчитываются от этого адреса. Операнд в памяти читается и записывается по физическому адресу `Address`, вычисленному из `Segment` и `Address` альтернативы его фрагмента. Биты регистра из его маски `Zero` читаются как 0, что бы ни было записано. Обращение по физическому адресу, где у машины нет памяти, завершает команду ошибкой; у интерпретатора цели есть память областей цели (**target.memory.region**).

### 13.5.6 Синтаксис ассемблера

**target.arch.asm-syntax** — Ассемблер и дизассемблер, порождаемые из описания (**target.arch.generated**), используют для одной команды такой синтаксис: имена её префиксов, мнемоника и операнды через запятую. Регистровый операнд — имя регистра; непосредственное значение — число в десятичной записи или с префиксом `0x`; относительный операнд — адрес перехода; дальний указатель — `сегмент:смещение`; операнд в памяти — `byte [адрес]`, `word [адрес]`, `dword [адрес]` или `qword [адрес]` по его разрядности либо `[адрес]` для операнда, у которого используется только адрес, где адрес — сумма регистров и смещения, которую может закодировать одна из альтернатив его фрагмента; регистр под маской-константой в адресе, например счётчик команд, выровненный вниз, пишется как регистр, а смещение, записанное как `-0`, выбирает альтернативу, вычитающую своё поле. Список регистров — регистры в фигурных скобках в порядке их номеров, например `{R4, R5, LR}`. Непосредственное значение с `Syntax` — число его синтаксиса. Регистр букв в именах не важен. Из нескольких кодировок одного текста ассемблер выбирает самую короткую, а из одинаково коротких — форму команды и альтернативу фрагмента, описанные первыми, предпочитая альтернативу с регистрами адреса в записанном порядке.

**target.arch.round-trip** — Для каждой кодировки, которую определяет описание, ассемблирование дизассемблированного текста ДОЛЖНО давать кодировку, дизассемблированный текст которой тот же.

### 13.5.7 Правила выбора команд

**target.arch.rule** — Правило выбора команд — значение типа `arch.Rule` с полями `Op` (машинная операция), `Width` (разрядность её операндов в битах, 0 для операции без разрядности), `From` (для `ext.s` и `ext.u` — разрядность операнда) и `Code` (шаблон команд). Генератор кода выражает каждую команду IR последовательностью машинных операций и заменяет каждую операцию шаблоном правила для неё.

**target.arch.ops** — Машинные операции перечислены ниже. `r` — результат; `x` и `y` — операнды; `p` и `q` — адреса (значения разрядности указателя по умолчанию); `k` и `n` — константы: смещение и размер в байтах; `L` и `f` — метки. Значение разрядности `Width` — целое по модулю 2^Width; знаковые операции читают его в дополнительном коде.

| `Op` | Операнды | Смысл |
| --- | --- | --- |
| `move` | `r`, `x` | `r = x`; `Width` — 8, 16 или разрядность слова |
| `add`, `sub`, `mul`, `and`, `or`, `xor` | `r`, `x`, `y` | операция по модулю 2^Width |
| `not`, `neg` | `r`, `x` | побитовое дополнение; отрицание по модулю 2^Width |
| `add.s`, `sub.s`, `mul.s`, `neg.s` | `r`, `x`, `y` | как `add` … `neg`, но если точный результат, прочитанный как знаковое целое, не помещается в `Width` бит, управление переходит на метку ловушки, а `r` не записывается |
| `add.u`, `sub.u`, `mul.u` | `r`, `x`, `y` | то же для беззнаковых целых |
| `div.s`, `rem.s` | `r`, `x`, `y` | частное, усечённое к нулю, и остаток знаковых целых; `y` ≠ 0, и `x` не минимум, если `y` равен −1 |
| `div.u`, `rem.u` | `r`, `x`, `y` | частное и остаток беззнаковых целых; `y` ≠ 0 |
| `shl`, `shr.u`, `shr.s` | `r`, `x`, `y` | сдвиги `x` на число `y` — беззнаковое значение разрядности слова; сдвиг на `Width` и больше даёт 0, а для `shr.s` — знак `x` в каждом бите |
| `eq`, `ne`, `lt.s`, `lt.u`, `le.s`, `le.u` | `r`, `x`, `y` | `r` — 8-битная 1, если отношение выполняется, иначе 0 |
| `ext.s`, `ext.u` | `r`, `x` | `x` разрядности `From`, расширенное знаком или нулями до `r` разрядности `Width` |
| `addr` | `r`, `x` | `r` — адрес слота `x` |
| `load` | `r`, `p`, `k` | `r` — значение по адресу `p + k`; `Width` — 8 или разрядность слова |
| `store` | `p`, `k`, `x` | записывает `x` по адресу `p + k` |
| `load.far`, `store.far` | как у `load`, `store` | то же, где `p` — дальний адрес (`unsafe.Far`): память отображения железа (**mem.unsafe.map**) |
| `copy` | `p`, `q`, `n` | копирует `n` байт с адреса `q` по адресу `p`; области не перекрываются |
| `zero` | `p`, `n` | обнуляет `n` байт по адресу `p` |
| `jump` | `L` | продолжает с `L` |
| `branch` | `x`, `L` | продолжает с `L`, если 8-битное `x` не 0, иначе со следующей операции |
| `call` | `f` | вызывает функцию по метке `f` |
| `callind` | `x` | вызывает функцию по адресу `x` |
| `enter` | `n` | начало функции: устанавливает базу кадра так, что указатель стека вызывающей функции в момент вызова равнялся базе кадра плюс `ABI.Params`, и резервирует `n` байт ниже базы кадра |
| `leave` | — | возвращает управление вызывающей функции, восстанавливая её базу кадра и указатель стека |
| `regin`, `regout` | `x` или `r`, `reg` | переносит `x` в регистр `reg` или регистр `reg` в `r` для вызовов пакета команд и операторов `asm`; регистр, для которого ни один шаблон не ассемблируется, не переносится |
| `flagsout` | `r` | сохраняет регистр флагов `ABI.Flags` в `r` |
| `start` | — | правило платформы: команды перед вызовом `main` |
| `exit` | `x` | правило платформы: завершает программу с кодом `x` разрядности слова |
| `write` | `x`, `p`, `y` | правило платформы: записывает `y` байт по адресу `p` в поток `x`: 1 — стандартный вывод, 2 — стандартный поток ошибок |
| `read` | `r`, `x`, `p`, `y` | правило платформы: читает не более `y` байт потока `x` (0 — стандартный ввод) по адресу `p`; `r` ширины слова — число прочитанных байт, 0 в конце потока |
| `block`, `loop`, `end` | — | на архитектуре со структурным потоком управления: начало блока, к концу которого приходит переход, начало цикла, который повторяет переход, и конец того или другого (**target.arch.structured**) |
| `vectors` | `{sp}`, `{f}`, `{d}` | правило платформы: начало таблицы векторов с начальным указателем стека, вектором сброса `f` и обработчиком по умолчанию `d` |
| `vector` | `f` | правило платформы: вектор следующего прерывания устройства с обработчиком `f` |
| `enter.handler`, `leave.handler` | `n` | как `enter` и `leave`, для обработчика прерывания: они также сохраняют и восстанавливают регистры, которые процессор не сохраняет при исключении, а `leave.handler` возвращается из исключения |
| `irq.save` | `r` | сохраняет состояние прерываний в `r` и запрещает их |
| `irq.restore` | `x` | восстанавливает состояние прерываний из `x` — значения `irq.save` |

**target.arch.template** — Шаблон команд — текст на ассемблере в синтаксисе **target.arch.asm-syntax**, по одной команде в строке, с подстановками в фигурных скобках:

1. `{x}`, `{y}`, `{r}`, `{p}`, `{q}` — операнд. Операнд в слоте — операнд в памяти `<размер> [<регистр кадра><смещение>]` с размером по `Width` (`byte`, `word`, `dword`, `qword`), где регистр кадра — `ABI.Frame`; операнд-константа, в том числе адрес функции или константных данных, — число.
2. `{x.i}` — часть `i` операнда, значение разрядности слова: часть 0 — младшая. Шаблоны операций шире слова называют части.
3. `{k}`, `{n}` — константное смещение или размер; `{L}`, `{f}` — метка; `{trap}` — метка ловушки проверяемой операции.
4. `@name` — метка, локальная для одного применения шаблона; строка `@name:` определяет её.
5. `{reg}` — регистр операций `regin` и `regout`.
6. `{x.h0}`, `{x.h1}` — младшие и старшие 16 битов операнда-константы разрядности слова или адреса метки; для операнда в слоте — операнд в памяти, так что шаблон не ассемблируется.
7. `{x.off}` — смещение слота `x` от регистра кадра числом.

Фигурные скобки вокруг имени регистра, например `{LR}`, — список регистров, а не подстановка. Строка `.word v`, где `v` — сумма чисел и меток, записывает `v` в слово разрядности слова, например элемент таблицы векторов.

**target.arch.select** — Для операции с данными `Op`, `Width` и `From` генератор кода использует первое правило архитектуры, затем платформы, с теми же тремя значениями, шаблон которого ассемблируется после подстановки операндов. Если ни один шаблон не ассемблируется из-за того, что операнд — константа, константа сначала переносится в слот. Если правила для `mul`, `mul.s`, `mul.u`, `div.s`, `div.u`, `rem.s`, `rem.u`, `shl`, `shr.s` или `shr.u` разрядности больше слова нет, операция — вызов функции пакета времени выполнения, имя которой — имя операции в верблюжьем регистре и разрядность, например `DivU32` для `div.u` 32 бит ([22-compiler](22-compiler.ru.md), 22.11). Отсутствие правила для любой другой операции, нужной программе, — ошибка сборки, называющая операцию и архитектуру.

**target.arch.abi** — У `arch.ABI` есть поля `Frame` (регистр с базой кадра; слоты адресуются относительно него), `FrameBottom` (регистр кадра вместо этого хранит низ кадра — указатель стека после `enter`, так что смещения слотов неотрицательны), `Params` (смещение области аргументов вызывающей функции от базы кадра), `Align` (выравнивание слотов и области аргументов в байтах), `Reserved` (регистры, на значения которых опирается порождённый код; вызовы пакета команд и операторы `asm` их не загружают), `Flags` (регистр флагов, который они сохраняют, но не загружают), `InterruptFrame` (число байт, которые процессор и `enter.handler` кладут при прерывании до кадра обработчика, для анализа стека, **emb.stack.compute**) и `Structured` (для структурного потока управления, **target.arch.structured**: мнемоники `Open` команд, открывающих блок, и `End` команды, закрывающей его). Стек растёт в сторону меньших адресов. Раскладка кадров и областей аргументов задана в [22-compiler](22-compiler.ru.md), 22.11.

**target.arch.rules-test** — Пока решатель не работает с битовыми векторами (шаг 22 плана), проверка **target.arch.rules-checked** выполняет каждое правило операции, кроме `jump`, `branch`, `call`, `callind`, `enter`, `leave`, `regin`, `regout`, `flagsout`, `enter.handler`, `leave.handler`, `irq.save`, `irq.restore`, `block`, `loop`, `end` и операций платформы, в интерпретаторе, порождённом из описания: полным перебором для 8-битных операндов, а для более широких — на граничных значениях (0, 1, максимумы и минимумы и их соседи) и на случайных значениях, сравнивая результат и то, перешло ли управление на метку ловушки, со смыслом из **target.arch.ops**. На архитектуре со структурным потоком управления шаблон выполняется её встроенным интерпретатором в блоке, из которого выходит метка ловушки. Остальные правила проверяются запуском эталонных программ (**conf.backend.ir**).

## 13.6 Разрядность целых и виды указателей

**target.word.int** — `int` и `uint` имеют ширину, заданную `Word`.

**target.word.usize** — `usize` имеет ширину адреса данных вида указателя по умолчанию: ширину плоского указателя или ближнего указателя на сегментных архитектурах.

**target.pointers.kinds** — У `target.Pointers` есть поля `Flat`, `Near`, `Far` и `Program`, каждое — ширина в битах; ноль означает, что такого вида нет. Виды указателей встречаются только внутри `unsafe` и пакетов архитектур (см. [06-memory](06-memory.ru.md)).

| Архитектура | `int` | `usize` | Виды указателей |
| --- | --- | --- | --- |
| `i8086` | 16 | 16 | `Near` 16, `Far` 32 (сегмент:смещение) |
| `avr` | 16 | 16 | `Near` 16 (RAM), `Program` 16 или 24 (flash, чтение специальными командами) |
| `msp430` | 16 | 16 | `Flat` 16 |
| `armv6m`, `armv7m`, `riscv32`, `wasm32` | 32 | 32 | `Flat` 32 |
| `x86_64`, `arm64`, `riscv64` | 64 | 64 | `Flat` 64 |

**Примечание** — В переносимом коде по умолчанию используются типы с явным размером (`i8` … `i64`, `u8` … `u64`).

## 13.7 Дробные числа

**target.floats.hard** — При `HardFloat` операции над `f32` и `f64` используют команды процессора для дробных чисел.

**target.floats.soft** — При `SoftFloat` они используют программную эмуляцию из стандартной библиотеки с теми же результатами по IEEE 754.

**target.floats.none** — При `NoFloat` функция, достижимая в сборке, в которой есть значение или операция типа `f32`, `f64` или дробного типа `simd`, — ошибка компиляции.

## 13.8 Области памяти и стек

**target.memory.region** — У `target.Region` есть поля `Name string`, `At` (начальный адрес), `Size` (байты) и `Exec bool`. Область с `Exec: true` содержит код и данные только для чтения и во время выполнения не записывается; область с `Exec: false` содержит изменяемые данные, данные с нулевой инициализацией и стеки.

**target.memory.placement** — Код и константы (**ct.const.placement**) размещаются в первой области с `Exec`; там же хранятся начальные значения изменяемых данных, которые копируются в RAM при запуске (см. [19-runtime](19-runtime.ru.md)). Изменяемые данные и стеки размещаются в первой области без `Exec`. Пока изменяемых данных с начальными значениями нет, изменяемые данные начинаются с нулевых байтов, которые записывает входной код (**target.platform.entry**).

**target.memory.overflow** — Если содержимое, назначенное любой области, превышает её размер, сборка завершается ошибкой. Диагностика ДОЛЖНА показывать размер области, общий объём использования и разбивку по пакетам: код, константы, статические данные и резерв стека.

**target.memory.stack** — `Stack` — размер стека `main`. Анализ стека сравнивает его с вычисленной максимальной глубиной (см. [14-embedded](14-embedded.ru.md)). У цели без областей памяти стек `main` следует за изменяемыми данными.

```go
const Description = target.Desc{
    Arch:     arch.ARMv7M,
    Platform: platform.Bare,
    Word:     32,
    Memory: []target.Region{
        {Name: "flash", At: 0x0800_0000, Size: 64 * KiB, Exec: true},
        {Name: "ram",   At: 0x2000_0000, Size: 20 * KiB},
    },
    Stack:    8 * KiB,
    Formats:  []target.Format{target.ELF, target.BIN, target.HEX},
    Device:   svd.Load("STM32F103.svd"),
    Floats:   target.SoftFloat,
    Provides: []Effect{Console, Gpio, Uart, Timers, Interrupts, StaticAlloc, Tasks},
    Lacks:    []Effect{File},
    OnPanic:  target.Reset,
}
```

## 13.9 Форматы бинарников

**target.format.interface** — Формат бинарника — значение, реализующее интерфейс `target.Format`. Компоновщик передаёт ему скомпонованный образ — сегменты с адресами и содержимым, точку входа и символы, — а формат создаёт выходной файл. Форматы — код на Anlang, как и архитектуры; добавление формата не меняет компилятор.

**target.format.kind** — Пока вычисления при компиляции не умеют вызывать методы на скомпонованном образе (шаг 26 плана), у интерфейса `target.Format` есть метод `Kind() string`, а формат каждого вида записывает инструментарий: `"flat"` для `target.Flat`, `"boot"` для `target.BootSector`, `"elf"` для `target.ELF`, `"bin"` для `target.BIN`, `"hex"` для `target.HEX`, `"wasm"` для `target.Wasm` и `"html"` для `target.Page`. `target.ELF`, `target.BIN`, `target.HEX` и `target.Page` — константы типов `target.ELFFormat`, `target.BINFormat`, `target.HEXFormat` и `target.HTML`.

**target.format.all** — Сборка создаёт по одному выходному файлу на каждый формат из `Formats` в `out/<target>/`.

| Формат | Значение | Требования |
| --- | --- | --- |
| flat (.COM) | `target.Flat{Origin, MaxSize}` | сырой образ без заголовка и релокаций, загружаемый по адресу `Origin`; выполнение начинается с первого байта; образ НЕ ДОЛЖЕН превышать `MaxSize` байт; для `.COM` в DOS `Origin` равен `0x100`, а `MaxSize` — `65280` |
| загрузочный сектор | `target.BootSector` | сырой образ, загружаемый по адресу `0x7C00`, не больше 510 байт, дополненный нулевыми байтами до 510 байт, за которыми идёт загрузочная сигнатура `0x55 0xAA`; файл занимает ровно 512 байт; выполнение начинается с первого байта |
| MZ (.EXE) | `target.MZ` | исполняемый файл DOS с заголовком MZ и таблицей релокаций |
| ELF | `target.ELF` | исполняемый файл Linux; на `bare` — сегменты загрузки по адресам областей для отладчиков и программ прошивки: образ в начале области `Exec`, точка входа — вектор сброса |
| PE | `target.PE` | исполняемый файл Windows |
| Mach-O | `target.MachO` | исполняемый файл macOS и iOS |
| wasm | `target.Wasm{Origin}` | модуль WebAssembly (**target.format.wasm**) |
| HTML-страница | `target.Page` | HTML-страница, которая выполняет модуль WebAssembly в браузере (**target.format.html**) |
| BIN | `target.BIN` | сырой образ содержимого области `Exec`, начиная с её начального адреса |
| Intel HEX | `target.HEX` | записи Intel HEX с тем же содержимым, что BIN |
| UF2 | `target.UF2{FamilyID}` | блоки UF2 для загрузчиков, работающих как USB-накопитель |

**target.format.size** — Превышение предела размера формата — ошибка сборки с той же разбивкой по пакетам, что в **target.memory.overflow**.

**target.format.wasm** — В модуле `target.Wasm` структурного образа есть: тип 0 — тип `[] → []` функций образа — и типы импортов; импорты платформы (**target.platform.imports**); функции, индекс которых — их адрес; таблица типа `funcref`, в которой каждая функция лежит по своему индексу, для косвенных вызовов; одна память, экспортированная как `memory`, достаточная для данных и стека; изменяемая глобальная переменная `i32` для каждого регистра архитектуры с начальным значением 0; экспорт `_start` кода входа; и один сегмент данных с константными данными и начальными изменяемыми данными по адресу `Origin`. Модуль — корректный WebAssembly 2.0.

**target.format.html** — Файл `target.Page` — HTML-страница, которая содержит модуль WebAssembly первого формата `target.Wasm` цели и выполняет его в браузере с функциями WASI из **target.platform.web**: стандартный вывод и стандартный поток ошибок появляются в консоли страницы, а стандартный ввод — то, что пользователь набирает в её поле ввода, каждый символ по мере набора, Enter — как перевод строки. Чтение ждёт ввода через JavaScript Promise Integration; в браузере без неё чтение видит только ввод, переданный в параметре запроса `input` страницы. Странице не нужен сервер: она работает из файла.

**target.format.macos-sign** — Исполняемый файл Mach-O для macOS на `arm64` ДОЛЖЕН иметь ad-hoc подпись кода, потому что операционная система не запускает неподписанный код arm64. Подпись приложений iOS для устройств описана в [17-ui](17-ui.ru.md).

## 13.10 Действие при панике

**target.panic.action** — У `target.PanicAction` есть значения `target.PrintAndExit`, `target.Reset` и `target.Halt`. Их поведение — сообщение, стек вызовов, сброс, остановка — определено в [19-runtime](19-runtime.ru.md).

## 13.11 Выбор цели

**target.select.flag** — Цель выбирается при сборке флагом `-target` и никогда — в исходном коде. В заголовке пакета есть только `profile` (см. [03-declarations](03-declarations.ru.md)).

**target.select.resolve** — Аргумент цели разрешается так:

1. Если он содержит `/`, это путь импорта пакета цели.
2. Иначе это имя цели. Реализация ищет в модуле пакеты целей с этим именем (**target.pkg.name**). Если найден ровно один, используется он; если больше одного, сборка завершается ошибкой.
3. Если в модуле ничего не найдено, используется `an/target/<name>`; если его нет, сборка завершается ошибкой.

**target.select.default** — Без `-target` собираются цели, перечисленные в `anlang.mod` (см. [20-toolchain](20-toolchain.ru.md)).

**target.select.files** — Для каждой цели исходные файлы выбираются по суффиксам платформы и архитектуры, как определено в [03-declarations](03-declarations.ru.md).

## 13.12 Сборка под несколько целей

**target.multi.flag** — `anlang build -target a,b,c` собирает все перечисленные цели за один запуск.

**target.multi.equivalent** — Результат для каждой цели ДОЛЖЕН совпадать со сборкой только этой цели. Реализация МОЖЕТ разделять работу между целями — например, проверку типов, эффектов и контрактов пакетов с одинаковыми наборами выбранных файлов, — но НЕ ДОЛЖНА допускать зависимости результата одной цели от другой.

**target.multi.output** — Результаты цели `t` помещаются в `out/<t>/`.

## 13.13 Стандартные цели

**target.std.name** — Имена целей стандартной библиотеки строятся по правилам:

1. Цель для операционной системы называется `<платформа>-<архитектура>`: `linux-x86_64`, `windows-x86_64`.
2. Цели DOS и BIOS называются по виду результата: `dos-com`, `dos-exe`, `bios-boot`.
3. Остальные загрузочные цели называются `<загрузочная среда>-<архитектура>`: `multiboot-x86_64`, `uefi-arm64`, `devicetree-riscv64`.
4. Цель для микроконтроллера называется по чипу, строчными буквами без разделителей: `stm32f103c8`, `rp2040`.
5. Мобильная цель называется по платформе и собирает все её архитектуры в один пакет: `android`, `ios`, `ios-sim`.
6. Цель для браузера — `web`.

Имена архитектур внутри имён целей сохраняют своё написание (`x86_64`).

**target.std.required** — Реализация ДОЛЖНА предоставлять следующие пакеты целей в `an/target/`. Столбец «Шаг» — шаг плана, на котором цель появляется ([24-roadmap](24-roadmap.ru.md)); цель обязательна начиная с выпуска, в котором этот шаг завершён.

| Цель | Архитектура | Платформа | Форматы | Шаг |
| --- | --- | --- | --- | --- |
| `dos-com` | `i8086` | `dos` | `Flat{Origin: 0x100, MaxSize: 65280}` | 13 |
| `stm32f103c8` | `armv7m` (Cortex-M3) | `bare` | ELF, BIN, Intel HEX | 15–16 |
| `web` | `wasm32` | `web` | wasm, HTML-страница | 18 |
| `linux-x86_64` | `x86_64` | `linux` | ELF | 26 |
| `linux-arm64` | `arm64` | `linux` | ELF | 27 |
| `macos-arm64` | `arm64` | `macos` | Mach-O | 27 |
| `windows-x86_64` | `x86_64` | `windows` | PE | 28 |
| `atmega328p` | `avr` | `bare` | ELF, Intel HEX | 51 |
| `dos-exe` | `i8086` | `dos` | MZ | 52 |
| `rp2040` | `armv6m` (Cortex-M0+) | `bare` | ELF, UF2 | 52 |
| `esp32c3` | `riscv32` | `bare` | ELF, BIN | 52 |
| `msp430g2553` | `msp430` | `bare` | ELF, Intel HEX | 52 |
| `bios-boot` | `i8086` | загрузочный сектор BIOS | `BootSector` | 55 |
| `multiboot-x86_64` | `x86_64` | Multiboot | ELF | 55 |
| `uefi-x86_64`, `uefi-arm64`, `uefi-riscv64` | по имени | UEFI | PE (приложение UEFI) | 55 |
| `devicetree-arm64`, `devicetree-riscv64` | по имени | Device Tree | ELF, BIN | 55 |
| `android` | `arm64`, `x86_64` | `android` | APK, AAB | 65 |
| `ios`, `ios-sim` | `arm64`; `arm64`, `x86_64` | `ios` | `.ipa`; `.app` | 66 |

**Примечание** — У `rp2040` два ядра; пока многоядерные микроконтроллеры не описаны ([14-embedded](14-embedded.ru.md)), цель использует только ядро 0. Другие чипы и платы проект добавляет своими пакетами целей (**target.pkg.location**).
