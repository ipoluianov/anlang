# 1. Лексическая структура

Этот файл задаёт исходный текст, лексемы, ключевые слова, контекстные слова и литералы, а также закрытые перечни отличий Anlang от Go. Всё, что здесь не сказано, устроено как в спецификации Go, разделы «Source code representation» и «Lexical elements».

## 1.1 Исходный текст

**lex.source.utf8** — Исходный файл ДОЛЖЕН быть текстом Unicode в кодировке UTF-8, как в Go.

**lex.source.extension** — Исходные файлы Anlang имеют расширение `.an`. Файлы с другими расширениями в каталоге пакета исходными не являются.

**lex.source.canonical** — Исходный файл ДОЛЖЕН быть в каноническом виде: в той последовательности байтов, которую для него выдаёт `anlang fmt`. Реализация ДОЛЖНА сообщать о файле не в каноническом виде как об ошибке в `anlang build` и `anlang check` и ДОЛЖНА предоставлять `anlang fmt`, который переписывает любой синтаксически правильный файл в канонический вид. Каноническое форматирование идемпотентно: форматирование канонического файла возвращает его без изменений.

**Примечание** — Канонический вид следует `gofmt`. Его точные правила задаются эталонной реализацией `anlang fmt` и её тестами (см. [20-toolchain](20-toolchain.ru.md)).

## 1.2 Лексемы, комментарии и точки с запятой

**lex.token.go** — Лексемы, пробельные символы, комментарии и автоматическая вставка точек с запятой — как в спецификации Go.

**lex.comment.inert** — Комментарии никогда не влияют на смысл программы. Директивы внутри комментариев (например, `//go:build` или прагмы `//go:` из Go) не действуют. Ограничения сборки выражаются профилями, выведенными эффектами и суффиксами имён файлов ([03-declarations](03-declarations.ru.md), **decl.file.suffix**).

## 1.3 Идентификаторы

**lex.ident.go** — Идентификаторы — как в Go.

**lex.ident.contextual** — Контекстные слова из §1.5 являются идентификаторами. Вне позиций, перечисленных в §1.5, их можно использовать как любой другой идентификатор.

## 1.4 Ключевые слова

**lex.keyword.set** — Следующие ключевые слова зарезервированы и НЕ ДОЛЖНЫ использоваться как идентификаторы:

```
break        default      func         interface    select
case         defer        go           map          struct
chan         else         goto         package      switch
const        fallthrough  if           range        type
continue     for          import       return       var

enum         inout        profile
```

Первые 25 — ключевые слова Go. Последние три новые:

| Ключевое слово | Назначение | Где задано |
| --- | --- | --- |
| `enum` | суммарный тип с вариантами, которые могут нести данные | [02-types](02-types.ru.md) §2.5 |
| `inout` | изменяемый параметр, получатель или переменная цикла без указателей | [03-declarations](03-declarations.ru.md) §3.8, [06-memory](06-memory.ru.md) |
| `profile` | объявление профиля в исходном файле | [03-declarations](03-declarations.ru.md) §3.3 |

**Примечание** — Код на Go, где `enum`, `inout` или `profile` используются как идентификаторы, переименовывается при `anlang port`.

## 1.5 Контекстные слова

Контекстное слово имеет особый смысл только в перечисленных ниже позициях. В этих позициях оно никогда не является идентификатором.

**lex.context.positions** — Контекстные слова и позиции, в которых они распознаются:

| Слово | Позиция | Смысл | Где задано |
| --- | --- | --- | --- |
| `requires` | первая лексема оператора в начальной контрактной области тела функции | предусловие | [08-contracts](08-contracts.ru.md) |
| `ensures` | то же, что у `requires` | постусловие или ограничение функции | [08-contracts](08-contracts.ru.md) |
| `invariant` | первая лексема оператора в начальной контрактной области тела оператора `for` | инвариант цикла | [08-contracts](08-contracts.ru.md) |
| `invariant` | первая лексема записи в начальной области объявлений списка полей структуры | инвариант типа | [02-types](02-types.ru.md) §2.4, [08-contracts](08-contracts.ru.md) |
| `layout` | первая лексема записи в начальной области объявлений списка полей структуры | раскладка структуры | [02-types](02-types.ru.md) §2.13 |
| `interrupt` | первая лексема объявления верхнего уровня | объявление обработчика прерывания | [03-declarations](03-declarations.ru.md) §3.10 |
| `trap` | первая лексема объявления верхнего уровня | объявление обработчика ловушки | [03-declarations](03-declarations.ru.md) §3.10 |
| `gpu` | первая лексема объявления верхнего уровня, за которой идёт `func` | объявление функции для GPU | [03-declarations](03-declarations.ru.md) §3.10 |
| `asm` | первая лексема оператора, за которой идёт `(`; или после `=` в операторе присваивания | ассемблерная вставка | [05-statements](05-statements.ru.md) §10 |

**lex.context.contract-region** — *Начальная контрактная область* тела функции или тела оператора `for` — это наибольшая последовательность операторов в начале блока, первая лексема которых — идентификатор `requires`, `ensures` (тела функций) или `invariant` (тела циклов). Оператор в этой области, начинающийся с одного из этих слов, является контрактным условием, даже если его можно было бы разобрать как оператор-выражение (например, `requires(x)`).

**lex.context.struct-region** — *Начальная область объявлений* списка полей структуры — это наибольшая последовательность записей в начале списка, первая лексема которых — `invariant` или `layout`. Каждая такая запись — объявление условия, а не поля. Поле с именем `invariant` или `layout` МОЖЕТ быть объявлено после начальной области объявлений.

**Примечание** — На верхнем уровне Go допускает только объявления, начинающиеся с ключевого слова, поэтому идентификатор в качестве первой лексемы объявления верхнего уровня однозначен. Внутри блоков идентификатор, за которым сразу идёт выражение, в Go недопустим, поэтому контрактным условиям не нужны зарезервированные слова.

## 1.6 Операции и знаки препинания

**lex.operator.go** — Набор операций и знаков препинания — как в Go. Лексемы `*` и `&` лексически остаются, но их унарный смысл, связанный с указателями, убран ([04-expressions](04-expressions.ru.md)).

## 1.7 Литералы

**lex.literal.go** — Целые, дробные, рунные и строковые литералы — как в Go, включая разделители цифр (`0x0800_0000`).

**lex.literal.no-prefix** — Других префиксов и суффиксов литералов, кроме имеющихся в Go, нет. Текст в определённой кодировке или с завершающим символом получается обычными функциями, вычисляемыми при компиляции (`encoding.CP866("…")`), и преобразованием в `cstring` или `dstring` ([02-types](02-types.ru.md) §2.3).

**lex.literal.no-imaginary** — Мнимые литералы убраны.

**lex.literal.default-type** — Тип по умолчанию у нетипизированной целой константы — `int`, у дробной — `f64`, у рунной — `i32`, у строковой — `string`.

## 1.8 Перечень новизны

Перечень новизны — закрытый список всего, что Anlang добавляет к Go. Добавление записи — проектное решение того же веса, что и новое ключевое слово, и оно ДОЛЖНО вноситься изменением этой таблицы.

**lex.novelty.closed** — Возможность Anlang, которой нет в таблице ниже и которая не является удалением или ограничением из §1.9, не входит в язык.

| Вид | Записи |
| --- | --- |
| ключевые слова | `enum`, `inout`, `profile` |
| контекстные слова | `requires`, `ensures`, `invariant`, `interrupt`, `trap`, `gpu`, `layout`, `asm` |
| синтаксические конструкции | `for const`; внешняя функция `func f(...) T = expr`; блок `asm`; шаблоны в `case` (`case Circle{r}:`); варианты в теле `enum` |
| семантика без нового синтаксиса | `nil` без разыменования; `inout`-переменная цикла в range-over-func; `...any` как кортеж при компиляции; типы синхронизации как дескрипторы; `inout`-аргументы в `go`; `const` от вызовов функций; выводимое ограничение нулевого значения параметров-типов (**type.zero.param-constraint**) |
| известные компилятору типы с операциями | `simd`, `fixed`, `wrap` |
| решено 2026-10-25 ([open-issues](open-issues.ru.md)) | предобъявленные функции `assert` и `old` ([08-contracts](08-contracts.ru.md)); варианты с данными как функции-конструкторы ([02-types](02-types.ru.md)); статический switch по типу для значений параметров-типов и элементов `...any`, а также `meta.Reject` ([10-compile-time](10-compile-time.ru.md)); константы составных типов ([10-compile-time](10-compile-time.ru.md)); предобъявленные `Secret` и `Untrusted` ([11-data-safety](11-data-safety.ru.md)); отложенные эффекты конструкторов `Cmd` ([07-effects](07-effects.ru.md), [17-ui](17-ui.ru.md)) |
