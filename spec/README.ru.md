# Спецификация Anlang

В этом каталоге лежит нормативная спецификация языка и среды Anlang. У каждого файла рядом есть перевод на русский (`NN-name.ru.md`).

## Статус

Черновик. Спецификация формализует дизайн из `anlang.md` по состоянию на 2026-10-25. Места, где `anlang.md` оставил вопрос открытым, перечислены в подразделе **Открытые вопросы** в конце соответствующего файла.

## Связь с Go

Anlang описан как разница относительно **The Go Programming Language Specification, версия go1.23** (далее — *спецификация Go*). Версия go1.23 взята за основу, потому что в ней есть range-over-func.

1. Там, где эта спецификация молчит, конструкция имеет синтаксис и смысл из спецификации Go.
2. Каждая конструкция Go, которую Anlang убирает или меняет, перечислена явно. Убраны типы указателей, операция взятия адреса `&`, функции `init` и значения типа `any` вне разрешённых позиций (см. [02-types](02-types.ru.md), [03-declarations](03-declarations.ru.md)).
3. При противоречии этой спецификации и спецификации Go действует эта спецификация.

## Соглашения

### Ключевые слова требований

Слова **MUST**, **MUST NOT**, **SHOULD**, **SHOULD NOT** и **MAY** используются в смысле RFC 2119 и в переводе передаются как **ДОЛЖЕН**, **НЕ ДОЛЖЕН**, **СЛЕДУЕТ**, **НЕ СЛЕДУЕТ** и **МОЖЕТ**.

- **Требования к программе** ограничивают программы на Anlang. Программа, нарушающая такое требование, отвергается при компиляции, если правило не говорит иного.
- **Требования к реализации** ограничивают инструментарий `anlang`.

### Идентификаторы правил

У каждого нормативного правила есть постоянный идентификатор, который пишется жирным перед текстом правила:

> **mem.inout.exclusive** — Пока `inout`-доступ к значению жив, программа НЕ ДОЛЖНА обращаться к этому значению никаким другим путём.

- Идентификатор имеет вид `<область>.<тема>.<имя>`: строчные ASCII-символы, точки и дефисы.
- Области соответствуют файлам: `lex`, `type`, `decl`, `expr`, `stmt`, `mem`, `eff`, `contract`, `conc`, `ct`, `safe`, `ffi`, `target`, `emb`, `os`, `gpu`, `ui`, `std`, `rt`, `tool`, `proto`, `impl`, `conf`.
- Смысл идентификатора никогда не меняется. Идентификатор удалённого правила повторно не используется.
- Диагностики компилятора ссылаются на идентификатор нарушенного правила. Тесты набора соответствия называются по проверяемым правилам.
- Идентификаторы не переводятся.

### Нотация

Синтаксис задаётся в EBNF из спецификации Go:

```
Production  = production_name "=" [ Expression ] "." .
Expression  = Term { "|" Term } .
Term        = Factor { Factor } .
Factor      = production_name | token [ "…" token ] | Group | Option | Repetition .
Group       = "(" Expression ")" .
Option      = "[" Expression "]" .
Repetition  = "{" Expression "}" .
```

- Имена продукций глобальны для всех файлов. Продукция, определённая в спецификации Go и не переопределённая здесь, сохраняет определение из Go.
- Переопределённая продукция помечается *(replaces Go)*, новая — *(new)*.

### Примеры и примечания

- Примеры кода ненормативны, если правило не говорит иного.
- Текст с пометкой **Примечание** ненормативен.
- Файлы и разделы с пометкой *справочный* ненормативны целиком.
