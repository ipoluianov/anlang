# 17. Пользовательские интерфейсы и мобильные приложения

Этот файл описывает профиль `ui`: модель приложения, дерево интерфейса, раскладку, отрисовку, сервисы платформы, мобильные цели, манифесты, разрешения, жизненный цикл приложения и горячую перезагрузку.

Один и тот же код `ui` работает в браузере, на десктопе, на iOS и Android и в текстовом режиме. Различаются только цель и набор предоставляемых эффектов.

## 1. Профиль `ui`

**ui.profile.effects** — Профиль `ui` разрешает все эффекты, разрешённые `app`, и дополнительно эффекты пакетов интерфейса и возможностей устройства (раздел 7). Он запрещает прямой доступ к железу: эффекты экземпляров периферии ([14-embedded](14-embedded.ru.md)), `Interrupts` и `Privileged`.

**ui.profile.calls** — Действует общее правило вызовов между профилями ([07-effects](07-effects.ru.md)): пакет `ui` может вызывать пакеты, допускающие `core` или `app`; пакет, допускающий только `core` или `app`, НЕ ДОЛЖЕН вызывать пакет, допускающий только `ui`.

## 2. Модель приложения

Приложение `ui` — конечный автомат. `View` превращает состояние в дерево интерфейса; `Update` превращает состояние и сообщение в новое состояние и команду.

```go
func Update(s State, m Msg) (State, Cmd) {
    switch m {
    case Inc:   return State{s.count + 1}, cmd.None
    case Dec:   return State{s.count - 1}, cmd.None
    case Reset: return State{0}, cmd.None
    }
}

func View(s State) ui.Node {
    return ui.Column(
        ui.Text(fmt.Sprint("Count: ", s.count)),
        ui.Row(ui.Button("−", Dec), ui.Button("+", Inc)),
    )
}
```

**ui.app.decls** — Главный пакет приложения `ui` ДОЛЖЕН объявить:

1. тип `State`;
2. тип `enum` с именем `Msg`;
3. `func Update(s State, m Msg) (State, Cmd)`;
4. `func View(s State) ui.Node`.

**ui.app.init** — Начальное состояние — нулевое значение `State`. Если у `State` нет нулевого значения ([02-types](02-types.ru.md)), главный пакет ДОЛЖЕН объявить `func Init() (State, Cmd)`, и начальные состояние и команда — её результаты. Пакет МОЖЕТ объявить `Init`, даже если у `State` есть нулевое значение.

**ui.view.pure** — `View` ДОЛЖНА быть чистой: её множество эффектов ДОЛЖНО быть подмножеством `{Alloc, Panic}`.

**ui.update.pure** — `Update` НЕ ДОЛЖНА выполнять эффекты, кроме `Alloc` и `Panic`. Работа с другими эффектами запрашивается возвратом `Cmd`.

**ui.cmd.describe** — `Cmd` — описание работы, а не сама работа. Построение `Cmd` (например, `camera.ScanBarcode(Scanned)`) не имеет эффектов. Эффекты, которые будут у работы, когда её выполнит рантайм, — *отложенные эффекты* конструктора; их объявляет пакет, определяющий конструктор, через `effect.Defer` ([07-effects](07-effects.ru.md) §7.7.1).

**ui.cmd.deferred** — Отложенные эффекты каждого конструктора `Cmd`, достижимого из `Update` или `Init`, входят в множество эффектов программы. Они подчиняются ограничениям эффектов и используются для вывода разрешений (раздел 8).

**ui.cmd.exec** — Рантайм выполняет каждую возвращённую `Cmd` как задачу ([09-concurrency](09-concurrency.ru.md)). Когда работа завершается, её результат доставляется в `Update` как `Msg`. Конструктор `Cmd`, дающий результат, принимает функцию, превращающую результат в `Msg`; в качестве такой функции можно использовать вариант `enum` с данными (`Scanned` в примере из раздела 13).

**ui.app.context** — `Init`, `Update` и `View` выполняются только в основном контексте интерфейса. Сообщения обрабатываются по одному в порядке доставки.

## 3. Дерево интерфейса

**ui.node.value** — `ui.Node` — неизменяемое дерево-значение. Неизменившиеся поддеревья МОГУТ разделяться между последовательными результатами `View`.

**ui.a11y.label** — Каждый конструктор интерактивного элемента (элемента, который порождает `Msg`, когда пользователь с ним взаимодействует) в `an/ui` ДОЛЖЕН принимать текстовую метку, и его контракт ДОЛЖЕН включать `requires len(label) > 0`. Поэтому элемент без текстовой метки не компилируется: пустая константная метка отвергается сразу, а для неконстантной требуется доказательство, что она не пуста ([08-contracts](08-contracts.ru.md)).

**Примечание** — У элемента, видимое содержимое которого — значок, всё равно есть текстовая метка; она используется для доступности.

## 4. Раскладка

**ui.layout.constraints** — Раскладка задаётся ограничениями между элементами и контейнерами, а не стилями.

**ui.layout.units** — Движок раскладки ДОЛЖЕН поддерживать две системы единиц: пиксели и символьные ячейки. Одно и то же дерево ДОЛЖНО раскладываться в любой из них без изменений программы.

**ui.layout.deterministic** — Раскладка ДОЛЖНА быть детерминированной: одно и то же дерево, доступная область и система единиц дают одни и те же позиции на любой цели и машине.

## 5. Отрисовка

**ui.render.own** — На всех целях дерево интерфейса рисует только рендер Anlang. Реализация НЕ ДОЛЖНА использовать нативные элементы интерфейса платформы, кроме встроенных нативных видов (раздел 6).

**ui.render.backends** — Реализация предоставляет три вида бэкендов рендера:

| Бэкенд | Цели |
| --- | --- |
| GPU | Metal (iOS, macOS), Vulkan (Android, Linux), Direct3D или Vulkan (Windows), WebGPU (браузер) |
| Программный растеризатор | Дисплеи микроконтроллеров, фреймбуферы, VGA в DOS |
| Текстовый режим | DOS 80×25, терминалы |

**ui.render.equivalence** — Для одного и того же дерева и размера GPU-бэкенд и программный растеризатор ДОЛЖНЫ давать изображения, совпадающие в пределах допуска, заданного набором соответствия ([23-conformance](23-conformance.ru.md)).

**ui.render.text** — Рендеры, рисующие глифы, ДОЛЖНЫ поддерживать шейпинг текста для сложных письменностей и двунаправленный текст.

## 6. Сервисы платформы

Рендер и движок раскладки одинаковы на всех целях. Небольшой набор сервисов берётся у платформы через внешние функции ([12-ffi](12-ffi.ru.md)):

| Сервис | Механизм платформы |
| --- | --- |
| Доступность | Экспорт дерева интерфейса в VoiceOver, TalkBack, ARIA в браузере |
| Ввод текста | Системная клавиатура, IME, автозаполнение |
| Системные диалоги | Выбор файла, запросы разрешений, буфер обмена |
| Встроенный нативный вид | Карта, веб-страница, видеоплеер |

**ui.platform.ffi** — У каждой привязки к сервису платформы есть объявленные эффекты, как у любой внешней функции. Поэтому прямой вызов API платформы не обходит ограничения эффектов.

**ui.platform.native-view** — Встраивание нативного вида — исключение для содержимого, которое рендер не может нарисовать. Нативный вид занимает прямоугольник, назначенный движком раскладки.

## 7. Цели и возможности

### 7.1 Цели

| Цель | Архитектуры | Результат | Мост к системе |
| --- | --- | --- | --- |
| `web` | wasm32 | Модуль `.wasm` | Импорты WebAssembly |
| десктоп (`linux`, `macos`, `windows`) | x86-64, arm64 | Исполняемый файл | Динамические библиотеки |
| `ios` | arm64 | Mach-O внутри `.ipa` | Рантайм Objective-C через внешние функции |
| `ios-sim` | arm64, x86-64 | `.app` для симулятора | Как у `ios` |
| `android` | arm64, x86-64 | `.so` внутри APK или AAB | Таблица функций JNI через внешние функции |

**ui.aot** — Выпускные сборки ДОЛЖНЫ содержать только код, скомпилированный заранее. Они НЕ ДОЛЖНЫ генерировать или интерпретировать код во время выполнения.

### 7.2 Возможности устройства как эффекты

**ui.cap.effects** — Системные возможности представлены эффектами: `Camera`, `Location`, `Notifications`, `Contacts`, `Photos`, `Bluetooth`, `Background`, `Network`. Пакеты стандартной библиотеки, предоставляющие эти возможности, объявляют соответствующие эффекты — напрямую или как отложенные эффекты конструкторов `Cmd`.

**ui.cap.background** — Работа, выполняемая, пока приложение в фоновом состоянии, требует эффекта `Background`. У каждой задачи, работающей в фоне, ДОЛЖЕН быть дедлайн, не превышающий фоновый лимит времени из описания платформы; компилятор проверяет это, когда дедлайн — константа, известная при компиляции.

## 8. Разрешения

**ui.perm.derive** — Для целей с объявляемыми разрешениями реализация ДОЛЖНА генерировать записи разрешений из множества эффектов программы, включая отложенные эффекты: записи `NS…UsageDescription` в `Info.plist` для iOS и записи `uses-permission` в `AndroidManifest.xml` для Android.

**ui.perm.exact** — Сгенерированное множество разрешений ДОЛЖНО совпадать ровно с множеством, которого требуют эффекты. Программа НЕ ДОЛЖНА добавлять записи разрешений другими способами.

**ui.perm.usage** — Для каждого эффекта, который платформа цели требует объяснить пользователю, `Manifest.Usage` ДОЛЖЕН содержать непустой текст для этого эффекта. Иначе сборка завершается ошибкой.

**ui.perm.web** — На цели `web` разрешения запрашивает браузер во время выполнения; записи разрешений не генерируются.

Соответствие эффектов записям платформы задаёт `an/app`. Типичные записи (справочно):

| Эффект | Ключ iOS `Info.plist` | Разрешение Android |
| --- | --- | --- |
| `Camera` | `NSCameraUsageDescription` | `android.permission.CAMERA` |
| `Location` | `NSLocationWhenInUseUsageDescription` | `android.permission.ACCESS_FINE_LOCATION` |
| `Contacts` | `NSContactsUsageDescription` | `android.permission.READ_CONTACTS` |
| `Photos` | `NSPhotoLibraryUsageDescription` | `android.permission.READ_MEDIA_IMAGES` |
| `Bluetooth` | `NSBluetoothAlwaysUsageDescription` | `android.permission.BLUETOOTH_CONNECT` |
| `Notifications` | — (запрашивается во время выполнения) | `android.permission.POST_NOTIFICATIONS` |
| `Network` | — | `android.permission.INTERNET` |

## 9. Манифест

```go
package scanner

import "an/app"

const Manifest = app.Desc{
    ID:      "com.example.scanner",
    Name:    "Scanner",
    Version: "1.2.0",
    Icon:    "assets/icon.svg",
    Usage: map[Effect]string{
        Camera: "The camera is used to scan barcodes",
    },
    IOS:     app.IOS{MinVersion: "16.0", Team: "ABCDE12345"},
    Android: app.Android{MinSDK: 26},
}
```

**ui.manifest.decl** — Для целей `ios`, `ios-sim` и `android` главный пакет ДОЛЖЕН объявить константу уровня пакета `Manifest` типа `app.Desc`.

**ui.manifest.fields** — У `app.Desc` есть поля:

| Поле | Тип | Смысл |
| --- | --- | --- |
| `ID` | `string` | Идентификатор приложения в обратной доменной записи |
| `Name` | `string` | Имя, которое видит пользователь |
| `Version` | `string` | Версия в виде `MAJOR.MINOR.PATCH` |
| `Icon` | `string` | Путь к значку SVG в проекте; все нужные размеры генерируются |
| `Usage` | `map[Effect]string` | Тексты-объяснения для эффектов, которым они нужны |
| `IOS` | `app.IOS` | `MinVersion` (минимальная версия iOS), `Team` (идентификатор команды Apple) |
| `Android` | `app.Android` | `MinSDK` (минимальный уровень API Android) |

**ui.manifest.check** — `ID`, `Name`, `Version` и `Icon` ДОЛЖНЫ быть непустыми; `Version` ДОЛЖНА иметь указанный вид; `Icon` ДОЛЖЕН указывать на существующий файл SVG. Нарушения — ошибки сборки.

## 10. Жизненный цикл

```go
type Lifecycle enum {
    Launching
    Active
    Inactive
    Background{deadline Duration}
    Terminating
}
```

**ui.lifecycle.enum** — `an/app` определяет состояния приложения как тип `enum` `Lifecycle`, приведённый выше.

**ui.lifecycle.delivery** — Рантайм доставляет каждое изменение состояния жизненного цикла в `Update` как сообщение. Программа получает эти сообщения, объявив в главном пакете `func OnLifecycle(l app.Lifecycle) Msg`; если она её не объявила, изменения жизненного цикла не доставляются.

## 11. Сборка и подпись

**ui.sign.ios** — Сборка для `ios` требует подписи сертификатами Apple для команды, указанной в `Manifest.IOS.Team`. Подпись выполняется инструментами Apple на macOS.

**ui.sign.android** — Сборка для `android` требует ключа подписи и Android SDK.

**ui.build.outputs** — `anlang build -target ios` даёт `.ipa`; `anlang build -target android` даёт AAB или APK ([20-toolchain](20-toolchain.ru.md)).

## 12. Горячая перезагрузка

**ui.hot.scope** — Горячая перезагрузка применяется только к отладочным сборкам программ `ui`. Изменения в `View`, `Update` и вызываемых ими функциях применяются к работающей программе без перезапуска, и текущее состояние сохраняется.

**ui.hot.state-change** — Если изменился тип `State`, текущее состояние нельзя сохранить как есть. Среда ДОЛЖНА либо применить функцию миграции, предоставленную разработчиком, либо перезапустить программу.

**ui.hot.mechanism** — Механизм зависит от цели:

| Цель | Механизм |
| --- | --- |
| Браузер, десктоп, симулятор iOS, Android (отладочная сборка) | Подгрузка нового машинного кода |
| iOS-устройство (только отладочная сборка) | Код интерфейса исполняется встроенным интерпретатором WebAssembly и подменяется; работает медленнее выпускной сборки |

**ui.hot.release** — Выпускные сборки НЕ ДОЛЖНЫ содержать поддержку горячей перезагрузки и встроенный интерпретатор.

## 13. Пример

```go
package scanner

profile ui

import (
    "an/camera"
    "an/cmd"
    "an/ui"
)

type State struct {
    codes []string
}

type Msg enum {
    Scan
    Scanned{code string}
    Clear
}

func Update(s State, m Msg) (State, Cmd) {
    switch m {
    case Scan:          return s, camera.ScanBarcode(Scanned)
    case Scanned{code}: return State{append(s.codes, code)}, cmd.None
    case Clear:         return State{}, cmd.None
    }
}

func View(s State) ui.Node {
    return ui.Column(
        ui.List(s.codes, ui.Text),
        ui.Row(
            ui.Button("Scan", Scan),
            ui.Button("Clear", Clear),
        ),
    )
}
```

У `camera.ScanBarcode` отложенный эффект `Camera`. На iOS и Android это даёт запись разрешения на камеру и требует `Manifest.Usage[Camera]`; в вебе браузер запрашивает доступ через `getUserMedia`.

## Открытые вопросы


1. **Нативные виды.** Отложено до реализации — шаг 62. Узел дерева интерфейса, занимающий прямоугольник раскладки; API фиксируется в [18-stdlib](18-stdlib.ru.md).
2. **Функция миграции состояния.** Отложено до реализации — шаг 63. Её пишет разработчик; её вид и то, как среда её находит, фиксируются вместе с горячей перезагрузкой.
3. **`Background` на Android.** Отложено до реализации — шаг 65. Аналог фоновых режимов iOS на Android (сервисы переднего плана и их разрешения) описывается вместе с целью Android.
