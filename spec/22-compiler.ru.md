# 22. Компилятор

Этот файл описывает, как устроен компилятор `anlang`. Он *справочный*, кроме правил с идентификаторами — это нормативные требования к реализации.

## 22.1 Нормативные требования

**impl.single-binary** — Инструментарий ДОЛЖЕН быть одним исполняемым файлом. Он НЕ ДОЛЖЕН требовать внешнего компилятора, ассемблера, компоновщика, решателя или SDK другого языка, чтобы собирать, проверять, тестировать и запускать программы на Anlang. Единственное исключение — подпись приложений iOS инструментами Apple (см. [17-ui](17-ui.ru.md)).

**impl.no-external-solver** — Решатель для контрактов ДОЛЖЕН быть частью инструментария. Внешние решатели (например, Z3 или cvc5) НЕ ДОЛЖНЫ использоваться.

**impl.cache.transparent** — Использование кэша сборки НЕ ДОЛЖНО менять ни один результат, диагностику или ответ протокола. Сборка с пустым кэшем и сборка с заполненным кэшем ДОЛЖНЫ давать побайтово одинаковые результаты.

**impl.incremental** — После изменения одной функции повторной проверке СЛЕДУЕТ занимать доли секунды на типичном проекте.

**impl.abi.external** — Внешние функции и колбэки ДОЛЖНЫ использовать C ABI цели, заданный её описаниями архитектуры и платформы (см. [12-ffi](12-ffi.ru.md), [13-targets](13-targets.ru.md)).

**impl.abi.unstable** — Внутренний ABI Anlang не стабилен между версиями компилятора. Поскольку каждый пакет всегда компилируется из исходников, скомпилированная форма пакета никогда не переиспользуется разными версиями компилятора; ключ кэша сборки включает версию компилятора (22.7).

**impl.bootstrap.archive** — Версия компилятора на Go ДОЛЖНА сохраняться, чтобы инструментарий можно было раскрутить с нуля и проверить компилятор на закладки (22.9).

## 22.2 Язык реализации

Прототип — один исполняемый файл `anlang`, написанный на Go без cgo. После шагов самосборки (22.9) компилятор написан на Anlang. Компилятор видит программу целиком — весь код лежит в проекте и стандартной библиотеке, — но кэширует результаты по пакетам.

## 22.3 Конвейер

1. **Разбор** каждого файла в синтаксическое дерево с каноническим форматированием (см. [01-lexical](01-lexical.ru.md)).
2. **Типизированное дерево**: разрешение имён, вывод и проверка типов, дженерики, `enum`, исчерпывающий `switch`.
3. **Эффекты**: сводки эффектов по пакетам, затем подстановка по всей программе (22.5).
4. **Проверки**: эффекты против профилей, `anlang.mod` и цели; контракты встроенным решателем; исключительность `inout`; владение периферией; анализ безопасности `nil`.
5. **Общее SSA-представление** с эффектами, одинаковое для всех целей.
6. **Оптимизации**, не зависящие от архитектуры.
7. **Понижение** под архитектуру по декларативным правилам выбора команд из её описания.
8. **Запись формата бинарника**: flat, MZ, ELF, PE, Mach-O, wasm, Intel HEX, UF2, BIN.
9. **Отчёты**: размер по пакетам, глубина стека, карта памяти.

## 22.5 Вывод эффектов

Нормативная семантика эффектов задана в [07-effects](07-effects.ru.md). Алгоритм состоит из двух шагов.

1. **Сводки по пакетам.** Граф вызовов пакета разбивается на компоненты сильной связности (рекурсия) и обходится снизу вверх с объединением множеств эффектов до неподвижной точки. Вызов через параметр (функциональное значение, метод интерфейса-параметра, метод параметра-типа) добавляет в сводку параметрическую ссылку вместо конкретного множества. Сводка зависит только от пакета и сводок импортируемых им пакетов, поэтому кэшируется по их хэшам.
2. **Подстановка по всей программе.** При сборке параметрические ссылки заменяются эффектами конкретных переданных функций и реализаций, а открытые ссылки на интерфейсы, сохранённые в структурах данных, — объединением сохранённых там реализаций. Этот шаг дешёвый; он проверяет ограничения профилей, целей, `anlang.mod` и обработчиков `interrupt`.

## 22.6 Понижение семантики значений

| Конструкция | Как компилируется |
| --- | --- |
| `inout` | указатель на время доступа; компилятор гарантирует, что других доступов к значению в это время нет |
| большое значение в аргументе | передаётся по указателю без копии, если вызываемая функция его не изменяет |
| типы синхронизации | указатель на объект; объект живёт в кадре создавшей его функции, если дескриптор не уходит в `task.Detach`, иначе — в куче с атомарным счётчиком ссылок |
| строки, срезы, словари | заголовок и буфер со счётчиком ссылок; запись в разделяемый буфер сначала его копирует; счётчик атомарный только для значений, переданных между задачами |
| `enum` | тег и объединение вариантов; `Option[T]` без тега, если у `T` есть недопустимое битовое представление |
| срез | указатель, длина и ёмкость размером в машинное слово каждый |
| проверки переполнения и границ | переход к обработчику паники цели; удаляются, если решатель доказал безопасность |

## 22.7 Кэш сборки

Ключ кэша пакета — хэш его исходников, хэши импортируемых им пакетов, цель и версия компилятора. Повторная сборка без изменений сводится к компоновке.

## 22.8 Решатель

Решатель пишется на Go вместе с прототипом, затем на Anlang. Нормативный интерфейс — детерминизм за счёт лимита шагов, сертификаты, контрпримеры — задан в [08-contracts](08-contracts.ru.md). Возможности наращиваются по этапам:

| Этап | Что доказывается | Типичные контракты |
| --- | --- | --- |
| 1 | линейная целочисленная арифметика | диапазоны, границы массивов, `lo <= hi` |
| 2 | битовые векторы | отсутствие переполнения, `bits.WrappingAdd`, маски регистров |
| 3 | массивы и срезы | содержимое после копирования, инварианты циклов |
| 4 | `enum` и `Option` | какой вариант возможен в данной точке |
| 5 | ограниченные кванторы | «для всех i в диапазоне» |

Доказанные условия кэшируются локально по хэшу условия и его контекста; неизменный код повторно не доказывается.

**comp.solver.stage1** — Этап 1 (шаг плана 20) — пакет `verify`. Он опровергает конъюнкцию из **contract.solver.normal-form** поиском, который по порядку разбирает её дизъюнкции, пропуская дизъюнкцию, которой удовлетворяет неравенство конъюнкции, и решает каждую конъюнкцию неравенств исключением Фурье — Моцкина над целыми: каждое выведенное неравенство усиливается (**contract.solver.certificate-form**), а исключение переменной берёт пары её верхних и нижних границ. Противоречие даёт шаги опровержения; иначе подстановка в обратном порядке исключения даёт рациональное решение, где у каждой переменной, в границах которой есть целое, — ближайшее к 0 целое. Решение с целыми значениями — контрпример; иначе поиск ветвится по первой переменной, значение v которой не целое, в точке ⌊v⌋, не глубже 64 ветвлений: более глубокая ветвь сдаётся, но контрпример, найденный в другой ветви, остаётся контрпримером. Проверщик — пакет `verify/check`, общие у них только типы данных.

**comp.solver.stage2** — Этап 2 (шаг плана 22) добавляет битовые векторы, которые `verify/vc` кодирует в линейной целочисленной арифметике, и распространение границ в решателе. Перед исключением решатель ограничивает каждую переменную строки этой строкой и границами её остальных переменных, с усилением, раундами, пока границы меняются, не более 64 раундов; переменная с равными границами подставляется в остальные строки, а её граница, которую выводит подстановка другой переменной и которую нарушает её значение, даёт противоречие. Каждая такая граница — шаг сертификата. Кодирования для значения x целого типа из n битов с диапазоном [lo, hi]:

1. *Перенос по модулю.* Арифметическая операция циклического типа, преобразование в циклический тип и `x << k` на константу k — терм r = x − 2ⁿ·q с новой переменной q и фактом lo ≤ r ≤ hi.
2. *Маски и сдвиги.* `x & (2ᵐ − 1)` — это x − 2ᵐ·q с 0 ≤ x − 2ᵐ·q ≤ 2ᵐ − 1, а `x >> k` на константу k — q с 2ᵏ·q ≤ x ≤ 2ᵏ·q + 2ᵏ − 1.
3. *Биты.* Биты x — новые переменные b₀ … bₙ₋₁ в [0, 1] с цепочкой делений пополам xᵢ = 2·xᵢ₊₁ + bᵢ от x₀ = x, где каждое xᵢ лежит в диапазоне оставшихся битов, а последнее равно bₙ₋₁ или −bₙ₋₁ для знакового типа. Остальные битовые операции соединяют биты по одному: z = a ∧ b через z ≤ a, z ≤ b, z ≥ a + b − 1, z ≥ 0; z = a ∨ b через z ≥ a, z ≥ b, z ≤ a + b, z ≤ 1; z = a ⊕ b через z = a + b − 2·c с c = a ∧ b; бит константы сразу даёт результат. Результат — Σ 2ⁱ·zᵢ, с весом −2ⁿ⁻¹ у старшего бита знакового типа.

Частные масок и сдвигов и биты терма определяются один раз для терма в точке программы, а биты результата битовой операции — её zᵢ, так что у равных термов одни и те же переменные и решателю не нужно доказывать их равенство. Битовая операция в выражении контракта над значениями вне диапазона типа операции имеет неизвестный результат (**contract.expr.bitwise**).

**comp.solver.search** — С шага плана 24 поиск расщепляет только дизъюнкцию, которую нарушает рациональная модель неравенств: из таких — ту, у которой меньше всего членов, не опровергаемых распространением границ за 2 000 шагов, которые учитываются. Если модель выполняет все дизъюнкции, поиск ветвится по значению, которое не целое. Опровержение случая, которое не использует ни неравенств, ни дизъюнкций, добавленных случаем, опровергает конъюнкцию без расщепления, и остальные случаи не ищутся. Модель, которая нарушает неравенство конъюнкции, не является контрпримером: обязательство неизвестно. Исключение берёт сначала переменную с коэффициентом ±1 в равенстве — паре строк e ≤ c и −e ≤ −c — и соединяет каждую другую строку с этой переменной с той половиной равенства, которая её сокращает.

**comp.vc** — Пакет `verify/vc` создаёт обязательства доказательства программы после вывода эффектов и вычислений при компиляции. Он символически исполняет тело каждой функции по синтаксическому дереву: целое значение — линейный терм над переменными решателя, логическое — формула, структура — значения её полей, а срез, массив или строка — терм своей длины и, для целых элементов, последовательность элементов и смещение своего первого элемента в ней. Элементы последовательности задаются её префиксной суммой — функцией P с P(0) = 0, элемент j которой равен P(j+1) − P(j): применение P — переменная для каждого терма с фактами, что она равна другим применениям при равных аргументах; `math.Sum` части последовательности — разность двух применений; запись v в элемент j даёт новую последовательность, префиксная сумма которой равна P до j и P плюс изменение элемента после j. Префиксные суммы литерала среза или массива из целых констант — константы при константных аргументах, а для не более чем 64 элементов при другом аргументе — одна из них или неизвестное значение вне [0, n]. У переменной, захваченной функциональным литералом, элемента другого типа, поля неотслеживаемого значения и переменной уровня пакета при каждом чтении неизвестное значение с диапазоном их типа и, кроме захваченной переменной, инвариантами её типа (**contract.type.assume**); так же у параметров на входе и результатов вызовов. Факты точки — предусловия, условия пути, постусловия вызовов перед ней и проверки перед ней. После ветвления состояния объединяются: факты каждой ветви с точки ветвления образуют член дизъюнкции, а переменная с разными значениями получает новую переменную, равную значению каждого члена. Цикл выполняет тело один раз из состояния перед ним, в котором у переменных, которые цикл изменяет — сами или их элементы и поля, — неизвестные значения (**contract.loop.default**, **contract.loop.induction**). Тело случая, которое кончается `fallthrough`, продолжается в следующее тело, которое начинается из объединения своего случая и этого конца. Цикл range по строке ограничивает только ключ, потому что ключ считает байты, а значение — руна. При каждом возврате переменные, переданные как `inout` в отложенные вызовы функции, или содержащие такой аргумент, получают неизвестные значения до доказательства постусловий, а именованные результаты читаются после этого (**stmt.defer.go**). Цикл с инвариантами доказывает их перед циклом и после тела и оператора после итерации на каждом пути, продолжающем цикл, и предполагает их в заголовке, а значит, и на выходе; у цикла range по n или xs в заголовке есть число завершённых итераций k, 0 ≤ k ≤ n, где отрицательное n заменяется на 0, с ключом k в теле, k + 1 в доказательстве после тела и n на выходе (**contract.loop.obligations**, **contract.loop.range**). Инварианты типов-структур доказываются на границах из **contract.type.boundaries**: в составных литералах, для параметров и получателя `inout` при каждом возврате, для аргументов и получателей вызовов, результатов, значений, отправляемых в каналы, и записей в поля, элементы и переменные уровня пакета; структура из более чем 64 значений, считая поля её полей, не отслеживается, и граница такого значения отвергается как ещё не поддерживаемая. До функций пакета решатель для каждого типа-структуры с инвариантами решает, выполняет ли их нулевое значение с нулевыми значениями полей (**contract.type.zero**). Значение перечислимого типа — индекс его варианта и значения полей каждого варианта: switch по вариантам предполагает индекс в каждом случае и даёт привязкам поля, а `Option.Get` даёт значение `Some` и то, равен ли индекс индексу `Some`. Квантор в контракте — предикат для новой переменной там, где формуле он нужен для каждого значения, — `ForAll` в цели или `Exists` в факте, или наоборот под отрицанием, — а иначе новое логическое значение, экземпляры которого — для `ForAll` логическое значение и i в [lo, hi), влекущие предикат в i, — берутся в индексах элементов, которые читает состояние, за вычетом смещений последовательностей и констант d выражений индекса x[i+d] предиката, не больше 32 (**std.math.quantifier**). Конгруэнтности префиксных сумм выполняются в каждом состоянии. Доказательство сначала даёт решателю факты состояния; конгруэнтности и экземпляры присоединяются к ним раундами, не больше 16, — каждые из тех, которые контрпример решателя нарушает или не решает, имея переменную контрпримера. Вызов доказывает предусловия вызываемой функции с аргументами, даёт переменным, переданным как `inout`, неизвестные значения и предполагает постусловия, в которых `old` даёт значения аргументов до вызова; в теле `old` даёт значения параметров на входе (**contract.expr.old**). Функция с `goto` или параметрами-типами не исполняется: её контракты отвергаются как ещё не поддерживаемые, а её сужающим преобразованиям нужны только факты выражения. Вызов функции в её собственном теле запоминает состояние и аргументы для границы глубины её рекурсии (**rt.stack.core-recursion**), которую IR хранит в `RecursionDepth` функции. Результаты пакета используются повторно, пока исходники пакета и пакетов перед ним те же. Доказанные проверки отмечаются в IR (`Proven` у команд индекса, среза и арифметики), и генератор кода не порождает для них проверок (**contract.check.proven**).

## 22.9 Самосборка

1. **Этап 0.** Компилятор пишется на Go. Синтаксис Anlang основан на Go, поэтому парсер, структуры данных и большая часть логики потом переносятся на Anlang почти построчно. Go даёт быструю сборку, простую кросс-компиляцию, один исполняемый файл без зависимостей и purego как проверенный образец вызова внешнего кода.
2. **Этап 1.** Компилятор переносится с Go на Anlang (с помощью `anlang port`) и собирается версией на Go.
3. **Этап 2.** Компилятор этапа 1 заново собирает собственные исходники; полученный исполняемый файл ДОЛЖЕН побайтово совпасть с исполняемым файлом этапа 1 (см. [23-conformance](23-conformance.ru.md), **conf.self-hosting**).
4. **Этап 3.** Версия на Go сохраняется в архиве для раскрутки с нуля и проверки компилятора на закладки (**impl.bootstrap.archive**).

Для этапа 1 нужны цели машины разработчика (x86-64 и arm64) и аллокатор `app`; см. [24-roadmap](24-roadmap.ru.md).

## 22.10 Промежуточное представление

Промежуточное представление (IR) — общая SSA-форма шага 5 конвейера (22.3). Его строит пакет `lower` из типизированного дерева всей программы, а выполняет интерпретатор IR из пакета `interp`, который служит эталоном для каждого бэкенда (см. [23-conformance](23-conformance.ru.md), **conf.backend.ir**).

### 22.10.1 Устройство

- *Программа* — набор функций с выделенной функцией `main`, размер `int` для цели и наборы методов конкретных типов, преобразуемых в интерфейсы; они нужны динамическим вызовам и утверждениям типа.
- *Функция* имеет параметры, свободные переменные (у функциональных литералов) и граф базовых блоков; первый блок — входной. Каждый блок заканчивается ровно одной управляющей инструкцией: `jump`, `if`, `return` или `panic`.
- Каждое значение определяется один раз (SSA). Значения — это результаты инструкций, параметры, свободные переменные, константы, функции и встроенные функции.
- Локальные переменные — ячейки: `alloc` даёт адрес новой ячейки, `load` читает её, `store` записывает. Поэтому переменные, захваченные функциональными литералами, и переменные, части которых изменяются, обходятся без φ-функций; последующий проход может превратить ячейки в SSA-значения.
- `inout`-параметр — это адрес. `fieldaddr`, `indexaddr` и `subsliceaddr` дают адреса частей значений; `inout`-аргумент передаёт такой адрес (**mem.inout.param**, **mem.inout.subslice**).
- Типы — это типы чекера с подставленными параметрами типа: обобщённые функции и типы переводятся мономорфизацией, по одной функции на каждый список аргументов типа.
- Семантика значений явная: `copy` отмечает каждое место логического копирования значения (присваивание, передача аргумента, возврат, запись в часть, захват замыканием). Бэкенд реализует его копированием при записи (22.6); интерпретатор разделяет значение и копирует его при первой записи по адресу.
- Отображение железа (**mem.unsafe.map**) — значение `global`: адрес его памяти, печатаемый его полным именем. Оператор `asm` — команда `asm(regs) "text"`, результат которой содержит выходные регистры (**stmt.asm.syntax**).
- О конструкциях, перевод которых относится к более поздним шагам плана (каналы, `go`, `select`, вычисления при компиляции, стандартная библиотека), построитель IR сообщает, что они пока не поддерживаются, с номером шага.

### 22.10.2 Текстовый формат

`anlang build -ir` выводит IR программы в следующем текстовом формате (см. [20-toolchain](20-toolchain.ru.md)). Формат предназначен для чтения и тестов; инструментарий его не принимает на вход. Например, функция

```go
func Sum(xs []int) int {
    t := 0
    for _, x := range xs {
        t += x
    }
    return t
}
```

из пакета `main` модуля `conf` выводится так:

```
func conf.Sum(xs []int) int
b0: // entry
	t0: *[]int = alloc // xs
	store t0, xs
	t1: *int = alloc // t
	store t1, 0:int
	t2: []int = load t0
	t3: []int = copy t2
	t4: int = call len(t3)
	t5: *int = alloc // index
	store t5, 0:int
	jump b1
b1: // range.head; preds: b0, b3
	t6: int = load t5
	t7: bool = t6 < t4
	if t7 b2 b4
b2: // range.body; preds: b1
	t8: int = index t3, t6
	t9: *int = alloc // x
	store t9, t8
	t10: int = load t9
	t11: int = load t1
	t12: int = t11 + t10
	store t1, t12
	jump b3
b3: // range.post; preds: b2
	t13: int = load t5
	t14: int = t13 + 1:int
	store t5, t14
	jump b1
b4: // range.done; preds: b1
	t15: int = load t1
	return t15
```

1. Функция начинается с заголовка `func NAME(PARAMS) RESULTS`, за которым у функции со свободными переменными следует `free(...)`. `NAME` — путь пакета и имя: `conf.main`, `conf.Point.Add` для метода, `conf.Map[int,string]` для экземпляра обобщённой функции, `conf.Stack.Push[string]` для метода экземпляра обобщённого типа, `conf.main$lit1` для функционального литерала, `conf.main$yield2` для тела цикла range-over-func, `Option[int].Some` для конструктора варианта, `conf.Print(int,string)` для экземпляра функции с параметром `...any`, элементы кортежа которой — отдельные параметры `args$0`, `args$1`, …. `inout`-параметр записывается как `NAME inout TYPE`.
2. Каждый блок начинается строкой `bN:`, за которой может идти комментарий с происхождением блока и его предшественниками.
3. Каждая инструкция занимает отдельную строку с отступом в одну табуляцию. Инструкция с результатом записывается как `tK: TYPE = OPERATION`, без результата — как `OPERATION`. Номера результатов уникальны в пределах функции.
4. Операнд записывается как имя результата `tK`, имя параметра или свободной переменной, имя функции или встроенной функции либо константа `VALUE:TYPE`; нулевое значение типа записывается как `zero:TYPE`.
5. Типы записываются как в исходном коде Anlang; адрес значения типа `T` записывается как `*T`. Это единственное место, где встречается `*T`: это тип IR, а не тип Anlang.

Операции:

| Операция | Значение |
| --- | --- |
| `alloc` | адрес новой ячейки с нулевым значением; комментарий называет переменную |
| `load a`, `store a, v` | чтение и запись значения по адресу `a` |
| `copy v` | логическая копия `v` (**mem.value.copy**) |
| `fieldaddr a, i`, `indexaddr a, i` | адрес поля `i` / элемента `i` значения по адресу `a`; `indexaddr` проверяет границы |
| `subsliceaddr a[lo:hi]` | адрес элементов с `lo` по `hi-1` среза или массива по адресу `a` для `inout`-аргумента (**mem.inout.subslice**) |
| `field v, i`, `index v, i` | поле / элемент значения; `index` проверяет границы |
| `lookup m, k [, ok]` | элемент словаря или нулевое значение; с `ok` — пара «значение, ok» |
| `mapupdate a, k, v` | записывает элемент словаря по адресу `a` |
| `slice v[lo:hi:max]` | выражение среза; опущенные границы пусты |
| `x OP y`, `OP x` | арифметические, логические операции и сравнения; целочисленные операции проверяемых типов паникуют при переполнении (**expr.int.checked**) |
| `convert v`, `makeinterface v` | преобразование к типу результата; преобразование конкретного значения к интерфейсному типу |
| `typeassert v.(T) [, ok]` | утверждение типа |
| `makeslice n, c`, `makemap`, `makestruct {...}`, `makearray [...]` | создание значений; `makearray` создаёт массив или элементы составного литерала среза |
| `makevariant #i {...}`, `variantindex v`, `variantfield v, #i.j` | создание варианта `i` значения `enum`, номер его варианта, поле `j` варианта `i` |
| `closure F [bindings]` | функциональное значение `F` со значениями его свободных переменных |
| `call f(args)`, `invoke v.M(args)` | вызов функции, функционального значения или встроенной функции; динамический вызов метода `M` значения интерфейса |
| `extract t, i` | результат `i` вызова с несколькими результатами |
| `jump bN`, `if v bT bF`, `return [vs]`, `panic v` | управляющие инструкции |
| `defer CALL` | отложенный вызов; аргументы вычисляются при выполнении `defer` (**stmt.defer.go**) |

Встроенные функции сохраняют имена Anlang (`len`, `append`, `copy`, `delete`, `print`); функции `an/fmt` и `an/bits`, встроенные в компилятор до шагов 9–10 плана, называются `fmt.Print`, `fmt.Println`, `fmt.Sprint` и `fmt.Sprintln`, а функции `an/bits` — `bits.WrappingAdd` … `bits.CheckedMul`; вспомогательные функции, которые вводит построитель IR, имеют имена, не являющиеся идентификаторами Anlang программы (`appendslice`, `appendstring`, `mapkeys`, `decoderune`, `Option.Get`).

### 22.10.3 Интерпретатор IR

`anlang run -emu ir` строит IR программы и выполняет его в интерпретаторе IR (**tool.emu.ir**). Интерпретатор:

- реализует семантику значений копированием при записи разделяемых значений, поэтому его наблюдаемое поведение — это поведение, определённое в [06-memory](06-memory.ru.md);
- вычисляет циклические типы `an/wrap` по модулю 2ⁿ (**expr.wrap.ops**) и функции `an/bits` (**expr.bits.functions**);
- выполняет проверки языка во время исполнения, с сообщениями о панике как в Go: целочисленное переполнение (**expr.int.checked**, **expr.int.div**), деление на ноль, границы, преобразования дробных чисел в целые (**type.conv.float-int**), длину `inout`-подсреза (**mem.inout.subslice**);
- выводит результат `fmt.Print` и `fmt.Println` в стандартный вывод, а `print`, `println` и сообщения о панике — в стандартный поток ошибок, в форматах Go;
- не имеет адресов: в выводе `print` указатель любого не-nil словаря, среза, функции или значения интерфейса печатается как `0x1`;
- не выполняет каналы, `go` и `select` (шаг 30 плана);
- не выполняет операторы `asm` и вызовы функций пакетов команд, относящиеся к одной архитектуре: программа, которая до них доходит, останавливается с ошибкой, а `unsafe.Data` возвращает 0.

## 22.11 Генерация кода

Генератор кода (пакет `codegen`) — бэкенд каждой архитектуры. Им управляют описание архитектуры и описание платформы, и в нём нет ничего, относящегося к одной архитектуре (**target.arch.no-compiler-change**). Он переводит IR программы вместе с используемыми ею функциями пакета времени выполнения `an/runtime` в машинные операции, заменяет каждую операцию шаблоном правила выбора команд ([13-targets](13-targets.ru.md), 13.5.7) и компонует результат в один образ, который записывает формат бинарника.

### 22.11.1 Раскладка данных

**comp.gen.layout** — Значения раскладываются в памяти так; значение выравнивается по меньшему из его размера и `ABI.Align`, а многобайтовые целые хранятся в порядке байтов архитектуры.

| Тип | Раскладка |
| --- | --- |
| `bool` | 1 байт, 0 или 1 |
| целые и циклические типы | их разрядность |
| `f32`, `f64` | IEEE 754 binary32 и binary64: биты как беззнаковое целое той же разрядности |
| `string` | адрес байтов, затем длина (`int`) |
| `cstring`, `dstring` | адрес байтов, которые заканчиваются терминатором |
| срез | адрес элементов, длина и ёмкость (`int`) |
| массив | элементы по порядку |
| структура | поля по порядку, каждое со следующего смещения, выровненного для него |
| `enum`, `Option` | номер варианта (1 байт для не более чем 256 вариантов, иначе 2), затем поля варианта, разложенные как структура; размер — размер наибольшего варианта |
| функция | адрес её кода |
| интерфейс | номер типа разрядности слова, 0 для `nil`, затем 8 байт: динамическое значение не больше 8 байт — на месте, большее — по адресу |

Номера типов интерфейсов назначаются в каждой программе динамическим типам, которые в ней встречаются; другой информации о типах во время выполнения нет (**rt.no-rtti**).

### 22.11.2 Кадры и вызовы

**comp.gen.frame** — У каждой функции есть кадр стека. Ниже базы кадра в нём лежит слот для каждого значения IR и каждой ячейки, а по младшим адресам — область аргументов её вызовов. Область аргументов содержит аргументы по порядку, каждый выровненный по `ABI.Align`, а за ними результаты. Функция обращается к своим параметрам и результатам по базе кадра плюс `ABI.Params` (**target.arch.abi**) и записывает туда результаты перед `leave`. Параметр `inout` передаётся адресом. Вызывающая функция копирует результаты из своей области аргументов после вызова. При `ABI.FrameBottom` регистр кадра хранит низ кадра, и слот, параметр или результат находится по размеру кадра плюс его смещение от базы кадра. Кадр есть и у входного кода (**target.platform.entry**).

**comp.gen.values** — Значение IR вычисляется в свой слот один раз и потом не меняется; константа — операнд шаблона, а строка или константа составного типа хранится в константных данных образа. `load` копирует значение из ячейки в свой слот, `store` копирует его в ячейку, а `copy` использует слот своего операнда. `slice` от массива в ячейке сначала копирует массив в слот результата, чтобы последующие записи в ячейку не меняли срез (**mem.value.copy**).

**comp.gen.escape** — Срез, элементы которого лежат в кадре стека, НЕ ДОЛЖЕН переживать кадр. До анализа ускользания (шаг 25 плана) генератор кода отвергает функцию, возвращающую значение с таким срезом, как ещё не поддерживаемую.

**comp.gen.handler** — Обработчик прерывания ([14-embedded](14-embedded.ru.md), **emb.irq.name**) — функция, которая начинается с `enter.handler` и возвращается через `leave.handler` (**target.arch.ops**). Генератор кода связывает её с вектором её прерывания (**emb.irq.vectors**).

**comp.gen.static** — Переменная уровня пакета атомарного типа — ячейка хранения в изменяемых данных образа, которые очищает код входа (**target.platform.entry**); её адрес — константный операнд.

**comp.gen.stack** — Для программы, пакет `main` которой выполняется в профиле `core`, генератор кода вычисляет стек, нужный программе, по кадрам её функций (**emb.stack.compute**). Он отвергает сборку с рекурсией без доказанной границы (**emb.stack.recursion**) с циклом вызовов, а на цели с размером `Stack` — сборку, которой нужно больше (**emb.stack.limit**), с самой глубокой цепочкой вызовов и размером кадра каждой. Программа в другом профиле использует стек без этого анализа; на `wasm32` шаблон `enter` вызывает ловушку, когда указатель стека опускается ниже наименьшего адреса стека (**rt.stack.reserve**).

**comp.gen.structured** — На архитектуре со структурным потоком управления (**target.arch.structured**) генератор кода размещает код каждой подпрограммы в блоках и циклах методом Н. Рэмси «Beyond Relooper» (2022). Части подпрограммы между её метками — узлы её графа потока управления; рёбра — метки в шаблонах узла и, если узел не кончается `jump`, `leave`, `leave.handler` или `exit`, переход к следующему узлу. Узлы, недостижимые из входа, опускаются. По обратному постпорядку и дереву доминаторов графа ребро в узел, который не позже в этом порядке, — обратное ребро, а его цель — *заголовок цикла*; узел, в который ведёт метка из более раннего узла или более одного ребра из более ранних узлов, — *узел слияния*. Код узла `x`: если `x` — заголовок цикла, то `loop`, затем код внутри, затем `end`; код внутри — для узлов слияния, которые `x` непосредственно доминирует, в порядке убывания, `block`, код внутри для остальных, `end` и код этого узла слияния, а в конце — шаблоны `x`, за которыми, если `x` переходит к узлу `s`, идёт `jump` в `s`, если `s` — узел слияния или заголовок цикла, а иначе код `s`. Операнд метки становится числом объемлющих блоков и циклов до блока или цикла её цели — её *глубиной метки*; несводимый граф, которого не бывает у подпрограмм Anlang, — ошибка сборки.

### 22.11.3 Понижение команд IR

**comp.gen.lower** — Генератор кода выражает команды IR машинными операциями (**target.arch.ops**):

| IR | Машинные операции |
| --- | --- |
| арифметика проверяемого целого типа | `add.s`, `add.u`, `sub.s`, … с меткой ловушки, вызывающей `PanicOverflow` (**expr.int.checked**) |
| арифметика циклического типа | `add`, `sub`, `mul`, … (**expr.wrap.ops**) |
| `/` и `%` | проверка делителя, вызывающая `PanicDivide` для 0; для проверяемого знакового типа — проверка деления минимума на −1, вызывающая `PanicOverflow`, а для циклического знакового типа — результат **expr.wrap.div** без деления; затем `div.s`, `div.u`, `rem.s` или `rem.u` |
| сдвиги | проверка знакового числа сдвига, вызывающая `PanicShift`, если оно отрицательно; число шире слова ограничивается наибольшим значением слова; затем `shl`, `shr.u` или `shr.s` |
| сравнения | `eq` … `le.u` для целых; для строк и составных значений — вызовы функций времени выполнения или сравнения частей |
| преобразования между целыми типами | `ext.s` или `ext.u` к более широкому типу, `move` младшей части к более узкому |
| `fieldaddr`, `indexaddr`, `field`, `index` | вычисление адресов с `add` и `mul`; проверка границ вызывает `PanicIndex` (**expr.bounds.check**) |
| `slice`, `subsliceaddr` | вычисление адресов и проверки границ Go, вызывающие функции `PanicSlice…` |
| `alloc`, `makestruct`, `makearray`, `makevariant` | `zero`, `store` и `copy` в слот |
| `call` | аргументы копируются в область аргументов, `call` или `callind`, результаты копируются обратно |
| `invoke` | выбор по номеру типа значения интерфейса метода каждого динамического типа |
| `defer` | запись отложенного вызова в кадре, включённая в цепочку, которую выполняют `return` и функции паники, от новых к старым (**stmt.defer.go**) |
| `if`, `jump` | `branch`, `jump` |
| `return` | отложенные вызовы кадра, затем `leave` |
| `panic` | функции паники со значением, напечатанным в формате интерпретатора IR |
| отображение железа | операции с памятью по его адресу: `load.far` и `store.far` для дальнего адреса |
| вызовы пакета команд, `asm` | `regin`, команды, `regout` и `flagsout` (**target.arch.instr-package**) |
| `fmt.Printf` | формат — константа, разбираемая при компиляции; для каждой директивы — вызов функции печати пакета времени выполнения |
| арифметика, сравнения, преобразования, `min` и `max` для `f32` и `f64` | вызовы функций плавающей точки пакета времени выполнения (**comp.gen.float**) |

### 22.11.4 Пакет времени выполнения

**comp.gen.runtime** — Пакет времени выполнения `an/runtime`, который компонует каждая программа, — исходный код на Anlang в профиле `core` (**rt.lang.anlang**). Он предоставляет функции, которые вызывает генератор кода: печать значений для `fmt.Print`, `fmt.Println`, `print` и `println` в форматах 22.10.3, функции паники, которые выполняют отложенные вызовы, а затем действие цели при панике с сообщениями интерпретатора IR, и арифметику операций без правил (**target.arch.select**). Его функции `write`, `read` и `exit` — примитивы, которые генератор кода реализует операциями платформы с теми же именами, `read` — с числом 1 в свой `inout`-байт, который возвращает `ReadByte` для `console.ReadByte` (**std.console.read**), а `DisableInterrupts` и `RestoreInterrupts` — операциями `irq.save` и `irq.restore` или ничем на цели без них. `PanicInterrupt` — обработчик по умолчанию таблицы векторов (**emb.irq.vectors**). Функция пакета времени выполнения попадает в образ, только если программа её вызывает (**rt.link.piecewise**).

**comp.gen.float** — Значения с плавающей точкой вычисляются программно на каждой цели (**target.floats.soft**), пока у цели с аппаратной плавающей точкой нет правил для них. Пакет времени выполнения предоставляет для f64 над битами как `u64` и для f32 над битами как `u32`: `AddF64`, `SubF64`, `MulF64`, `DivF64`, `NegF64`, `EqF64`, `LtF64`, `LeF64`, `MinF64`, `MaxF64`, преобразования `F64FromI64`, `F64FromU64`, `F64FromF32`, `F32FromF64`, `F32FromI64`, `F32FromU64`, `I64FromF64`, `U64FromF64` (с разрядностью целого; возвращают, помещается ли отброшенное к нулю значение, так что значение, которое не помещается, вызывает `PanicOverflow`, **type.conv.float-int**) и то же с `F32`. Результаты — как в IEEE 754 с округлением к ближайшему, при равенстве к чётному; результат NaN — тихий NaN без полезной нагрузки. Операция над f32 вычисляется в binary64 и округляется один раз, что даёт результат binary32 для сумм, разностей, произведений и частных. `PrintFloat` печатает для `fmt.Print` кратчайшие цифры, которые читаются обратно как то же значение, `PrintFloatF` — глаголы `e`, `E`, `f`, `F`, `g`, `G` и `v` функции `fmt.Printf` с шириной, точностью и флагами `+`, `-`, пробел и `0` и правильно округлёнными цифрами, а `PrintF64` печатает для `print` как печать времени выполнения Go; цифры получаются точной арифметикой над натуральными числами до 1280 битов.

**comp.gen.panic** — До отдельных отладочных таблиц (шаг 41 плана) действие `PrintAndExit` записывает в стандартный поток ошибок `panic: `, причину и перевод строки, без трассировки стека (**rt.panic.trace**), и завершает программу с кодом 2.

### 22.11.5 Компоновка

**comp.gen.link** — Компоновщик размещает код входа (**target.platform.entry**), функции и константные данные, в этом порядке, с начального адреса формата бинарника или с начала первой области `Exec` у цели с областями памяти; изменяемые данные идут за ними или лежат в начале первой области без `Exec` (**target.memory.placement**). Он ассемблирует каждую команду порождённым ассемблером по её адресу; поскольку длина команды может зависеть от адресов меток, размещение повторяется, пока ни одна длина не изменится, а команда, которая не ассемблируется ни по одному адресу размещения, получает длину на следующем. Сборка, образ которой превышает ограничение размера формата или области, отвергается с размером кода каждого пакета, константных данных и статических данных (**target.format.size**, **target.memory.overflow**). Компоновщик также сообщает адрес каждой функции — карту памяти образа.

**comp.gen.link-structured** — На архитектуре со структурным потоком управления компоновщик ассемблирует код каждой подпрограммы как одну функцию в порядке порождения после импортов платформы (**target.platform.imports**); адрес подпрограммы — индекс её функции. Он размещает константные данные, а затем изменяемые данные, которые кончаются стеком `main` (**target.memory.stack**), с начального адреса первого формата. Образ содержит функции, данные, индекс кода входа и размер памяти, которые формат записывает как модуль (**target.format.wasm**).

### 22.11.6 Охват

**comp.gen.coverage** — Генератор кода шага 13 плана переводит все конструкции профиля `core`, кроме следующих, о которых он сообщает как о ещё не поддерживаемых, с шагом плана, который их добавляет: операторы `defer` в циклах, `inout`-подсрезы, `inout`-доступ к отображениям железа по дальним адресам, директивы `fmt.Printf`, кроме `%v`, `%d`, `%s`, `%t`, `%c`, `%x`, `%X`, `%o`, `%b` с флагами, шириной и точностью, а для значений с плавающей точкой — кроме `%e`, `%E`, `%f`, `%F`, `%g`, `%G` и `%v` без флага `#` (шаг 25).
