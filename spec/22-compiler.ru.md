# 22. Компилятор

Этот файл описывает, как устроен компилятор `anlang`. Он *справочный*, кроме правил с идентификаторами — это нормативные требования к реализации.

## 22.1 Нормативные требования

**impl.single-binary** — Инструментарий ДОЛЖЕН быть одним исполняемым файлом. Он НЕ ДОЛЖЕН требовать внешнего компилятора, ассемблера, компоновщика, решателя или SDK другого языка, чтобы собирать, проверять, тестировать и запускать программы на Anlang. Единственное исключение — подпись приложений iOS инструментами Apple (см. [17-ui](17-ui.ru.md)).

**impl.no-external-solver** — Решатель для контрактов ДОЛЖЕН быть частью инструментария. Внешние решатели (например, Z3 или cvc5) НЕ ДОЛЖНЫ использоваться.

**impl.cache.transparent** — Использование кэша сборки НЕ ДОЛЖНО менять ни один результат, диагностику или ответ протокола. Сборка с пустым кэшем и сборка с заполненным кэшем ДОЛЖНЫ давать побайтово одинаковые результаты.

**impl.incremental** — После изменения одной функции повторной проверке СЛЕДУЕТ занимать доли секунды на типичном проекте.

**impl.abi.external** — Внешние функции и колбэки ДОЛЖНЫ использовать C ABI цели, заданный её описаниями архитектуры и платформы (см. [12-ffi](12-ffi.ru.md), [13-targets](13-targets.ru.md)).

**impl.abi.unstable** — Внутренний ABI Anlang не стабилен между версиями компилятора. Поскольку каждый пакет всегда компилируется из исходников, скомпилированная форма пакета никогда не переиспользуется разными версиями компилятора; ключ кэша сборки включает версию компилятора (22.7).

**impl.bootstrap.archive** — Версия компилятора на Go ДОЛЖНА сохраняться, чтобы инструментарий можно было раскрутить с нуля и проверить компилятор на закладки (22.9).

## 22.2 Язык реализации

Прототип — один исполняемый файл `anlang`, написанный на Go без cgo. После шагов самосборки (22.9) компилятор написан на Anlang. Компилятор видит программу целиком — весь код лежит в проекте и стандартной библиотеке, — но кэширует результаты по пакетам.

## 22.3 Конвейер

1. **Разбор** каждого файла в синтаксическое дерево с каноническим форматированием (см. [01-lexical](01-lexical.ru.md)).
2. **Типизированное дерево**: разрешение имён, вывод и проверка типов, дженерики, `enum`, исчерпывающий `switch`.
3. **Эффекты**: сводки эффектов по пакетам, затем подстановка по всей программе (22.5).
4. **Проверки**: эффекты против профилей, `anlang.mod` и цели; контракты встроенным решателем; исключительность `inout`; владение периферией; анализ безопасности `nil`.
5. **Общее SSA-представление** с эффектами, одинаковое для всех целей.
6. **Оптимизации**, не зависящие от архитектуры.
7. **Понижение** под архитектуру по декларативным правилам выбора команд из её описания.
8. **Запись формата бинарника**: flat, MZ, ELF, PE, Mach-O, wasm, Intel HEX, UF2, BIN.
9. **Отчёты**: размер по пакетам, глубина стека, карта памяти.

## 22.4 Пакеты реализации

| Пакет | Ответственность |
| --- | --- |
| `syntax` | лексер, парсер, дерево, каноническое форматирование |
| `types` | разрешение имён, проверка типов, дженерики, `enum`, исчерпывающий `switch` |
| `effects` | вывод эффектов, проверка на границах |
| `verify` | обязательства доказательства из контрактов, встроенный решатель, проверщик сертификатов |
| `ir` | общее SSA-представление с эффектами |
| `lower` | семантика значений, копирование при записи, `enum`, проверки переполнения и границ |
| `arch/...` | описания архитектур; из них — выбор команд, ассемблер, пакеты команд, интерпретаторы |
| `link` | компоновщик и запись форматов: flat, MZ, ELF, PE/COFF, Mach-O, wasm, Intel HEX, UF2 |
| `interp` | встроенные интерпретаторы для тестов |
| `diff` | семантический дифф двух версий кода |
| `server` | протокол среды и LSP |
| `cmd/anlang` | командная строка |

## 22.5 Вывод эффектов

Нормативная семантика эффектов задана в [07-effects](07-effects.ru.md). Алгоритм состоит из двух шагов.

1. **Сводки по пакетам.** Граф вызовов пакета разбивается на компоненты сильной связности (рекурсия) и обходится снизу вверх с объединением множеств эффектов до неподвижной точки. Вызов через параметр (функциональное значение, метод интерфейса-параметра, метод параметра-типа) добавляет в сводку параметрическую ссылку вместо конкретного множества. Сводка зависит только от пакета и сводок импортируемых им пакетов, поэтому кэшируется по их хэшам.
2. **Подстановка по всей программе.** При сборке параметрические ссылки заменяются эффектами конкретных переданных функций и реализаций, а открытые ссылки на интерфейсы, сохранённые в структурах данных, — объединением сохранённых там реализаций. Этот шаг дешёвый; он проверяет ограничения профилей, целей, `anlang.mod` и обработчиков `interrupt`.

## 22.6 Понижение семантики значений

| Конструкция | Как компилируется |
| --- | --- |
| `inout` | указатель на время доступа; компилятор гарантирует, что других доступов к значению в это время нет |
| большое значение в аргументе | передаётся по указателю без копии, если вызываемая функция его не изменяет |
| типы синхронизации | указатель на объект; объект живёт в кадре создавшей его функции, если дескриптор не уходит в `task.Detach`, иначе — в куче с атомарным счётчиком ссылок |
| строки, срезы, словари | заголовок и буфер со счётчиком ссылок; запись в разделяемый буфер сначала его копирует; счётчик атомарный только для значений, переданных между задачами |
| `enum` | тег и объединение вариантов; `Option[T]` без тега, если у `T` есть недопустимое битовое представление |
| срез | указатель, длина и ёмкость размером в машинное слово каждый |
| проверки переполнения и границ | переход к обработчику паники цели; удаляются, если решатель доказал безопасность |

## 22.7 Кэш сборки

Ключ кэша пакета — хэш его исходников, хэши импортируемых им пакетов, цель и версия компилятора. Повторная сборка без изменений сводится к компоновке.

## 22.8 Решатель

Решатель пишется на Go вместе с прототипом, затем на Anlang. Нормативный интерфейс — детерминизм за счёт лимита шагов, сертификаты, контрпримеры — задан в [08-contracts](08-contracts.ru.md). Возможности наращиваются по этапам:

| Этап | Что доказывается | Типичные контракты |
| --- | --- | --- |
| 1 | линейная целочисленная арифметика | диапазоны, границы массивов, `lo <= hi` |
| 2 | битовые векторы | отсутствие переполнения, `bits.WrappingAdd`, маски регистров |
| 3 | массивы и срезы | содержимое после копирования, инварианты циклов |
| 4 | `enum` и `Option` | какой вариант возможен в данной точке |
| 5 | ограниченные кванторы | «для всех i в диапазоне» |

Доказанные условия кэшируются локально по хэшу условия и его контекста; неизменный код повторно не доказывается.

## 22.9 Самосборка

1. **Этап 0.** Компилятор пишется на Go. Синтаксис Anlang основан на Go, поэтому парсер, структуры данных и большая часть логики потом переносятся на Anlang почти построчно. Go даёт быструю сборку, простую кросс-компиляцию, один исполняемый файл без зависимостей и purego как проверенный образец вызова внешнего кода.
2. **Этап 1.** Компилятор переносится с Go на Anlang (с помощью `anlang port`) и собирается версией на Go.
3. **Этап 2.** Компилятор этапа 1 заново собирает собственные исходники; полученный исполняемый файл ДОЛЖЕН побайтово совпасть с исполняемым файлом этапа 1 (см. [23-conformance](23-conformance.ru.md), **conf.self-hosting**).
4. **Этап 3.** Версия на Go сохраняется в архиве для раскрутки с нуля и проверки компилятора на закладки (**impl.bootstrap.archive**).

Для этапа 1 нужны цели машины разработчика (x86-64 и arm64) и аллокатор `app`; см. [24-roadmap](24-roadmap.ru.md).

## 22.10 Открытые вопросы


1. **Текстовый формат IR.** Отложено до реализации — шаг 6. До этого интерпретатор IR и тесты используют текстовую форму, определяемую реализацией.
2. **Формат описаний архитектур.** Отложено до реализации — шаг 11; относится к [13-targets](13-targets.ru.md).
3. **Аллокатор общего назначения для `app`.** Отложено до реализации — шаг 25. Собственный или перенесённый; подходит любой аллокатор, удовлетворяющий [06-memory](06-memory.ru.md) и проходящий фаззинг из [23-conformance](23-conformance.ru.md).
