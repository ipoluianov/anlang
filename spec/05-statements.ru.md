# 05. Операторы

Этот файл описывает, чем операторы Anlang отличаются от операторов Go: `switch` по типам `enum` с шаблонами, завершающие операторы, `range` с `inout`-переменными цикла, `for const`, `go`, `defer` с `inout`-аргументами, правило неиспользованной ошибки и `asm`.

Там, где этот файл молчит, операторы ведут себя как в спецификации Go (см. [README](README.ru.md)). Контрактные строки в начале тела функции, цикла и структуры описаны в [08-contracts](08-contracts.ru.md).

**stmt.go** — Оператор, не изменённый этим файлом, имеет синтаксис, правила и смысл из спецификации Go, включая правила для меток, `break`, `continue`, `goto` и `fallthrough` и требование, чтобы тело функции с результатами заканчивалось завершающим оператором. Программа, нарушающая их, ДОЛЖНА быть отвергнута.

## 1. Switch по типам `enum`

### 1.1 Синтаксис

`switch`, выражение-метка которого имеет тип `enum`, — это *switch по вариантам*. Его ветви содержат *шаблоны вариантов* вместо выражений.

```
VariantSwitchStmt = "switch" [ SimpleStmt ";" ] Expression "{" { VariantCaseClause } "}" .   (new)
VariantCaseClause = VariantSwitchCase ":" StatementList .                                     (new)
VariantSwitchCase = "case" VariantPattern { "," VariantPattern } | "default" .                (new)
VariantPattern    = VariantName [ "{" [ PatternBinding { "," PatternBinding } [ "," ] ] "}" ] . (new)
PatternBinding    = identifier .                                                              (new)
```

`VariantName` определён в [04-expressions](04-expressions.ru.md).

**stmt.switch.variant.parse** — Switch по вариантам разбирается как `ExprSwitchStmt` грамматики Go: каждый `VariantPattern` синтаксически — это `Expression` (идентификатор, квалифицированный идентификатор или составной литерал, элементы которого — идентификаторы). Как switch по вариантам он интерпретируется при проверке типов, когда выражение-метка имеет тип `enum`.

**stmt.switch.variant.tag** — Выражение-метка в switch по вариантам ДОЛЖНО присутствовать. `switch` с меткой типа `enum` НЕ ДОЛЖЕН содержать обычных выражений в ветвях.

### 1.2 Шаблоны и привязки

**stmt.switch.variant.name** — Каждый `VariantName` в шаблоне ДОЛЖЕН обозначать вариант типа `enum` метки.

**stmt.switch.variant.bindings** — Шаблон без фигурных скобок сопоставляется с вариантом и ничего не привязывает. Шаблон со скобками ДОЛЖЕН содержать ровно одну `PatternBinding` на каждое поле данных варианта в порядке объявления полей. Каждая привязка объявляет новую переменную с областью видимости в пределах ветви; её значение — копия соответствующего поля. Пустой идентификатор `_` ничего не привязывает.

**stmt.switch.variant.multi** — Ветвь с несколькими шаблонами НЕ ДОЛЖНА содержать привязок.

```go
switch s {
case Circle{r}:      return math.Pi * r * r
case Rect{w, h}:     return w * h
}

switch m {
case Inc, Dec:       return step(s, m), cmd.None   // несколько шаблонов, без привязок
case Scanned{code}:  return add(s, code), cmd.None
case Clear:          return State{}, cmd.None
}
```

### 1.3 Исчерпывающий разбор

**stmt.switch.variant.exhaustive** — Switch по вариантам без ветви `default` ДОЛЖЕН назвать каждый вариант типа `enum` в каком-либо шаблоне. Поэтому добавление варианта в тип `enum` делает каждый неполный switch по нему ошибкой компиляции.

**stmt.switch.variant.duplicate** — Вариант НЕ ДОЛЖЕН встречаться больше чем в одном шаблоне одного switch по вариантам.

**stmt.switch.variant.default** — Ветвь `default` разрешена.

**stmt.switch.variant.no-fallthrough** — Switch по вариантам НЕ ДОЛЖЕН содержать оператор `fallthrough`.

### 1.4 Завершающие операторы

**stmt.terminating.variant** — Помимо завершающих операторов спецификации Go, switch по вариантам — завершающий оператор, если:

1. он исчерпывающий без ветви `default` или у него есть ветвь `default`;
2. в нём нет оператора `break`, относящегося к нему; и
3. список операторов каждой ветви заканчивается завершающим оператором.

**Примечание** — Это правило позволяет функции `func Area(s Shape) f64` заканчиваться исчерпывающим `switch` без `return` после него.

## 2. `if` и `for`

**stmt.if-for.go** — Операторы `if`, а также трёхчастная форма и форма с условием у `for` ведут себя как в Go. Тело цикла МОЖЕТ начинаться со строк `invariant`: тело `ForStmt` — это `LoopBody` (*(replaces Go)*, определена в [08-contracts](08-contracts.ru.md)), а не `Block`. Это относится ко всем формам `for`, включая `range` и range-over-func. Тело цикла range-over-func — блок объемлющей функции, а не функциональный литерал: `return`, `break`, `continue` и `go` внутри него относятся к объемлющей функции.

## 3. `range`

### 3.1 Формы из Go

**stmt.range.go** — `range` по массивам, срезам, строкам, словарям, каналам, целым числам и функциям-итераторам ведёт себя как в Go 1.23 с расширением из §3.2.

**stmt.range.copy** — Значения итерации `range` по массиву, срезу, строке или словарю — копии элементов ([06-memory](06-memory.ru.md), **mem.value.copy**). Чтобы изменить элемент, нужно индексировать адресуемый операнд: `xs[i].Increment()`.

### 3.2 Итераторы, выдающие `inout`-доступ

Функция-итератор может выдавать `inout`-доступ к значению. Это механизм, которым контейнеры дают доступ к своим частям ([06-memory](06-memory.ru.md), **mem.part.container**).

**stmt.range.inout-iter** — Помимо типов функций-итераторов Go 1.23, выражение диапазона МОЖЕТ иметь тип вида:

```go
func(yield func(inout V) bool)
func(yield func(K, inout V) bool)
```

**stmt.range.inout** — Когда итератор выдаёт `inout V`, соответствующая переменная цикла — *`inout`-переменная цикла*:

1. она ДОЛЖНА объявляться через `:=` в заголовке `range`; форма с `=` для неё не допускается;
2. в теле цикла она адресуема и обозначает значение, выданное итератором; изменения через неё изменяют это значение;
3. она второго класса ([06-memory](06-memory.ru.md), **mem.ref.second-class**): тело НЕ ДОЛЖНО её сохранять, возвращать, отправлять, преобразовывать в интерфейс, захватывать в замыкание, кроме разрешённого **expr.closure.capture-inout**, или передавать в `go` или `task.Detach`. Чтение даёт копию, на которую таких ограничений нет.

**stmt.range.inout-exclusive** — Пока выполняется тело цикла, итератор держит `inout`-доступ к выданному значению. Применяется **mem.inout.exclusive**: тело НЕ ДОЛЖНО обращаться к выданному значению иначе как через переменную цикла. В частности, тело НЕ ДОЛЖНО обращаться к операнду, из которого получен итератор (например, к `stats` в `range stats.Lock()`), так, чтобы это пересекалось с выданным значением.

**stmt.range.exit** — Выход из тела цикла через `break`, `return`, `goto`, `continue` с меткой внешнего цикла или панику заставляет ожидающий вызов `yield` вернуть `false`, как в Go 1.23. Затем функция-итератор выполняется до конца, включая отложенные вызовы. Поэтому завершающее действие итератора, например снятие блокировки, выполняется при любом выходе из цикла.

```go
for s := range stats.Lock() {
    if s.count == MaxRecords {
        return ErrFull           // итератор снимает блокировку до возврата из Record
    }
    s.count++
}
```

**stmt.range.yield-after-false** — Если итератор снова вызывает `yield` после того, как тот вернул `false`, программа вызывает панику, как в Go 1.23.

**Примечание** — Выдаёт ли итератор доступ один раз (`Lock`, `Edit`) или много раз (все элементы контейнера) — свойство итератора, а не языка.

## 4. `for const`

**stmt.for-const.syntax** — Синтаксис цикла, выполняемого при компиляции:

```
ForConstStmt = "for" "const" ( IdentifierList ":=" ) "range" Expression Block .   (new)
```

Его семантика, включая допустимые выражения диапазона, описана в [10-compile-time](10-compile-time.ru.md).

## 5. `go`

**stmt.go.syntax** — Оператор `go` имеет синтаксис Go. Его семантика — структурированные задачи, эффекты, `inout`-аргументы, распространение ошибок — описана в [09-concurrency](09-concurrency.ru.md).

## 6. `select`

**stmt.select.go** — `select` ведёт себя как в Go. Приём из канала `nil` и отправка в него блокируют навсегда, поэтому канал `nil` отключает свою ветвь, как в Go.

## 7. `defer`

**stmt.defer.go** — `defer` ведёт себя как в Go с правилами ниже.

**stmt.defer.value-args** — Аргументы для параметров-значений отложенного вызова вычисляются и копируются при выполнении оператора `defer`, как в Go.

**stmt.defer.inout-args** — Путь операнда `inout`-аргумента отложенного вызова (например, индекс в `xs[i]`) вычисляется при выполнении оператора `defer`. Сам `inout`-доступ начинается только при выполнении отложенного вызова. Между оператором `defer` и отложенным вызовом программа МОЖЕТ пользоваться операндом как обычно.

**Примечание** — Так же ведёт себя Go с указателями-получателями: `defer f.Close()` видит состояние `f` на момент выполнения `Close`.

## 8. Ошибки и отброшенные результаты

**stmt.error.unused** — Значение типа `error` или любого другого типа, реализующего `error`, полученное из вызова, НЕ ДОЛЖНО отбрасываться неявно. А именно, ошибки компиляции:

1. оператор-выражение, состоящий из вызова, который возвращает хотя бы одно значение-ошибку;
2. оператор `defer`, вызов в котором возвращает хотя бы одно значение-ошибку;
3. присваивание или краткое объявление переменных, принимающее меньше результатов, чем возвращает вызов, если отброшенный результат — значение-ошибка.

**stmt.error.discard** — Значение-ошибка отбрасывается явно присваиванием пустому идентификатору `_`.

```go
Login("alice", wrongPassword)                 // ошибка: результат отброшен неявно
_, _ = Login("alice", wrongPassword)          // разрешено: явное отбрасывание
defer func() { _ = f.Close() }()              // разрешено
```

**stmt.error.go** — Вызов в операторе `go` не отбрасывает свой результат-ошибку: ошибка передаётся вызову-владельцу через `task.Wait`, и программа должна получить её или явно от неё отказаться ([09-concurrency](09-concurrency.ru.md), **conc.task.error**, **conc.struct.error-wait**).

## 9. Присваивания

**stmt.assign.go** — Присваивания ведут себя как в Go. Присваивание логически копирует значение ([06-memory](06-memory.ru.md), **mem.value.copy**). Левый операнд присваивания части значения ДОЛЖЕН быть адресуемым ([04-expressions](04-expressions.ru.md), **expr.addr.def**), кроме индексного выражения словаря `m[k] = v`.

**stmt.assign.overflow** — `++`, `--` и арифметические операторы присваивания следуют **expr.int.checked** и **expr.wrap.ops**.

## 10. `asm`

**stmt.asm.restrictions** — Оператор `asm` МОЖЕТ встречаться только:

1. в пакете профиля `core`;
2. в файле, имя которого имеет суффикс архитектуры ([03-declarations](03-declarations.ru.md)); текст команд записывается в синтаксисе этой архитектуры.

**stmt.asm.syntax** — `asm` — контекстное слово, начинающее оператор `asm`, если за ним в начале оператора следует `(`:

```
AsmStmt = [ ExpressionList "=" ] "asm" "(" [ Expression ] ")" raw_string_lit .   (new)
```

Необязательное выражение — значение-структура, поля которой называют входные регистры, например значение типа `Regs` пакета команд. Необязательная левая часть получает значение-структуру, поля которой называют выходные регистры. Текст команд — сырой строковый литерал, по одной команде в строке в синтаксисе ассемблера архитектуры ([13-targets](13-targets.ru.md), **target.arch.asm-syntax**); строка `name:` объявляет метку, которую могут называть относительные операнды, а `;` начинает комментарий. Поля называют регистры архитектуры; как и в вызовах пакета команд, зарезервированные регистры и регистр флагов ABI не загружаются (**target.arch.instr-package**). Интерпретатор IR не выполняет операторы `asm` (**tool.emu.ir**).

**stmt.asm.effects** — Эффекты оператора `asm` — эффекты его команд по описанию архитектуры ([07-effects](07-effects.ru.md)).

## 11. Блоков `unsafe` нет

**stmt.unsafe.none** — В Anlang нет оператора-блока `unsafe`. Небезопасные операции — функции пакета `an/unsafe` ([06-memory](06-memory.ru.md), **mem.unsafe.package**).
