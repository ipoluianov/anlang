# Открытые вопросы

Сводный указатель подразделов «Открытые вопросы» всех файлов спецификации. Раздел 1 фиксирует все решения; раздел 2 перечисляет вопросы, отложенные до реализации. Открытых вопросов по дизайну нет.

## 1. Решено

Решения от 2026-10-25. Текст правил в файлах спецификации нормативен; из подразделов «Открытые вопросы» эти пункты убраны.

### 1.3 Принятые технические решения

Предварительные технические решения, принятые как записаны, 2026-10-25. Нормативен текст правил в файлах спецификации.

#### 01-lexical
- Неканоническое форматирование — ошибка в любой сборке (**lex.source.canonical**).
- Вызов `requires(x)` в начале тела — строка контракта; иначе пишется `(requires)(x)`.
- `layout` пишется в начальной области объявлений списка полей структуры.
- Нетипизированные рунные константы по умолчанию имеют тип `i32`.

#### 02-types
- Неэкспортируемые варианты экспортируемых enum разрешены; внешнему `switch` нужен `default` (**type.enum.variant-export**).
- Типы с порядком байтов можно использовать везде (**type.endian**).
- Преобразование в `cstring`/`dstring` во время выполнения копирует и паникует на встроенном терминаторе; `ffi.CString(s)` равносилен `cstring(s)` (**type.string.terminator-conv**, **ffi.mem.cstring**).
- Преобразование дробного числа в целое паникует, если значение непредставимо (**type.conv.float-int**).
- Переполнение `fixed` и целочисленных `simd` проверяется, как у целых.
- Структуры с `layout` содержат только простые данные фиксированного размера (**type.layout.fields**).

#### 03-declarations
- Каналов на уровне пакета нет (**decl.var.package-kinds**).
- Имена обработчиков не объявляются ни в какой области видимости (**decl.handler.name**).

#### 04-expressions
- `<<` на проверяемых целых отбрасывает биты, как в Go (**expr.int.shift**).
- Преобразование дробного числа в целое вне диапазона — переполнение (**expr.float.to-int**).
- Целые элементы `simd` проверяются; `*` и `/` у `fixed` округляют к нулю (**expr.known.fixed**).
- Параметр `...any` можно использовать только в `for const`, `len` и при передаче дальше (**expr.call.any-forward**).

#### 05-statements
- `default` в switch по вариантам разрешён (**stmt.switch.variant.default**).
- Отложенные вызовы, возвращающие ошибку, требуют явного отбрасывания.
- Мёртвые записи ошибок под **stmt.error.unused** не подпадают.
- Путь `inout`-операнда в `defer` фиксируется в операторе, доступ начинается при выполнении вызова (**stmt.defer.inout-args**).

#### 06-memory
- Изменение длины `inout`-части среза вызывает панику (**mem.inout.subslice**).
- API арены дополнен `Get` и `Delete`; устаревшие дескрипторы вызывают панику.
- Аренам в `core` для роста нужен `Alloc`; арена фиксированной ёмкости может быть добавлена.
- Значения освобождаются не позже конца области видимости последней копии.

#### 07-effects
- Точные запрещённые эффекты по профилям (**eff.profile.allowed**).
- Функциональные значения, сохранённые в данных, разрешаются по функциональному типу во всей программе.
- `Alloc` добавляется везде, где операция может копировать (**eff.infer.determinism**).
- `Without` у функций с параметрическими ссылками проверяется в объявлении и в каждом вызове (**eff.without.check**).

#### 08-contracts
- `result` есть только у функции с одним безымянным результатом (**contract.expr.result**).
- Инварианты при экспортируемых полях проверяются на границах.

#### 09-concurrency
- `task.LockThread` действует до конца задачи (**conc.os.lock-thread**).
- `RWMutex.RLock()` выдаёт копию (**conc.sync.rwmutex**).

#### 11-data-safety
- Текстовые и структурированные декодеры возвращают `Untrusted`, чтение сырых байтов — нет (**safe.untrusted.sources**).
- API для команды оболочки одной строкой нет (**safe.untrusted.shell**).
- `ExposeSecret` объявлен через `effect.Declare` в `an/secret`.

#### 12-ffi
- Вызов функции недоступной необязательной библиотеки вызывает панику (**ffi.lib.optional**).
- Неразрешённые символы библиотеки C в объектных файлах — ошибка сборки (**ffi.static.unresolved**).
- Строки C возвращаются как `ffi.Handle` и копируются через `ffi.GoString`.
- Колбэков не меньше 1024, они не освобождаются; вызовы из чужих потоков выполняются как задачи (**ffi.callback.lifetime**, **ffi.callback.context**).

#### 13-targets
- Создаются все форматы из `Formats` (**target.format.all**).
- Размещение: первая область с `Exec` и первая без.
- Профили `main` по платформам — таблица в 13.4.
- Цели проекта ищутся по имени каталога (**target.select.resolve**).
- Поля `target.Pointers`: `Flat`, `Near`, `Far`, `Program`.

#### 14-embedded
- Векторы без обработчика вызывают панику по `OnPanic`.
- Тактовая частота — поле `Clock` в `target.Desc`.

#### 15-os
- `PhysAddr`, `VirtAddr` в `an/mm`; ширина задаётся целью.
- Порядок памяти по умолчанию `SeqCst` (**os.smp.atomic**).
- Сигнатуры точки входа задаёт каждая загрузочная платформа (**os.boot.entry**).

#### 16-gpu
- Размер запуска в контрактах — `gpu.GlobalSize()` (**gpu.dispatch.requires**).
- Функции для GPU можно объявлять в любом пакете, допускающем `core` (**gpu.subset.profile**).

#### 17-ui
- Фоновые лимиты сравниваются с описанием платформы (**ui.cap.background**).
- Таблица соответствия эффектов разрешениям справочная; нормативное соответствие — в `an/app`.

#### 18-stdlib
- Обязательный набор: 18.3 плюс 18.3.1 и 18.3.3.
- `an/runtime` нельзя импортировать.
- `an/log` во всех профилях, `an/html` в `app` и `ui`.
- `an/simd` во всех профилях.

#### 19-runtime
- Выпускные и отладочные сборки (**rt.dev.builds**).
- Статус выхода при панике ненулевой.
- Размер стека округляется до выравнивания цели.

#### 20-toolchain
- Статусы выхода 0 / 1 / 2 (**tool.exit-status**).
- Ссылки на тесты в `REQUIREMENTS`: голые имена уникальны, иначе квалифицируются.
- Идентификаторы требований вида `AUTH-3`.
- `anlang diff` принимает два каталога.
- Переход на новую редакцию через `anlang fmt -edition`.
- `anlang flash` сначала собирает (**tool.cmd.flash**).

#### 21-protocol
- Позиции: строка с 1, столбец в байтах с 1.
- Гарантия исправления: диагностика исчезает и новых ошибок не появляется (**proto.diag.fix**).
- Собственные методы отладчика, без Debug Adapter Protocol.

### 1.4 Новые решения

| № | Файл | Вопрос | Решение |
| --- | --- | --- | --- |
| 1 | 02-types, 01-lexical | Нулевое значение параметра-типа | `var x T` и другие использования нулевого значения допустимы; они дают `T` выведенное ограничение «требует нулевого значения», которое распространяется, как сводки эффектов; подстановка типа без нулевого значения — ошибка в точке подстановки с цепочкой до использования; `anlang doc` и `anlang query` показывают ограничение (**type.zero.param-use**, **type.zero.param-constraint**, **type.zero.param-instantiation**, **type.zero.param-tools**) |
| 2 | 10-compile-time, 20-toolchain | Генераторы | Объявляются в `anlang.mod` строкой `generate <генератор> <входы> -> <выходной пакет>`; результат не коммитится, а создаётся в кэше сборки по хэшу генератора и входов; выходной пакет импортируется, как пакет проекта; `anlang gen -show` выводит его; каталог проекта с выходным путём — ошибка (**tool.mod.generate**, **tool.mod.generate.unique**, **tool.cmd.gen**, **ct.gen.declared**, **ct.gen.cache**, **ct.gen.package**, **ct.gen.conflict**) |
| 3 | 18-stdlib | Печать в стандартный вывод | `fmt.Print`, `Println`, `Printf` ничего не возвращают и вызывают панику при сбое записи (эффекты `Console`, `Panic`); `fmt.Fprint*` в `io.Writer` возвращают `(int, error)`, как в Go (**std.fmt.print**, **std.fmt.fprint**, **std.fmt.sprint**) |
| 4 | 18-stdlib | Идентичность ошибок | Ошибки `errors.New` сравниваются по значению (одинаковый текст — равные ошибки); `errors.As` в форме «значение, ok»: `As[T](err) (T, bool)`; рекомендуемая форма ошибок пакета — `enum` с `Error() string`, идентичность от типа (**std.errors.value**, **std.errors.as**, **std.errors.enum**) |
| 5 | 13-targets, 15-os | Цель загрузочного сектора BIOS | Цель `an/target/bios-boot` (i8086, `core`); формат `target.BootSector`: образ по адресу `0x7C00`, не больше 510 байт, дополнение нулями, сигнатура `0x55 0xAA`, файл 512 байт; вход `func main()` с `DS=ES=SS=0`, `SP=0x7C00`; `bios.BootDrive()`; возврат из `main` останавливает процессор (**os.boot.bios**) |
| 6 | 13-targets | Стандартные цели и их имена | Правила имён (ОС: `<платформа>-<архитектура>`; DOS и BIOS — по виду результата; загрузочные: `<среда>-<архитектура>`; микроконтроллеры — по чипу; мобильные — по платформе; `web`) и список из 22 обязательных целей с шагом плана для каждой; для `rp2040` добавлена архитектура `armv6m` (**target.std.name**, **target.std.required**) |
| 7 | 03-declarations | Суффиксы файлов при `_` в имени архитектуры | Суффиксы сравниваются с концом имени файла, а не через разбиение по `_`, поэтому `main_x86_64.an` и `main_linux_x86_64.an` выбираются правильно (**decl.file.suffix**); найдено при реализации драйвера сборки |
| 8 | 02-types | Разделитель полей варианта | Запятые, как в списке параметров: `TooLong{word string, max int}` (**type.enum.fields**) |
| 9 | 20-toolchain | Каноническое форматирование | Стиль gofmt с табами для общей с Go части, сортировка импортов, раскладка конструкций Anlang; каноническая форма — неподвижная точка форматирования; там, где gofmt неидемпотентен, эвристики решают по раскладке вывода (**tool.fmt.style**, **tool.fmt.fixed-point**, **tool.fmt.differences**); значения в anlang.mod выровнены по 9-му столбцу (**tool.mod.format**) |
| 10 | 23-conformance | Расположение набора соответствия на диске | `conformance/testdata/<rule>/`: однофайловые тесты `<name>.an` модуля `conf` и тесты-проекты `<name>/`; ожидаемое множество правил — в одном комментарии `// want:`, другие правила — в `// checks:`; диагностики без правила никогда не совпадают (**conf.suite.layout**) |
| 11 | 02-types, 03-declarations, 04-expressions, 05-statements | Идентификаторы правил для ошибок, унаследованных от Go | Общие правила для того, что «как в Go»: выражения (**expr.go**), операторы, включая метки и отсутствующий return (**stmt.go**), преобразования (**type.conv.go**); неиспользуемые импорты (**decl.import.used**) и неиспользуемые локальные переменные (**decl.var.unused**) — ошибки, как в компиляторе Go; найдено при реализации чекера |
| 12 | 02-types | Приём с отброшенным значением из канала типа без нулевого значения | Допустим: оператор приёма `<-ch` и `case <-ch:` в `select` не используют нулевое значение (**type.zero.chan-receive**); найдено при реализации чекера |
| 13 | 02-types, 04-expressions | Вызов `inout`-метода через неадресуемое значение интерфейса | Допустим: имеет ли динамический метод `inout`-получатель, статически неизвестно; вызов изменяет копию, которую хранит значение интерфейса, и для временного значения она отбрасывается (**type.interface.inout-method**, **expr.method.interface-inout**); найдено при реализации чекера |
| 14 | 06-memory | Вызов параметров функционального типа, например `yield` итераторов | Обязательство — в месте вызова: параметр функционального типа известен как не-nil в своей функции, а аргумент для него должен быть доказанно не-nil; `range` передаёт `yield`, не равный nil; для интерфейсных параметров остаётся **mem.nil.call** (**mem.nil.func-param**); найдено при реализации чекера |
| 15 | 22-compiler, 20-toolchain | Вид IR, его текстовый формат и запуск | SSA с ячейками для переменных, явный `copy` в местах логического копирования и мономорфизация обобщённого кода; текстовый формат из 22.10.2, который выводит `anlang build -ir`; `anlang run -emu ir` выполняет программу в интерпретаторе IR для любой цели, а программа, завершившаяся паникой, выходит с кодом 2 (**tool.cmd.build.ir**, **tool.emu.ir**) |
| 16 | 23-conformance | Ожидаемое поведение эталонных программ и сравнение с Go | Файл `<name>.out` рядом с положительным тестом содержит стандартный вывод и стандартный поток ошибок в порядке записи и последнюю строку `exit status N`; исполняемые («run») программы дистрибутива Go сравниваются в интерпретаторе IR, кроме программ, поведение которых зависит от перечисленного отличия Anlang (**conf.suite.layout**, **conf.reference**, **conf.go.common-subset**) |
| 17 | 06-memory | Неадресуемый первый операнд `copy`, `delete` или `clear`, например `copy(f(), src)` | Запрещён: первый операнд передаётся с `inout`-доступом и должен быть адресуемым; элемент словаря таким не является (**mem.inout.builtin**, **expr.addr.map**); найдено при реализации интерпретатора IR |
| 18 | 04-expressions | Константные выражения циклических типов; `x / -1` для минимального значения знакового циклического типа | Константы циклических типов приводятся по модулю 2ⁿ, а константное преобразование к циклическому типу усекает значение, как для значений; нетипизированная константа без преобразования по-прежнему должна быть представима; `min / -1` даёт `min`, а `min % -1` равно 0, как в Go, поэтому деление на ноль — единственная паника циклической арифметики (**expr.wrap.const**, **expr.wrap.other-ops**); найдено при реализации `an/wrap` |
| 19 | 07-effects | Какие именно операции являются источниками `Alloc`, `Panic` и `Block` и что означает параметрическая ссылка, если аргумент неизвестен | Закрытые списки операций, определяемые синтаксически по типизированному дереву, чтобы две реализации вычисляли одинаковые сводки: запись в элементы среза имеет `Alloc`, потому что буфер может быть разделяемым, преобразования к интерфейсам имеют `Alloc`, кроме скаляров, пустых структур и перечислений без данных, операции с каналами в ветках `select` ждут только как часть `select`; неизвестный аргумент замыкает параметрическую ссылку в открытую ссылку типа параметра, а преобразования между интерфейсными типами передают реализации (**eff.source.alloc-ops**, **eff.source.panic-ops**, **eff.source.wait**, **eff.source.builtin**, **eff.infer.close**, **eff.attr.flow**); найдено при реализации вывода эффектов |
| 20 | 07-effects | У каких функций сообщается нарушение ограничения атрибуции | У каждой функции, где эффект входит в пакет — из источника в её теле или из функции другого пакета; вызывающие функции того же пакета повторно не сообщаются, поэтому один источник даёт одну диагностику на пакет (**eff.constraint.report**); найдено при реализации проверки профилей |
| 21 | 10-compile-time | Конкретные пределы вычислений при компиляции; может ли проект их поднять | 10 000 000 инструкций IR и 16 777 216 значений на вычисление, фиксированы для редакции, не настраиваются (**ct.limit.values**) |
| 22 | 02-types, 07-effects, 08-contracts | Сужающие преобразования: отказ при компиляции (**type.conv.int-narrow**) или проверка во время выполнения (**contract.check.runtime**, **eff.source.panic**) | Отказ, если не доказано; списки проверок во время выполнения называют вместо них преобразования дробных чисел в целые. До решателя доказательства используют закрытый набор интервальных фактов: константы, диапазоны типов, `&` и `%` с константами, `>>` на константу и ключи `range` по известным длинам (**type.conv.int-narrow-facts**); найдено при реализации вычислений при компиляции, где пример CRC из 10.2 требует `u32(i)` |
| 23 | 10-compile-time | Составные литералы в объявлениях констант | Разрешены: составной литерал делает константу вычисляемой, как вызов (**ct.const.call**) |
