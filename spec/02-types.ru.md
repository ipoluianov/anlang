# 2. Типы

Этот файл задаёт систему типов Anlang как разницу относительно спецификации Go, разделы «Types», «Properties of types and values», «The zero value» и «Conversions». Смысл значений во время выполнения (копирование, разделение, `inout`) задан в [06-memory](06-memory.ru.md).

## 2.1 Обзор

**type.go** — Каждый тип из спецификации Go является типом Anlang с тем же смыслом, если этот файл не говорит иного.

Изменения такие:

- новые числовые, строковые типы и типы с порядком байтов (§2.2, §2.3, §2.13);
- объявления условий в структурах (§2.4);
- типы `enum` (§2.5) и `Option[T]` (§2.6);
- отсутствие типов указателей (§2.7);
- ограничения на `any` (§2.9);
- типы-дескрипторы (§2.10);
- ограниченный `nil` (§2.11);
- типы без нулевого значения (§2.12);
- сужающие преобразования на основе доказательства (§2.14);
- известные компилятору библиотечные типы с операциями (§2.15).

## 2.2 Числовые типы

**type.int.fixed** — Предобъявленные целые типы фиксированного размера:

| Тип | Значения |
| --- | --- |
| `i8`, `i16`, `i32`, `i64` | знаковые целые в дополнительном коде размером 8, 16, 32, 64 бита |
| `u8`, `u16`, `u32`, `u64` | беззнаковые целые размером 8, 16, 32, 64 бита |

**type.int.word** — Предобъявленные типы `int` и `uint` — знаковое и беззнаковое целое размером в машинное слово цели (поле `Word` описания цели, [13-targets](13-targets.ru.md)). `int` имеет 16 бит на `i8086`, 32 бита на `armv7m` и `wasm32`, 64 бита на `x86_64` и `arm64`.

**type.int.usize** — Предобъявленный тип `usize` — беззнаковое целое, размер которого равен размеру адресного пространства цели. Длины, ёмкости и индексы массивов, срезов и строк имеют тип `int`, как в Go; `usize` — тип размеров и смещений в памяти.

**type.int.distinct** — Все целые типы различны. Никакие два из них не являются псевдонимами, в том числе `int` и тип фиксированного размера того же размера на данной цели.

**type.float** — Предобъявленные дробные типы — `f32` и `f64`, двоичные binary32 и binary64 по IEEE 754.

**type.float.target** — Описание цели объявляет поддержку дробных чисел как `hard`, `soft` или `none` ([13-targets](13-targets.ru.md)). При `soft` операции над `f32` и `f64` выполняются программно с идентичными результатами. При `none` программа, использующая `f32` или `f64` в коде, достижимом для этой цели, ДОЛЖНА быть отвергнута.

**type.numeric.removed** — Предобъявленных типов Go `int8`, `int16`, `int32`, `int64`, `uint8`, `uint16`, `uint32`, `uint64`, `uintptr`, `float32`, `float64`, `complex64`, `complex128`, `byte` и `rune` в Anlang нет.

**Примечание** — `anlang port` переписывает их: `byte` → `u8`, `rune` → `i32`, `float64` → `f64` и так далее.

**type.numeric.methods** — У предобъявленных типов нет методов. Действия сверх встроенных операций дают обобщённые функции стандартной библиотеки (`bits.WrappingAdd`, `bits.CheckedAdd`, `conv.Narrow`).

## 2.3 Строковые типы

**type.string** — `string` — неизменяемая последовательность байтов с текстом в UTF-8, как в Go. Цикл `range` по `string` выдаёт кодовые точки типа `i32`.

**type.string.cstring** — `cstring` — неизменяемая последовательность байтов, завершённая нулевым байтом, для внешних функций ([12-ffi](12-ffi.ru.md)). Байты перед завершающим НЕ ДОЛЖНЫ содержать нулевой байт.

**type.string.dstring** — `dstring` — неизменяемая последовательность байтов, завершённая символом `$` (0x24), для функций DOS. Байты перед завершающим НЕ ДОЛЖНЫ содержать `$`.

**type.string.terminator-const** — Константа типа `string` или константа типа `[]u8` (результат вычисления при компиляции, [10-compile-time](10-compile-time.ru.md)) присваиваема типам `cstring` и `dstring`. Завершающий байт добавляется при компиляции. Если константа содержит завершающий байт, программа ДОЛЖНА быть отвергнута.

```go
dos.Print(encoding.CP866("Hello from Anlang!\r\n"))   // константа []u8; "$" добавлен при компиляции
```

**type.string.terminator-conv** — Неконстантное значение `string` или `[]u8` преобразуется в `cstring` или `dstring` только явно: `cstring(x)` или `dstring(x)`. Преобразование копирует байты и добавляет завершающий. Если значение содержит завершающий байт, преобразование вызывает панику; поэтому у преобразования есть эффекты `Alloc` и `Panic`, если отсутствие завершающего байта не доказано ([07-effects](07-effects.ru.md)).

## 2.4 Структурные типы

**type.struct.go** — Структурные типы, встроенные поля и теги полей — как в Go.

Список полей структуры МОЖЕТ начинаться с объявлений условий *(replaces Go)*:

```
StructType     = "struct" "{" { StructClause ";" } { FieldDecl ";" } "}" .
StructClause   = InvariantClause | LayoutClause .
LayoutClause   = "layout" LayoutKind .
LayoutKind     = "packed" | "c" .
```

`InvariantClause` определена в [08-contracts](08-contracts.ru.md). Распознавание `invariant` и `layout` как слов условий следует **lex.context.struct-region** ([01-lexical](01-lexical.ru.md)). `packed` и `c` в `LayoutKind` — идентификаторы, распознаваемые только в этой позиции.

**type.struct.invariant** — `InvariantClause` объявляет инвариант типа. Выражение ДОЛЖНО иметь тип `bool` и МОЖЕТ обращаться к полям структуры по имени. Когда и как проверяется инвариант, задано в [08-contracts](08-contracts.ru.md).

**type.struct.layout-once** — Структурный тип ДОЛЖЕН содержать не более одного `LayoutClause`.

```go
type Range struct {
    invariant lo <= hi
    lo, hi int
}

type Header struct {
    layout packed
    magic   u32be
    version u16le
}
```

## 2.5 Типы enum

Тип enum — суммарный тип: значение этого типа — ровно один из его вариантов, и вариант может нести данные.

```
TypeLit      = … | EnumType .                                   (replaces Go)
EnumType     = "enum" "{" { VariantDecl ";" } "}" .               (new)
VariantDecl  = identifier [ "{" [ VariantField { "," VariantField } [ "," ] ] "}" ] .
VariantField = IdentifierList Type .
```

**type.enum.fields** — Поля варианта записываются как список параметров: группы имён с типом через запятую, как в `Rect{w, h f64}` и `TooLong{word string, max int}`. У каждого поля есть имя; `inout` и `...` не допускаются.

```go
type Shape enum {
    Circle{r f64}
    Rect{w, h f64}
}

type Lifecycle enum {
    Launching
    Active
    Inactive
    Background{deadline Duration}
    Terminating
}
```

**type.enum.nonempty** — Тип enum ДОЛЖЕН объявлять хотя бы один вариант. Имена вариантов внутри одного типа enum ДОЛЖНЫ быть различны, и имена полей внутри одного варианта ДОЛЖНЫ быть различны.

**type.enum.defined** — Литерал типа enum МОЖЕТ встречаться только как базовый тип в объявлении типа. Поэтому каждый тип enum — определённый (defined) тип.

**type.enum.generic** — Тип enum МОЖЕТ иметь параметры-типы, как обобщённое объявление типа в Go.

```go
type Option[T any] enum {
    None
    Some{value T}
}
```

**type.enum.variant-scope** — Имя каждого варианта объявляется в области видимости, содержащей объявление типа enum: для enum уровня пакета — в блоке пакета. Два типа enum, объявленных в одном блоке, НЕ ДОЛЖНЫ иметь вариантов с одинаковым именем, и имя варианта НЕ ДОЛЖНО конфликтовать с другим объявлением в этом блоке. Вне объявляющего пакета к варианту обращаются через квалифицированный идентификатор, как к любому другому экспортированному имени: `lifecycle.Active`.

**type.enum.variant-export** — Вариант экспортирован, если экспортировано его имя. Вариант экспортированного типа enum с неэкспортированным именем можно разобрать только внутри объявляющего пакета; вне его `switch` по такому типу не может быть исчерпывающим и поэтому ДОЛЖЕН содержать ветку `default` ([05-statements](05-statements.ru.md)).

**type.enum.value** — Вариант без данных обозначает значение типа enum.

**type.enum.constructor** — Вариант с данными является конструктором: функцией, параметры которой — поля варианта в порядке объявления, а результат — тип enum. Его можно вызвать (`Some(root)`, `Rect(2, 3)`) или использовать как функциональное значение (`camera.ScanBarcode(Scanned)`). Для обобщённого enum аргументы-типы выводятся так же, как при вызове обобщённой функции, или из контекста присваивания.

**type.enum.patterns** — Значения типа enum разбираются исчерпывающим `switch` с шаблонами ([05-statements](05-statements.ru.md)). Поля варианта через селектор недоступны.

**type.enum.comparable** — Тип enum сравним, если сравнимы типы всех полей всех его вариантов. Два значения равны, если это один и тот же вариант и их соответствующие поля равны.

**type.enum.zero** — Нулевое значение типа enum — его первый вариант, если этот вариант не несёт данных. Если первый вариант несёт данные, у типа enum нет нулевого значения (§2.12).

**Примечание** — Представление значений enum задано в [22-compiler](22-compiler.ru.md). `Option[T]` не нуждается в теге, если у `T` есть недопустимый набор битов.

## 2.6 Option и пара «значение, ok»

**type.option.decl** — `Option` — предобъявленный обобщённый тип enum, объявленный как бы так:

```go
type Option[T any] enum {
    None
    Some{value T}
}

func (o Option[T]) Get() (T, bool)
```

`None` и `Some` предобъявлены во вселенском блоке (§2.17).

**type.option.get** — `o.Get()` возвращает значение `Some` и `true` либо нулевое значение `T` и `false` для `None`. `Get` использует нулевое значение `T`, поэтому `T` требует нулевого значения (**type.zero.param-constraint**): для `Option[T]`, у которого `T` без нулевого значения, `Get` отвергается, и `o` ДОЛЖЕН разбираться через `switch`.

**type.option.none-assign** — `None` присваиваем любому типу `Option[T]`. Его аргумент-тип берётся из контекста присваивания; если контекста нет, программа ДОЛЖНА быть отвергнута.

**type.absence.comma-ok** — Результат функции, который может отсутствовать, СЛЕДУЕТ выражать парой «значение, ok» `(T, bool)`, как поиск в словаре в Go; `Option[T]` СЛЕДУЕТ использовать для полей и элементов коллекций.

**Примечание** — Это соглашение для проектирования библиотек; стандартная библиотека ему следует.

```go
user, ok := Find(users, "alice")
if !ok {
    return ErrNotFound
}

if p, ok := n.parent.Get(); ok {
    visit(p)
}
```

## 2.7 Типы указателей и другие составные типы

**type.pointer.removed** — Типов указателей нет. Синтаксис типа `*T` недопустим, встроенной функции `new` не существует.

**Примечание** — Изменение значения вызывающего выполняется через `inout` ([03-declarations](03-declarations.ru.md) §3.8, [06-memory](06-memory.ru.md)); буферы — это срезы; внешние объекты — `ffi.Handle`. Сырые указатели существуют только внутри пакета `an/unsafe` ([06-memory](06-memory.ru.md)).

**type.composite.go** — Типы массивов, срезов, словарей, каналов и функций — как в Go, со следующими изменениями:

- **type.func.inout** — Параметр функционального типа МОЖЕТ быть помечен `inout` (`func(s inout Stats)`) с синтаксисом из [03-declarations](03-declarations.ru.md) §3.8.
- **type.map.value** — Элементы словаря не адресуемы, как в Go.
- **type.chan.handle** — Типы каналов являются типами-дескрипторами (§2.10).

## 2.8 Интерфейсные типы и error

**type.interface.go** — Интерфейсные типы, наборы методов, наборы типов, встраивание, реализация и приведения типов — как в Go.

**type.interface.copy** — Значение интерфейса хранит копию присвоенного ему динамического значения. Последующее изменение оригинала не меняет копию, и наоборот.

**type.interface.inout-method** — Метод с `inout`-получателем входит в набор методов своего типа получателя. Его вызов через значение интерфейса изменяет копию, хранящуюся в значении интерфейса; операнд-интерфейс при этом ДОЛЖЕН быть адресуемым ([04-expressions](04-expressions.ru.md)).

**type.interface.nil** — Нулевое значение интерфейсного типа — `nil`. Вызов метода у значения интерфейса разрешён только там, где доказано, что значение не `nil` (**mem.nil.call**, [06-memory](06-memory.ru.md)).

**type.error** — `error` — предобъявленный интерфейсный тип из Go:

```go
type error interface {
    Error() string
}
```

## 2.9 Тип any

**type.any.positions** — `any` (и равносильный ему `interface{}` с пустым набором методов) МОЖЕТ использоваться только

1. как ограничение типа (`[T any]`) и
2. как тип элемента последнего вариадического параметра `...any`, аргументы которого образуют кортеж, известный при компиляции ([10-compile-time](10-compile-time.ru.md)).

Переменная, поле, результат, элемент или невариадический параметр типа `any` ДОЛЖНЫ быть отвергнуты.

**type.interface.empty-value** — То же ограничение действует для любого интерфейсного типа с пустым набором методов.

## 2.10 Типы-дескрипторы

**type.handle.set** — Типы-дескрипторы:

- типы каналов `chan T`, `chan<- T`, `<-chan T`;
- `sync.Mutex[T]` и `sync.RWMutex[T]` из пакета `an/sync`;
- типы пакета `an/atomic` (`atomic.U32` и подобные).

**type.handle.copy** — Копия значения типа-дескриптора ссылается на тот же объект, что и оригинал. У всех остальных типов семантика значений. Правила разделения, размещения и доступа заданы в [06-memory](06-memory.ru.md) и [09-concurrency](09-concurrency.ru.md).

**type.handle.zero** — Нулевое значение `sync.Mutex[T]`, `sync.RWMutex[T]` и типов `atomic` — готовый объект, содержимое которого — нулевое значение типа содержимого. Нулевое значение типа канала — `nil`.

**Примечание** — `ffi.Handle` не является типом-дескриптором в этом смысле: это непрозрачное значение, обозначающее внешний объект ([12-ffi](12-ffi.ru.md)).

## 2.11 nil

**type.nil.types** — `nil` — предобъявленный идентификатор, обозначающий нулевое значение интерфейсных типов, срезов, словарей и каналов. Он присваиваем этим типам и сравним с их значениями. Значением никакого другого типа он не является.

**type.nil.empty** — Срез и словарь со значением `nil` — пустые значения: `len` возвращает 0, `append` к срезу `nil` и присваивание элементу словаря `nil` работают. Канал со значением `nil` блокирует навсегда при отправке и приёме, как в Go.

**type.nil.no-deref** — Ни одна операция не разыменовывает `nil`. Единственная операция, которая могла бы сделать это в Go, — вызов метода у значения интерфейса `nil` — отвергается при компиляции, если не доказано, что значение не `nil` (**mem.nil.call**).

## 2.12 Нулевые значения

**type.zero.go** — У каждого типа есть нулевое значение, как в Go, кроме типов из **type.zero.none**. Нулевые значения новых типов:

| Тип | Нулевое значение |
| --- | --- |
| `i8`…`u64`, `int`, `uint`, `usize`, типы с порядком байтов | `0` |
| `f32`, `f64` | `0.0` |
| `cstring`, `dstring` | пустая строка (только завершающий байт) |
| тип enum | первый вариант, если он не несёт данных |
| `Option[T]` | `None` |
| типы-дескрипторы | §2.10 |
| интерфейс, срез, словарь, канал | `nil` |
| `Secret[T]`, `Untrusted[T]` | обёртка вокруг нулевого значения `T` ([11-data-safety](11-data-safety.ru.md)) |
| типы `wrap`, `fixed`, `simd` | все биты нулевые |

**type.zero.none** — Следующие типы не имеют нулевого значения:

1. тип enum, первый вариант которого несёт данные;
2. структурный тип с инвариантом типа, который не выполняется для нулевого значения структуры или выполнение которого для него компилятор не может доказать ([08-contracts](08-contracts.ru.md));
3. тип массива, у типа элемента которого нет нулевого значения;
4. структурный тип с полем, у типа которого нет нулевого значения;
5. `Secret[T]` и `Untrusted[T]`, где у `T` нет нулевого значения;
6. конкретизированный обобщённый тип, который после подстановки попадает под пункты 1–5.

**type.zero.uses** — Для типа `T` без нулевого значения программа НЕ ДОЛЖНА содержать операцию, неявно создающую нулевое значение `T`. В частности:

- **type.zero.var** — `var x T` без инициализатора отвергается.
- **type.zero.literal** — Составной литерал структурного типа ДОЛЖЕН задавать каждое поле, у типа которого нет нулевого значения.
- **type.zero.make** — `make([]T, n)` и `make([]T, n, m)` отвергаются, если `n` не константа 0; `make` с ёмкостью остаётся допустимым.
- **type.zero.map-index** — Для словаря с типом элемента `T` однозначное индексное выражение `m[k]` отвергается; допустима только форма `v, ok := m[k]`, и `v` можно использовать только там, где `ok` истинно.
- **type.zero.chan-receive** — Для канала с типом элемента `T` однозначный приём `<-ch` отвергается; допустима только форма `v, ok := <-ch`, потому что приём из закрытого канала выдаёт нулевое значение. Приём, значение которого отбрасывается, — оператор приёма `<-ch` или `case <-ch:` в `select`, — допустим.

**Нулевые значения параметров-типов.** Ограничения «есть нулевое значение» в синтаксисе нет; требование выводится, как сводка эффектов ([07-effects](07-effects.ru.md)).

**type.zero.param-use** — Внутри обобщённой функции или метода операции, создающие нулевое значение параметра-типа `P` (`var x P` без инициализатора, составной литерал с пропущенным полем типа `P`, `make([]P, n)`, однозначные формы индексирования словаря и приёма из канала, `Option[P].Get`), допустимы.

**type.zero.param-constraint** — Такая операция даёт `P` выведенное ограничение *требует нулевого значения*. Ограничение распространяется: если обобщённая функция передаёт свой параметр-тип `Q` как аргумент для параметра, требующего нулевого значения, то и `Q` требует нулевого значения. Ограничение входит в сводку обобщённой функции и вычисляется по пакетам, как сводки эффектов.

**type.zero.param-instantiation** — Подстановка типа без нулевого значения (**type.zero.none**) в параметр-тип, требующий нулевого значения, — ошибка компиляции. Диагностика выдаётся в точке подстановки и ДОЛЖНА показывать цепочку от подстановки до операции, использующей нулевое значение.

**type.zero.param-tools** — `anlang doc` и `anlang query` ДОЛЖНЫ показывать выведенное ограничение каждого параметра-типа ([20-toolchain](20-toolchain.ru.md)).

```go
func Find[T any](xs []T, pred func(T) bool) (T, bool) {
    for _, x := range xs {
        if pred(x) {
            return x, true
        }
    }
    var zero T                 // T: requires a zero value (inferred)
    return zero, false
}

_, _ = Find(shapes, isBig)     // error: Shape has no zero value; Find uses the zero value of T at find.an:7
```

**Примечание** — Для типов enum автор управляет этим порядком вариантов.

## 2.13 Порядок байтов и раскладка

**type.endian** — Предобъявленные типы с порядком байтов: `u16le`, `u16be`, `u32le`, `u32be`, `u64le`, `u64be`, `i16le`, `i16be`, `i32le`, `i32be`, `i64le`, `i64be`. Каждый имеет множество значений и операции целого типа той же знаковости и размера; в памяти он хранится в указанном порядке байтов. Каждый из них — отдельный тип; преобразование в другие целые типы и из них явное и следует §2.14.

**type.layout.default** — Без `LayoutClause` порядок полей, выравнивание и заполнение структуры выбирает компилятор. Программа НЕ ДОЛЖНА на них полагаться.

**type.layout.c** — При `layout c` структура имеет раскладку равносильной структуры C по C ABI цели ([13-targets](13-targets.ru.md)): поля в порядке объявления, с правилами выравнивания цели.

**type.layout.packed** — При `layout packed` поля размещаются в порядке объявления без заполнения.

**type.layout.fields** — Структура с `LayoutClause` ДОЛЖНА иметь поля только целых типов, типов с порядком байтов, дробных типов, массивов, структур с `layout` и типов enum без данных. Поля других типов (срезы, строки, словари, интерфейсы, типы-дескрипторы, функции) отвергаются.

**Примечание** — Раскладка структур с `layout` для буферов GPU и внешних функций используется в [12-ffi](12-ffi.ru.md) и [16-gpu](16-gpu.ru.md).

## 2.14 Присваиваемость и преобразования

**type.assign.go** — Присваиваемость — как в Go, со следующими дополнениями:

- `nil` присваиваем только по **type.nil.types**;
- `None` присваиваем по **type.option.none-assign**;
- константы присваиваемы типам `cstring` и `dstring` по **type.string.terminator-const**;
- нетипизированная целая константа присваиваема типу `wrap`, если она представима соответствующим целым типом;
- нетипизированная числовая константа присваиваема типу `fixed`; значение округляется до ближайшего представимого при компиляции, а при выходе за диапазон программа отвергается.

**type.conv.go** — Преобразования, не описанные в этом разделе, — как в Go.

**type.conv.int-widen** — Преобразование между целыми типами (включая типы с порядком байтов и целые, лежащие в основе типов `wrap`), при котором целевой тип может представить любое значение исходного, разрешено всегда.

**type.conv.int-narrow** — Любое другое преобразование `T(x)` между целыми типами разрешено, только если компилятор доказал, что значение `x` представимо в `T` ([08-contracts](08-contracts.ru.md)). Иначе программа ДОЛЖНА быть отвергнута, а диагностике СЛЕДУЕТ предложить `conv.Narrow[T](x)`, возвращающий `(T, bool)`.

```go
func PutChar(x, y u16, c u8, attr u8) { … }

for i, c := range []u8("HELLO") {
    PutChar(u16(i)+10, 5, c, 0x1E)        // разрешено: i < 5 доказано
}

v, ok := conv.Narrow[u8](n)               // неизвестно, помещается ли n
```

**type.conv.wrap** — Преобразование из любого целого типа в тип `wrap` и из любого типа `wrap` в тип `wrap` разрешено всегда и отбрасывает старшие биты (по модулю 2ⁿ). Преобразование из типа `wrap` в обычный целый тип следует **type.conv.int-widen** и **type.conv.int-narrow** для соответствующего целого типа.

**type.conv.float-int** — Преобразование из дробного типа в целый вызывает панику, если отброшенное до целого значение не представимо в целевом типе, если представимость не доказана. Преобразования из целых типов в дробные — как в Go.

**type.conv.constant** — Преобразования констант — как в Go: значение ДОЛЖНО быть представимо в целевом типе.

**type.conv.string** — Преобразования между `string` и `[]u8` — как в Go. Преобразования в `cstring` и `dstring` следуют §2.3.

**type.conv.no-implicit** — Неявных преобразований между различными неконстантными типами нет.

## 2.15 Известные компилятору библиотечные типы

У некоторых типов стандартной библиотеки есть операции. Во всём остальном это обычные объявленные типы; компилятор знает семантику их операций. Это не перегрузка операций: у пользовательских типов операций быть не может.

**type.known.wrap** — Пакет `an/wrap` объявляет `wrap.U8`, `wrap.U16`, `wrap.U32`, `wrap.U64`, `wrap.I8`, `wrap.I16`, `wrap.I32`, `wrap.I64`. Каждый имеет представление соответствующего целого типа. Операции `+`, `-`, `*`, `<<`, унарный `-` и побитовые операции вычисляются по модулю 2ⁿ и никогда не вызывают панику. `/` и `%` — как у соответствующего целого типа, включая панику при делении на ноль. Операции сравнения определены. Оба операнда бинарной операции ДОЛЖНЫ иметь один и тот же тип `wrap`, кроме счётчика сдвига, который следует Go.

**type.known.simd** — Пакет `an/simd` объявляет векторные типы, такие как `simd.F32x4`, `simd.F64x2`, `simd.I32x4`, `simd.U8x16`. Арифметические операции применяются поэлементно к двум операндам одного векторного типа. Целочисленная поэлементная арифметика следует правилам типа элемента (с проверкой переполнения), если в [18-stdlib](18-stdlib.ru.md) не сказано иное. Скаляры преобразуются в векторы явно (`simd.F32x4Splat(3)`).

**type.known.fixed** — Пакет `an/fixed` объявляет типы с фиксированной точкой, такие как `fixed.Q16` (16.16) и `fixed.Q8` (8.8). Операции `+`, `-`, `*`, `/` и операции сравнения определены для двух операндов одного типа с фиксированной точкой; переполнение проверяется как у целых.

**type.known.closed** — Множество библиотечных типов с операциями — ровно `wrap`, `simd` и `fixed` (**lex.novelty.closed**). У `decimal` и других библиотечных типов есть только методы.

## 2.16 Secret и Untrusted

**type.safety.ref** — `Secret[T]` и `Untrusted[T]` — обобщённые типы стандартной библиотеки, ограничения которых (нет `==`, печать, приёмники) заданы в [11-data-safety](11-data-safety.ru.md). Для целей этого файла это структуроподобные типы с одним полем типа `T`.

## 2.18 Параметры-типы

**type.param.go** — Параметры-типы, ограничения типов, множества типов, инстанцирование и выведение типов — как в Go, со следующими изменениями:

- `any` и другие интерфейсы с пустым набором методов допустимы как ограничения, но не как типы значений (**type.any.positions**);
- интерфейс, множество типов которого ограничено элементами-типами или `comparable`, — только ограничение, как в Go: он НЕ ДОЛЖЕН быть типом значения;
- нулевое значение параметра-типа подчиняется **type.zero.param-use**, **type.zero.param-constraint** и **type.zero.param-instantiation**;
- переключатель типа по значению, тип которого — параметр-тип, разрешается при компиляции (**ct.typeswitch.static**, [10-compile-time](10-compile-time.ru.md));
- обобщённые псевдонимы типов (`type Set[T comparable] = map[T]bool`) допустимы, как в Go 1.24.

Аргумент-тип, не удовлетворяющий своему ограничению, аргумент-тип, который не удаётся вывести, и операция, допустимая не для каждого типа из множества типов параметра-типа, нарушают это правило.

```go
type Number interface {
    ~i32 | ~i64 | ~f64
}

func Sum[T Number](xs []T) T {
    var s T
    for _, x := range xs {
        s += x
    }
    return s
}

total := Sum([]f64{1, 2.5})        // T выведен как f64
_ = Sum[string]                     // ошибка: string не удовлетворяет Number
```
