# 7. Эффекты и профили

Этот файл описывает эффекты: что это такое, откуда они берутся, как компилятор их выводит, кому они засчитываются и где ограничиваются. Здесь же описаны профили — именованные наборы ограничений эффектов для пакетов.

Эффекты никогда не пишутся в сигнатурах функций. Программа ограничивает эффекты только на границах (§7.6).

## 7.1 Модель эффектов

**eff.model.set** — *Эффект* — это имя, обозначающее вид действия, которое функция может выполнить. *Эффекты функции* образуют конечное множество эффектов. Пустое множество означает, что функция не делает ничего, кроме вычислений над своими аргументами и локальными значениями.

**eff.model.identity** — Два эффекта совпадают тогда и только тогда, когда они объявлены одним объявлением: базовым эффектом (§7.2), эффектом, объявленным через `effect.Declare` (§7.7), или эффектом экземпляра периферии (§7.8).

**eff.model.names** — В исходном коде Anlang эффекты — значения типа `effect.Effect` из пакета `an/effect`. Базовые эффекты — экспортируемые константы этого пакета (`effect.Alloc`, `effect.Network`). В `anlang.mod`, в диагностиках и в выводе инструментов эффект записывается голым именем (`Alloc`, `SQL`, `TIM2`); если у двух эффектов программы одинаковое голое имя, инструменты уточняют его путём объявившего пакета.

**eff.model.foreign** — Эффект `Foreign` означает «может делать что угодно». При любой проверке ограничений (§7.6) множество, содержащее `Foreign`, считается содержащим все эффекты.

**Примечание** — В `anlang.md` базовые эффекты записаны без квалификатора (`effect.Without(Alloc, Panic)`, `ffi.Effects{File}`). В исходниках на Anlang каноническая форма — с квалификатором (**eff.model.names**).

## 7.3 Источники эффектов

Эффект попадает в программу только в *источнике*. Все остальные функции получают эффекты от вызываемых функций (§7.4).

**eff.source.primitive** — Примитивы стандартной библиотеки, предоставляемые реализацией (системные вызовы, команды прерываний, выделение памяти, доступ к часам и к случайным числам), несут фиксированные эффекты, указанные в документации каждого примитива.

**eff.source.alloc** — Операция, которая может выделить динамическую память, имеет эффект `Alloc`. Такие операции перечислены в [06-memory](06-memory.ru.md).

**eff.source.panic** — Операция, которая может вызвать панику, имеет эффект `Panic`. Сюда входят проверки переполнения целых, проверки границ индексов и срезов, проверки сужающих преобразований, проверки поколения в аренах и явные вызовы `panic`. Проверка, которую компилятор удалил, потому что решатель доказал, что она не может сработать ([08-contracts](08-contracts.ru.md), **contract.check.runtime**), эффекта не даёт.

**eff.source.wait** — Точка ожидания ([09-concurrency](09-concurrency.ru.md), **conc.wait.points**) имеет эффект `Block`.

**eff.source.go** — Оператор `go` и вызов `task.Go` имеют эффект `Tasks`.

**eff.source.global** — Чтение или запись переменной уровня пакета, включая отображение железа, имеет эффект `Global`.

**eff.source.asm** — Блок `asm` имеет эффекты, которые описание архитектуры объявляет для входящих в него команд ([13-targets](13-targets.ru.md)).

**eff.source.instruction** — Вызов функции из пакета команд архитектуры (`an/arch/...`) имеет эффекты, которые описание архитектуры объявляет для этой команды.

**eff.source.external** — Внешняя функция ([12-ffi](12-ffi.ru.md)) имеет ровно те эффекты, что перечислены в её аргументе `ffi.Effects`. Если аргумент `ffi.Effects` не указан, она имеет эффект `Foreign`. Компилятор не может проверить объявленные эффекты внешних функций; инструменты ДОЛЖНЫ показывать их как непроверенные ([20-toolchain](20-toolchain.ru.md)).

**eff.source.mark** — Вызов `effect.Mark(e)` добавляет эффект `e` функции, содержащей вызов (§7.7).

## 7.4 Вывод и сводки

Эффекты выводит компилятор. Программа никогда не записывает эффекты функции.

**eff.infer.summary** — *Сводка эффектов* функции `f` — это тройка Σ(f) = (C, P, Q):

- C — *конкретные эффекты* `f`: множество эффектов;
- P — *параметрические ссылки* `f`: ссылки вида «эффекты вызова параметра p», «эффекты метода M параметра p» и «эффекты метода M параметра-типа T»;
- Q — *открытые ссылки* `f`: ссылки вида «эффекты метода M интерфейсного типа I» и «эффекты вызова значения функционального типа F» для значений, которые получены не из параметра.

**eff.infer.rules** — Σ(f) — наименьшая (по покомпонентному включению множеств) тройка, удовлетворяющая всем следующим правилам:

1. Каждый источник (§7.3) в теле `f` добавляет свои эффекты в C.
2. Статический вызов `g(a1, …, an)` добавляет C(g) и Q(g) в C(f) и Q(f). Для каждой ссылки из P(g), относящейся к параметру `pi` функции `g`:
   - если аргумент `ai` сам является параметром `f` (или значением-методом параметра), ссылка становится соответствующей ссылкой в P(f);
   - иначе аргумент — конкретное функциональное значение или значение конкретного типа, и сводка соответствующей функции или метода добавляется в Σ(f) по правилу 2 рекурсивно.
3. Вызов через функциональное значение или метод интерфейса, получатель которого — параметр `f`, добавляет соответствующую ссылку в P(f).
4. Вызов через функциональное значение или метод интерфейса, значение которого получено не из параметра `f` (прочитано из поля, элемента, словаря, канала, переменной уровня пакета или из результата), добавляет соответствующую открытую ссылку в Q(f).
5. Вызов метода у значения, тип которого — параметр-тип `T`, добавляет в P(f) ссылку «эффекты метода M типа T».
6. Преобразование в `f` значения конкретного типа `T` к интерфейсному типу `I` добавляет в Σ(f), для каждого метода M из `I`, C и Q метода `T.M` и записывает `T.M` как реализацию открытой ссылки «эффекты метода M интерфейса I» (§7.5).
7. Создание в `f` функционального значения (функционального литерала, значения-метода или имени функции, использованного как значение) типа `F` добавляет C и Q созданной функции в Σ(f) и записывает эту функцию как реализацию открытой ссылки «эффекты вызова значения типа F» (§7.5). Ссылки функционального литерала на захваченные им параметры `f` становятся ссылками в P(f).

**eff.infer.recursion** — Для взаимно рекурсивных функций сводки — наименьшая неподвижная точка правил **eff.infer.rules**.

**eff.infer.generic** — У обобщённой функции одна сводка. При каждой конкретизации ссылки на методы параметров-типов заменяются сводками методов аргументов-типов.

**eff.infer.modular** — Сводка функции зависит только от исходного кода её пакета и от сводок функций импортируемых им пакетов. Она НЕ ДОЛЖНА зависеть от того, кто вызывает функцию.

**eff.infer.determinism** — Вывод эффектов ДОЛЖЕН быть ровно настолько точным, насколько задают эти правила. Реализация НЕ ДОЛЖНА убирать эффект дополнительным анализом, кроме удаления источников `Panic` по доказательствам решателя согласно **eff.source.panic**. Поэтому две соответствующие спецификации реализации вычисляют одинаковые сводки.

**Примечание** — Примеры сводок:

```go
func Fetch(url string) ([]u8, error)                     // C = {Network, Alloc, Block}
func Hash(data []u8) u64                                 // C = {}
func Slice[T any](xs inout []T, less func(a, b T) bool)  // C = {}, P = {less}
func Serve(l Listener, h Handler) error                  // C = {Network, Block, …}, P = {h.ServeHTTP}
```

## 7.5 Атрибуция и эффекты исполнения

Эффекты используются двумя разными способами, и спецификация их различает.

**eff.attr.own** — *Собственные эффекты* функции `f` — это C(f). Эффект функции, переданной как аргумент, засчитывается вызывающему, который её передал, а не вызываемой функции, которая её вызывает (**eff.infer.rules**, пункт 2). Эффект реализации, сохранённой в структуре данных, засчитывается функции, которая преобразовала её к интерфейсу или создала функциональное значение (**eff.infer.rules**, пункты 6 и 7).

**eff.attr.resolve** — В масштабе всей программы открытая ссылка «эффекты метода M интерфейса I» разрешается в объединение эффектов исполнения всех методов `T.M`, записанных как её реализации; открытая ссылка «эффекты вызова значения типа F» — в объединение эффектов исполнения всех функций, записанных как её реализации.

**eff.attr.exec** — *Эффекты исполнения* вызова — это эффекты, которые могут произойти во время его выполнения:

- для функции без параметрических ссылок: X(f) = C(f) ∪ resolve(Q(f));
- для вызова с аргументами X вычисляется после замены каждой параметрической ссылки эффектами исполнения соответствующего аргумента.

**eff.attr.use** — Собственные эффекты проверяются ограничениями атрибуции, эффекты исполнения — ограничениями исполнения. Для каждого ограничения в §7.6 указано, какой вид эффектов оно проверяет.

**Примечание** — Атрибуция сохраняет сводки пакетов честными: у парсера JSON, который вызывает колбэк с доступом к сети, в собственных эффектах нет `Network`. Эффекты исполнения сохраняют корректность гарантий времени выполнения: обработчик прерывания, вызывающий сохранённый колбэк с `Alloc`, нарушает своё ограничение, откуда бы колбэк ни взялся.

## 7.6 Ограничения

Ограничения пишутся только на границах. Каждое ограничение — множество эффектов, которых НЕ ДОЛЖНО быть в ограничиваемом множестве.

| Граница | Ограничиваемое множество | Вид | Правило |
| --- | --- | --- | --- |
| Профиль пакета | собственные эффекты каждой функции пакета | атрибуция | **eff.profile.allowed** |
| `effects` в `anlang.mod` | собственные эффекты каждой функции подходящих пакетов | атрибуция | **eff.mod.deny** |
| `ensures effect.Without(...)` | эффекты исполнения каждого вызова функции | исполнение | **eff.without.check** |
| `interrupt`, `trap` | эффекты исполнения обработчика | исполнение | **eff.handler.implicit** |
| `Provides`, `Lacks` цели | эффекты исполнения программы | исполнение | **eff.target.check** |
| Контексты периферии | эффекты исполнения каждого контекста исполнения | исполнение | [14-embedded](14-embedded.ru.md) |
| Манифест приложения | эффекты исполнения программы | исполнение | [17-ui](17-ui.ru.md) |

**eff.constraint.report** — При нарушении ограничения диагностика ДОЛЖНА назвать ограничение, нарушающий эффект и цепочку вызовов от ограничиваемой функции до источника эффекта, например `TIM2 → buffer.Push → grow → Alloc`.

### 7.6.1 `ensures effect.Without`

**eff.without.form** — `effect.Without(e1, …, en)` — известная компилятору функция пакета `an/effect`. Она МОЖЕТ встречаться только как всё выражение строки `ensures` ([08-contracts](08-contracts.ru.md), **contract.constraint.forms**). Её аргументы ДОЛЖНЫ быть константными выражениями типа `effect.Effect`.

**eff.without.check** — Для функции `f` с `ensures effect.Without(E)`:

1. в объявлении `f` множество X(f), вычисленное без параметрических ссылок, НЕ ДОЛЖНО содержать ни одного эффекта из E;
2. в каждом вызове `f` эффекты исполнения этого вызова НЕ ДОЛЖНЫ содержать ни одного эффекта из E.

### 7.6.2 Обработчики прерываний и ловушек

**eff.handler.implicit** — Функция, объявленная через `interrupt` или `trap`, имеет неявное ограничение `ensures effect.Without(Alloc, Block, Panic)`. Её эффекты исполнения проверяются по **eff.without.check**.

### 7.6.3 Цель

**eff.target.check** — Пусть X — эффекты исполнения программы: объединение эффектов исполнения `main`, каждой функции, запускаемой как задача, и каждого обработчика `interrupt` и `trap`, вместе с отложенными эффектами программы (**eff.deferred.program**). X ДОЛЖНО удовлетворять правилам цели из [13-targets](13-targets.ru.md) §13.3: каждый эффект окружения из X указан в `Provides` цели (**target.effects.provides**), ни один эффект из X не указан в `Lacks` (**target.effects.lacks**), а `Foreign` подчиняется **target.effects.foreign**. Какие эффекты относятся к эффектам окружения, задаёт **target.effects.environment**; остальные эффекты (`Panic`, `Block`, `Global` и свои эффекты) по цели не проверяются (**target.effects.computational**).

## 7.7 Свои эффекты

**eff.custom.declare** — `effect.Declare(name)` — известная компилятору функция. Она МОЖЕТ встречаться только как инициализатор константы уровня пакета. `name` ДОЛЖЕН быть константной строкой. Каждый вызов объявляет отдельный эффект; его идентичность — эта константа (§7.1, **eff.model.identity**), а голое имя — `name`.

```go
package sql

import "an/effect"

const SQL = effect.Declare("SQL")

func (db DB) Query(q string, args ...any) (Rows, error) {
    effect.Mark(SQL)
    …
}
```

**eff.custom.mark** — `effect.Mark(e)` — известная компилятору функция, аргумент которой ДОЛЖЕН быть константой типа `effect.Effect`. Она добавляет `e` в конкретные эффекты функции, в теле которой стоит вызов. Во время выполнения она ничего не делает.

**eff.custom.additive** — Свой эффект никогда не скрывает другие эффекты. Эффекты функции, вызывающей `effect.Mark`, по-прежнему — объединение всех её источников; сетевой вызов за `SQL` сохраняет `Network`.

### 7.7.1 Отложенные эффекты

Функция МОЖЕТ возвращать описание работы, которую рантайм выполнит позже, например `Cmd` профиля `ui` ([17-ui](17-ui.ru.md)). Эффекты этой будущей работы — *отложенные эффекты* функции.

**eff.deferred.declare** — `effect.Defer(e1, …, en)` — известная компилятору функция, аргументы которой ДОЛЖНЫ быть константами типа `effect.Effect`. Она добавляет `e1, …, en` к отложенным эффектам функции, в теле которой стоит вызов. Во время выполнения она ничего не делает и конкретных эффектов не добавляет.

**eff.deferred.attribution** — Отложенные эффекты вызываемой функции засчитываются вызывающей так же, как собственные эффекты (**eff.attr.own**): их видят профили и правила `anlang.mod`. Эффектами исполнения вызывающей они не являются: `effect.Without` и ограничения обработчиков их не видят.

**eff.deferred.program** — Отложенные эффекты всех функций, достижимых в программе, входят в множество эффектов программы. Они проверяются по цели (§7.6.3) и используются для вывода разрешений ([17-ui](17-ui.ru.md)).

## 7.8 Эффекты экземпляров периферии

**eff.periph.instance** — Описание устройства ([14-embedded](14-embedded.ru.md)) объявляет по эффекту на каждый экземпляр периферии (`TIM2`, `USART1`), а там, где железо позволяет независимый доступ, и на каждый пин. Любое обращение к экземпляру, в том числе через копию обозначающего его значения, имеет этот эффект в дополнение к эффекту класса (`Timers`, `Uart`, `Gpio`).

**eff.periph.ownership** — Правила, которые по эффектам экземпляров проверяют исключительное использование в каждом контексте исполнения, описаны в [14-embedded](14-embedded.ru.md).

## 7.9 Профили

Профиль — именованный набор ограничений эффектов и языковых ограничений, который объявляется для пакета строкой `profile` ([03-declarations](03-declarations.ru.md)).

**eff.profile.names** — Профилей три, от самого строгого к наименее строгому: `core` ⊑ `app` ⊑ `ui`.

**eff.profile.allowed** — Собственные эффекты (**eff.attr.own**) каждой функции пакета с профилем p НЕ ДОЛЖНЫ содержать эффектов, которые p запрещает:

| Профиль | Запрещённые эффекты | Дополнительные ограничения |
| --- | --- | --- |
| `core` | `Alloc`, `Detach` | — |
| `app` | `Interrupts`, `Privileged`, эффекты железа (эффекты классов и экземпляров из группы «Железо» в **eff.base.set**) | НЕ ДОЛЖЕН импортировать `an/unsafe`; НЕ ДОЛЖЕН содержать `asm`, объявлений `interrupt` и `trap` |
| `ui` | те же, что у `app` | те же, что у `app` |

**eff.profile.privileged** — `Privileged` по умолчанию закрыт во всех профилях: функция пакета с собственным эффектом `Privileged` отвергается, если `anlang.mod` не разрешает его для этого пакета (**eff.mod.allow**).

**eff.profile.import** — Профили пакета P и импортируемого им пакета Q ДОЛЖНЫ удовлетворять условию: для каждого профиля p, объявленного P, Q объявляет какой-то профиль q, такой что q ⊑ p. Более строгий пакет можно использовать из менее строгого; обратное отвергается.

**eff.profile.multiple** — Пакет МОЖЕТ объявить несколько профилей. Он проверяется для каждого из них; иначе говоря, он ДОЛЖЕН удовлетворять самому строгому из объявленных профилей и правилу импорта для каждого объявленного профиля.

**eff.profile.default** — Пакет без строки `profile` имеет профиль `app`.

```go
package crc

profile core, app, ui
```

**Примечание** — Пакет `crc` выше можно использовать и из прошивки, и из веб-страницы. Пакет `httpclient` с профилем `app` нельзя импортировать из пакета `core`.

**eff.profile.ui** — Дополнительные правила профиля `ui` (устройство `Update` и `View`, доступность в типах, отрисовка) описаны в [17-ui](17-ui.ru.md).

## 7.10 Ограничения эффектов в `anlang.mod`

**eff.mod.syntax** — Блок `effects` в `anlang.mod` содержит записи `<шаблон> deny {<эффекты>}` и `<шаблон> allow {<эффекты>}`. Полная грамматика `anlang.mod` — в [20-toolchain](20-toolchain.ru.md).

**eff.mod.pattern** — Шаблон — путь пакета относительно корня модуля. Шаблон `path` подходит пакету `path`; шаблон `path/...` подходит `path` и всем пакетам под ним; шаблон `...` подходит всем пакетам проекта.

**eff.mod.deny** — Для каждой записи `deny` собственные эффекты каждой функции каждого подходящего пакета НЕ ДОЛЖНЫ содержать ни одного из перечисленных эффектов.

**eff.mod.allow** — Запись `allow` открывает для подходящих пакетов эффекты, закрытые по умолчанию (**eff.profile.privileged**). Запись `allow` НЕ ДОЛЖНА открывать эффект, который запрещает профиль пакета.

**eff.mod.precedence** — Если пакету подходят несколько записей, записи с более длинным шаблоном имеют приоритет перед записями с более коротким; для одного шаблона `deny` имеет приоритет перед `allow`.

```
effects (
    jsonparse/...  deny  {Network, File, Panic}
    kernel/...     allow {Privileged}
)
```

## 7.11 Видимость эффектов

**eff.report.tools** — Реализация ДОЛЖНА делать сводку эффектов каждой функции доступной через `anlang doc`, `anlang query` и протокол среды ([20-toolchain](20-toolchain.ru.md), [21-protocol](21-protocol.ru.md)), включая для каждого эффекта цепочку вызовов до его источника.

**eff.report.diff** — `anlang diff` ДОЛЖЕН показывать эффекты, которые есть у одной версии функции и нет у другой ([20-toolchain](20-toolchain.ru.md)).
