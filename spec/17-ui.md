# 17. User Interfaces and Mobile Applications

This file specifies the `ui` profile: the application model, the UI tree, layout, rendering, platform services, mobile targets, manifests, permissions, the application lifecycle and hot reload.

The same `ui` code runs in the browser, on the desktop, on iOS and Android and in text mode. Only the target and the set of provided effects differ.

## 1. The `ui` profile

**ui.profile.effects** — The `ui` profile permits every effect permitted by `app` and, in addition, the effects of the UI and device-capability packages (section 7). It denies direct hardware access: instance effects of peripherals ([14-embedded](14-embedded.md)), `Interrupts` and `Privileged`.

**ui.profile.calls** — The general rule for calls between profiles applies ([07-effects](07-effects.md)): a `ui` package may call packages that allow `core` or `app`; a package that allows only `core` or `app` MUST NOT call a `ui`-only package.

## 2. Application model

A `ui` application is a state machine. `View` turns the state into a UI tree; `Update` turns the state and a message into a new state and a command.

```go
func Update(s State, m Msg) (State, Cmd) {
    switch m {
    case Inc:   return State{s.count + 1}, cmd.None
    case Dec:   return State{s.count - 1}, cmd.None
    case Reset: return State{0}, cmd.None
    }
}

func View(s State) ui.Node {
    return ui.Column(
        ui.Text(fmt.Sprint("Count: ", s.count)),
        ui.Row(ui.Button("−", Dec), ui.Button("+", Inc)),
    )
}
```

**ui.app.decls** — The main package of a `ui` application MUST declare:

1. a type `State`;
2. an `enum` type `Msg`;
3. `func Update(s State, m Msg) (State, Cmd)`;
4. `func View(s State) ui.Node`.

**ui.app.init** — The initial state is the zero value of `State`. If `State` has no zero value ([02-types](02-types.md)), the main package MUST declare `func Init() (State, Cmd)`, and the initial state and command are its results. A package MAY declare `Init` even when `State` has a zero value.

**ui.view.pure** — `View` MUST be pure: its effect set MUST be a subset of `{Alloc, Panic}`.

**ui.update.pure** — `Update` MUST NOT perform effects other than `Alloc` and `Panic`. Work with other effects is requested by returning a `Cmd`.

**ui.cmd.describe** — A `Cmd` is a description of work, not the work itself. Constructing a `Cmd` (for example `camera.ScanBarcode(Scanned)`) has no effects. The effects that the work will have when the runtime executes it are the *deferred effects* of the constructor; they are declared by the package that defines the constructor with `effect.Defer` ([07-effects](07-effects.md) §7.7.1).

**ui.cmd.deferred** — The deferred effects of every `Cmd` constructor reachable from `Update` or `Init` are part of the effect set of the program. They are subject to effect constraints and are used to derive permissions (section 8).

**ui.cmd.exec** — The runtime executes each returned `Cmd` as a task ([09-concurrency](09-concurrency.md)). When the work completes, its result is delivered as a `Msg` to `Update`. A `Cmd` constructor that produces a result takes a function that turns the result into a `Msg`; an `enum` variant with data can be used as that function (`Scanned` in the example of section 13).

**ui.app.context** — `Init`, `Update` and `View` run only in the main UI context. Messages are processed one at a time in the order of delivery.

## 3. The UI tree

**ui.node.value** — `ui.Node` is an immutable tree value. Unchanged subtrees MAY be shared between successive results of `View`.

**ui.a11y.label** — Every constructor of an interactive element (an element that produces a `Msg` when the user acts on it) in `kern/ui` MUST take a text label, and its contract MUST include `requires len(label) > 0`. An element without a text label therefore does not compile: an empty constant label is rejected directly, and a non-constant label requires a proof that it is not empty ([08-contracts](08-contracts.md)).

**Note** — An element whose visible content is an icon still has a text label; the label is used for accessibility.

## 4. Layout

**ui.layout.constraints** — Layout is specified by constraints between elements and containers, not by styles.

**ui.layout.units** — The layout engine MUST support two unit systems: pixels and character cells. The same tree MUST be laid out in either system without changes to the program.

**ui.layout.deterministic** — Layout MUST be deterministic: the same tree, available area and unit system produce the same positions on every target and machine.

## 5. Rendering

**ui.render.own** — On every target the UI tree is drawn only by the renderer of Kern. The implementation MUST NOT use the platform's native UI elements, except for embedded native views (section 6).

**ui.render.backends** — The implementation provides three kinds of renderer backend:

| Backend | Targets |
| --- | --- |
| GPU | Metal (iOS, macOS), Vulkan (Android, Linux), Direct3D or Vulkan (Windows), WebGPU (browser) |
| Software rasterizer | Microcontroller displays, framebuffers, VGA in DOS |
| Text mode | DOS 80×25, terminals |

**ui.render.equivalence** — For the same tree and size, the GPU backend and the software rasterizer MUST produce images that are equal within a tolerance defined by the conformance suite ([23-conformance](23-conformance.md)).

**ui.render.text** — The renderers that draw glyphs MUST support text shaping of complex scripts and bidirectional text.

## 6. Platform services

The renderer and the layout engine are the same on all targets. A small set of services is taken from the platform through external functions ([12-ffi](12-ffi.md)):

| Service | Platform mechanism |
| --- | --- |
| Accessibility | Export of the UI tree to VoiceOver, TalkBack, ARIA in the browser |
| Text input | System keyboard, IME, autofill |
| System dialogs | File picker, permission requests, clipboard |
| Embedded native view | Map, web page, video player |

**ui.platform.ffi** — Each binding to a platform service has declared effects, like every external function. A direct call of a platform API therefore does not bypass effect constraints.

**ui.platform.native-view** — Embedding a native view is an exception for content that cannot be drawn by the renderer. A native view occupies a rectangle assigned by the layout engine.

## 7. Targets and capabilities

### 7.1 Targets

| Target | Architectures | Output | Bridge to the system |
| --- | --- | --- | --- |
| `web` | wasm32 | `.wasm` module | WebAssembly imports |
| desktop (`linux`, `macos`, `windows`) | x86-64, arm64 | Executable | Dynamic libraries |
| `ios` | arm64 | Mach-O inside `.ipa` | Objective-C runtime through external functions |
| `ios-sim` | arm64, x86-64 | `.app` for the simulator | Same as `ios` |
| `android` | arm64, x86-64 | `.so` inside APK or AAB | JNI function table through external functions |

**ui.aot** — Release builds MUST contain only code compiled ahead of time. They MUST NOT generate or interpret code at run time.

### 7.2 Device capabilities as effects

**ui.cap.effects** — System capabilities are represented by effects: `Camera`, `Location`, `Notifications`, `Contacts`, `Photos`, `Bluetooth`, `Background`, `Network`. The standard library packages that provide these capabilities declare the corresponding effects, directly or as deferred effects of `Cmd` constructors.

**ui.cap.background** — Work performed while the application is in the background state requires effect `Background`. Every task that runs in the background MUST have a deadline that does not exceed the background time limit given by the platform description; the compiler checks this when the deadline is a compile-time constant.

## 8. Permissions

**ui.perm.derive** — For targets with declared permissions, the implementation MUST generate the permission entries from the effect set of the program, including deferred effects: `NS…UsageDescription` entries in `Info.plist` for iOS and `uses-permission` entries in `AndroidManifest.xml` for Android.

**ui.perm.exact** — The generated set of permissions MUST be exactly the set required by the effects. The program MUST NOT add permission entries by other means.

**ui.perm.usage** — For every effect that the target platform requires to explain to the user, `Manifest.Usage` MUST contain a non-empty text for that effect. Otherwise the build fails.

**ui.perm.web** — On the `web` target permissions are requested by the browser at run time; no permission entries are generated.

The mapping from effects to platform entries is defined by `kern/app`. Typical entries (informative):

| Effect | iOS `Info.plist` key | Android permission |
| --- | --- | --- |
| `Camera` | `NSCameraUsageDescription` | `android.permission.CAMERA` |
| `Location` | `NSLocationWhenInUseUsageDescription` | `android.permission.ACCESS_FINE_LOCATION` |
| `Contacts` | `NSContactsUsageDescription` | `android.permission.READ_CONTACTS` |
| `Photos` | `NSPhotoLibraryUsageDescription` | `android.permission.READ_MEDIA_IMAGES` |
| `Bluetooth` | `NSBluetoothAlwaysUsageDescription` | `android.permission.BLUETOOTH_CONNECT` |
| `Notifications` | — (requested at run time) | `android.permission.POST_NOTIFICATIONS` |
| `Network` | — | `android.permission.INTERNET` |

## 9. Manifest

```go
package scanner

import "kern/app"

const Manifest = app.Desc{
    ID:      "com.example.scanner",
    Name:    "Scanner",
    Version: "1.2.0",
    Icon:    "assets/icon.svg",
    Usage: map[Effect]string{
        Camera: "The camera is used to scan barcodes",
    },
    IOS:     app.IOS{MinVersion: "16.0", Team: "ABCDE12345"},
    Android: app.Android{MinSDK: 26},
}
```

**ui.manifest.decl** — For the targets `ios`, `ios-sim` and `android`, the main package MUST declare a package-level constant `Manifest` of type `app.Desc`.

**ui.manifest.fields** — `app.Desc` has the fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `ID` | `string` | Application identifier in reverse domain notation |
| `Name` | `string` | Name shown to the user |
| `Version` | `string` | Version in the form `MAJOR.MINOR.PATCH` |
| `Icon` | `string` | Path to an SVG icon in the project; all required sizes are generated |
| `Usage` | `map[Effect]string` | Usage texts for effects that require them |
| `IOS` | `app.IOS` | `MinVersion` (minimum iOS version), `Team` (Apple team identifier) |
| `Android` | `app.Android` | `MinSDK` (minimum Android API level) |

**ui.manifest.check** — `ID`, `Name`, `Version` and `Icon` MUST be non-empty; `Version` MUST have the stated form; `Icon` MUST name an existing SVG file. Violations are build errors.

## 10. Lifecycle

```go
type Lifecycle enum {
    Launching
    Active
    Inactive
    Background{deadline Duration}
    Terminating
}
```

**ui.lifecycle.enum** — `kern/app` defines the application states as the `enum` type `Lifecycle` above.

**ui.lifecycle.delivery** — The runtime delivers each change of the lifecycle state to `Update` as a message. The program receives these messages by declaring `func OnLifecycle(l app.Lifecycle) Msg` in the main package; if it does not declare it, lifecycle changes are not delivered.

## 11. Build and signing

**ui.sign.ios** — Building for `ios` requires signing with Apple certificates for the team given in `Manifest.IOS.Team`. Signing uses Apple's tools on macOS.

**ui.sign.android** — Building for `android` requires a signing key and the Android SDK.

**ui.build.outputs** — `kern build -target ios` produces an `.ipa`; `kern build -target android` produces an AAB or APK ([20-toolchain](20-toolchain.md)).

## 12. Hot reload

**ui.hot.scope** — Hot reload applies only to debug builds of `ui` programs. Changes to `View`, `Update` and the functions they call are applied to the running program without restart, and the current state is preserved.

**ui.hot.state-change** — If the type `State` changes, the current state cannot be kept as is. The environment MUST either apply a migration function provided by the developer or restart the program.

**ui.hot.mechanism** — The mechanism depends on the target:

| Target | Mechanism |
| --- | --- |
| Browser, desktop, iOS simulator, Android (debug build) | Loading new machine code |
| iOS device (debug build only) | UI code runs in the built-in WebAssembly interpreter and is replaced; slower than a release build |

**ui.hot.release** — Release builds MUST NOT contain hot reload support or the built-in interpreter.

## 13. Example

```go
package scanner

profile ui

import (
    "kern/camera"
    "kern/cmd"
    "kern/ui"
)

type State struct {
    codes []string
}

type Msg enum {
    Scan
    Scanned{code string}
    Clear
}

func Update(s State, m Msg) (State, Cmd) {
    switch m {
    case Scan:          return s, camera.ScanBarcode(Scanned)
    case Scanned{code}: return State{append(s.codes, code)}, cmd.None
    case Clear:         return State{}, cmd.None
    }
}

func View(s State) ui.Node {
    return ui.Column(
        ui.List(s.codes, ui.Text),
        ui.Row(
            ui.Button("Scan", Scan),
            ui.Button("Clear", Clear),
        ),
    )
}
```

`camera.ScanBarcode` has the deferred effect `Camera`. On iOS and Android this produces the camera permission entry and requires `Manifest.Usage[Camera]`; on the web the browser asks for access through `getUserMedia`.

## Open issues

1. **Background limits.** `kern.md` says that the compiler checks background tasks against the platform limits but not how. Provisional: deadlines of background tasks compared with a limit in the platform description (**ui.cap.background**).
2. **State migration function.** Provisional: provided by the developer; its form and how the environment finds it are not specified.
3. **Native views.** Provisional: a node of the UI tree that occupies a laid-out rectangle; the API is to be fixed in [18-stdlib](18-stdlib.md).
4. **Effect to permission mapping.** The table in section 8 is informative; the normative mapping belongs to `kern/app` and the platform descriptions.
5. **`Background` on Android.** The Android counterpart of iOS background modes (foreground services and their permissions) is not specified.
