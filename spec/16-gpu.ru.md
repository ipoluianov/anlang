# 16. Программирование GPU

Этот файл описывает функции для GPU: шейдеры и вычислительные ядра на Kern, правила доступа к данным, запуск и шейдерные цели.

Функция для GPU исполняется многими потоками GPU одновременно. Правила ниже делают гонки данных между этими потоками невозможными по построению. Синтаксис объявления `gpu` — продукция `GpuFunctionDecl` в [03-declarations](03-declarations.ru.md) §3.10.

## 1. Функции для GPU

**gpu.decl.kind** — Функция, объявленная с `gpu`, — *функция для GPU*. Она компилируется для шейдерной цели (раздел 4), а не для процессора цели программы.

**gpu.decl.no-call** — Функцию для GPU НЕ ДОЛЖЕН вызывать напрямую код на процессоре. Она исполняется только через `gpu.Dispatch` (раздел 3).

**gpu.subset.calls** — Функция для GPU МОЖЕТ вызывать только обычные функции, которые удовлетворяют всем правилам этого раздела; такие функции тоже компилируются для шейдерной цели. Тело функции для GPU и каждой вызываемой ею функции НЕ ДОЛЖНО содержать:

1. рекурсию, прямую или косвенную;
2. вызовы через функциональные значения или значения интерфейсов;
3. операторы `go`, `select`, операции с каналами и `defer`;
4. `asm` и использование `unsafe`.

**gpu.subset.effects** — У функции для GPU и у каждой вызываемой ею функции множество эффектов ДОЛЖНО быть пустым, кроме эффектов операций `kern/gpu` из этого файла. В частности, у них НЕ ДОЛЖНО быть `Alloc`, `Block`, `Tasks` и `Panic`; поэтому проверки переполнения и границ ДОЛЖНЫ быть доказаны или обработаны явно ([08-contracts](08-contracts.ru.md)).

**gpu.subset.profile** — Каждый пакет, содержащий функцию для GPU или функцию, вызываемую из неё, ДОЛЖЕН допускать профиль `core` ([07-effects](07-effects.ru.md)).

**gpu.result** — У функции для GPU нет результатов.

## 2. Доступ к данным

### 2.1 Типы параметров

**gpu.param.types** — Каждый параметр функции для GPU ДОЛЖЕН иметь один из следующих типов:

1. *тип данных GPU*: `bool`, целый тип фиксированного размера, `f32`, `f64`, векторный тип `kern/simd`, тип `kern/fixed` или тип массива или структуры, элементы или поля которого — типы данных GPU;
2. срез типа данных GPU (*входной буфер*);
3. `gpu.Out[T]`, где `T` — тип данных GPU (*выходной буфер*).

**gpu.param.layout** — Раскладка типа данных GPU в памяти буферов ДОЛЖНА совпадать на процессоре и на GPU. Реализация выбирает раскладку, удовлетворяющую правилам шейдерной цели, и использует её для типа с обеих сторон. Программе НЕ ДОЛЖНО требоваться описывать раскладку дважды.

### 2.2 Входы

**gpu.in.readonly** — Параметры, кроме выходных буферов, внутри функции для GPU и вызываемых ею функций доступны только для чтения: присваивание параметру, элементу входного буфера или полю параметра — ошибка.

### 2.3 Выходы

**gpu.out.write-only** — Выходной буфер доступен только для записи: единственная допустимая операция над значением типа `gpu.Out[T]` внутри функции для GPU — присваивание `out[i] = v`.

**gpu.out.own-index** — В присваивании `out[i] = v` индекс `i` ДОЛЖЕН быть собственным глобальным номером потока: выражением `gpu.GlobalID().x` или переменной, значение которой решатель доказал равным ему. Любой другой индекс — ошибка.

**Примечание** — Поэтому каждый элемент выходного буфера записывается не более чем одним потоком, и гонок между потоками нет.

**gpu.out.bounds** — Индекс, равный глобальному номеру потока, всё равно может выходить за пределы выходного буфера. Присваивание подчиняется обычным правилам границ: его границы ДОЛЖНЫ быть доказаны или защищены проверкой в теле.

### 2.4 Номер потока

**gpu.id.global** — `gpu.GlobalID()` возвращает глобальный номер исполняющего потока — структуру с полями `x`, `y`, `z` типа `u32`. `gpu.GlobalSize()` возвращает число потоков запуска в том же виде.

**gpu.id.no-requires** — Условие `requires` функции для GPU НЕ ДОЛЖНО ссылаться на `gpu.GlobalID()`: номер потока назначает GPU, и никакой вызывающий код не может обеспечить условие на него. Условия на номер потока проверяются в теле.

## 3. Запуск

```go
gpu.Dispatch(Blur, len(img), img, out)
```

**gpu.dispatch.form** — `gpu.Dispatch(f, n, args...)` исполняет функцию для GPU `f` в `n` потоках, где `n` — неотрицательное целое. `args` ДОЛЖНЫ соответствовать параметрам `f` по числу и типам.

**gpu.dispatch.requires** — Условия `requires` функции `f` МОГУТ ссылаться на её параметры и на `gpu.GlobalSize()`. Они — обязательства доказательства в точке вызова `gpu.Dispatch`: вместо параметров подставляются аргументы, а вместо `gpu.GlobalSize().x` — `n` ([08-contracts](08-contracts.ru.md)).

**gpu.dispatch.sync** — `gpu.Dispatch` возвращает управление после завершения всех потоков. После возврата элементы, записанные в выходные буферы, видны вызывающему коду.

**gpu.dispatch.effect** — У `gpu.Dispatch` эффект `GPU`. Этот эффект допустим только в профилях `app` и `ui` и только на целях, платформа которых его предоставляет.

## 4. Шейдерные цели

**gpu.target.kinds** — Реализация ДОЛЖНА поддерживать следующие шейдерные цели:

| Шейдерная цель | С чем используется |
| --- | --- |
| `spirv` | Vulkan, OpenCL |
| `wgsl` | WebGPU в браузере |
| `msl` | Metal на iOS и macOS |

**gpu.target.select** — Шейдерная цель определяется платформой цели программы: `msl` для iOS и macOS, `wgsl` для веба, `spirv` для остальных платформ, предоставляющих `GPU`.

**gpu.target.embed** — Скомпилированные функции для GPU ДОЛЖНЫ встраиваться в результат сборки программы. Их сборке НЕ ДОЛЖНЫ требоваться внешние компиляторы шейдеров.

## 5. Пример

```go
gpu func Blur(img []simd.F32x4, out gpu.Out[simd.F32x4]) {
    i := gpu.GlobalID().x
    if i == 0 || i+1 >= u32(len(img)) {
        return
    }
    out[i] = (img[i-1] + img[i] + img[i+1]) / simd.F32x4Splat(3)
}
```

## 6. Цели на развитие (справочный раздел)

- Индексы — взаимно однозначные функции от номера потока, доказанные решателем.
- `gpu.Atomic[T]` и разделяемая память рабочей группы `gpu.Shared[T]` для редукций и гистограмм.

## Открытые вопросы


1. **Создание и чтение выходных буферов.** Отложено до реализации — шаг 64. Конструктор с длиной и метод, возвращающий элементы срезом после запуска; имена фиксируются в [18-stdlib](18-stdlib.ru.md).
2. **Семантика дробных чисел и `f64`.** Отложено до реализации — шаг 64. `f64` в функции для GPU — ошибка на шейдерных целях без поддержки `f64`; точные гарантии дробной арифметики фиксируются для каждой шейдерной цели.
3. **Direct3D.** Отложено до реализации — шаг 64. Вычисления на Windows идут через `spirv` и Vulkan; добавлять ли шейдерные цели Direct3D, решается на этом шаге.
