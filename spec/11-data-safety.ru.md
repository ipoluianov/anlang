# 11. Безопасность данных

Область: `safe`.

Два типа-обёртки превращают целые классы уязвимостей в ошибки компиляции:

- `Secret[T]` — для паролей, ключей и токенов;
- `Untrusted[T]` — для данных, пришедших извне программы.

SQL-инъекции, межсайтовый скриптинг, обход путей и пароли в логах становятся невозможными без явного действия, которое находится поиском.

## 11.1 Типы-обёртки

**safe.types.predeclared** — `Secret` и `Untrusted` — обобщённые типы, предобъявленные во всеобъемлющем блоке, как `Option`. Операции над ними предоставляют пакеты `kern/secret` и `kern/untrusted`.

**safe.types.zero** — Нулевое значение `Secret[T]` и `Untrusted[T]` оборачивает нулевое значение `T` (см. [02-types](02-types.ru.md)).

**safe.types.distinct** — `Secret[T]` и `Untrusted[T]` отличны от `T`. Значение типа-обёртки не присваиваемо и не преобразуемо в `T`, а значение `T` не присваиваемо и не преобразуемо в тип-обёртку. Единственные способы войти и выйти — функции, перечисленные в этом файле.

**safe.types.opaque** — У значения-обёртки нет доступных полей, методов `T`, операций и индексации. В частности, `+`, `==`, `<`, `len`, `range`, взятие среза и выбор поля над значением-обёрткой — ошибки компиляции.

**safe.types.meta** — Рефлексия при компиляции считает, что у обоих типов-обёрток нет полей (**ct.meta.opaque** в [10-compile-time](10-compile-time.ru.md)). Поэтому обобщённые сериализаторы не могут прочитать их содержимое.

**safe.types.static-switch** — Статический switch по типу (**ct.typeswitch.static**) МОЖЕТ сопоставлять `Secret[T]` и `Untrusted[T]`. Так функции с `...any` распознают аргументы-обёртки.

## 11.2 `Secret[T]`

| Ограничение | Что это предотвращает |
| --- | --- |
| `fmt` и логгеры печатают его как `***` | пароли в логах |
| нет `==`; сравнение только `secret.Equal` за постоянное время | атаки по времени |
| память затирается нулями при освобождении | секреты в дампах памяти |
| не передаётся в сеть, файлы и UI без `secret.Expose`, у которого эффект `ExposeSecret` | случайное раскрытие |

### 11.2.1 Создание секретов

**safe.secret.new** — `secret.New(x T) Secret[T]` оборачивает значение. Функции стандартной библиотеки, производящие секретный материал, — запрос пароля, генерация ключей, расшифровка файлов ключей — возвращают `Secret[T]`.

### 11.2.2 Производные секреты

**safe.secret.map** — `secret.Map(s Secret[T], f func(T) U) Secret[U]` применяет `f` к содержимому и оборачивает результат. Множество эффектов `f` НЕ ДОЛЖНО содержать эффектов ввода-вывода, железа, `Global`, `Foreign` и `ExposeSecret`. У самого `secret.Map` нет эффекта `ExposeSecret`: производное значение остаётся секретом.

**Примечание** — Хэширование и выработка ключей пишутся через `secret.Map`: `crypto.Hash(pass)` возвращает `Secret[[]u8]` и ничего не раскрывает.

### 11.2.3 Сравнение секретов

**safe.secret.no-eq** — `Secret[T]` несравним. Он НЕ ДОЛЖЕН быть операндом `==` или `!=`, ключом словаря или выражением `switch`.

**safe.secret.equal** — `secret.Equal(a, b Secret[T]) bool` сравнивает содержимое. `T` ДОЛЖЕН быть `string`, `[]u8` или массивом `u8`. Реализация ДОЛЖНА тратить время, зависящее только от длин `a` и `b`, но не от их содержимого.

```go
func Login(user string, pass Secret[string]) (Session, error) {
    hash, err := db.PasswordHash(user)              // Secret[[]u8]
    if err != nil {
        return Session{}, err
    }
    if !secret.Equal(crypto.Hash(pass), hash) {
        return Session{}, ErrDenied
    }
    log.Info("login", user, pass)                   // в лог попадёт: login alice ***
    return newSession(user), nil
}
```

### 11.2.4 Печать секретов

**safe.secret.print** — Каждая функция стандартной библиотеки, форматирующая значения, — `fmt`, `log`, преобразование в строку в `strconv`, кодировщики `json` и других форматов — ДОЛЖНА выводить аргумент `Secret[T]` как три символа `***` независимо от `T` и от глагола формата.

**safe.secret.debugger** — Отладчики и отчёты об аварийном завершении ДОЛЖНЫ показывать значение `Secret[T]` как `***` (см. [20-toolchain](20-toolchain.ru.md), [19-runtime](19-runtime.ru.md)).

### 11.2.5 Раскрытие секретов

**safe.secret.expose** — `secret.Expose(s Secret[T]) T` возвращает содержимое. Каждый вызов `secret.Expose` имеет эффект `ExposeSecret`, который распространяется, как любой другой эффект (см. [07-effects](07-effects.ru.md)). `ExposeSecret` — свой эффект, объявленный через `effect.Declare` в пакете `kern/secret`.

**safe.secret.sinks** — Из-за **safe.types.distinct** `Secret[T]` не может попасть в параметры типа `T` у функций сети, файлов, UI и внешних функций. Функция стандартной библиотеки, принимающая `...any` и пишущая в такой приёмник, ДОЛЖНА отвергать аргументы `Secret[T]` при компиляции через `meta.Reject` (**ct.reject.call**); исключение — функции форматирования, которые печатают `***` по **safe.secret.print**.

**safe.secret.ffi** — `Secret[T]` не является передаваемым типом для внешних функций (см. [12-ffi](12-ffi.ru.md)). Секретный материал передаётся во внешний код только после `secret.Expose`.

### 11.2.6 Затирание секретов

**safe.secret.zero** — Когда память, содержащая представление значения `Secret[T]`, освобождается или переиспользуется, реализация ДОЛЖНА сначала заполнить её нулями. Это касается слотов стека в конце их времени жизни, буферов копирования при записи при освобождении последней ссылки, слотов арен и стеков задач. Оптимизация НЕ ДОЛЖНА удалять это затирание.

**safe.secret.copies** — Копии, созданные семантикой значений, затираются по тому же правилу. Когда компилятор перемещает или копирует представление секрета, он ДОЛЖЕН затереть исходную память, когда она перестаёт использоваться.

**Примечание** — Значения, находившиеся только в регистрах процессора или скопированные внешним кодом после `secret.Expose`, гарантированно затереть нельзя.

## 11.3 `Untrusted[T]`

Всё, что приходит извне программы, стандартная библиотека возвращает как `Untrusted[T]`.

### 11.3.1 Источники

**safe.untrusted.sources** — Следующие функции стандартной библиотеки ДОЛЖНЫ возвращать внешние данные, обёрнутые в `Untrusted`:

- тело HTTP-запроса, параметры запроса, заголовки, cookies и параметры пути;
- данные из файлов, сокетов, стандартного ввода и каналов, прочитанные через текстовые или структурные декодеры (`json`, `csv`, построчное чтение `bufio`);
- переменные окружения и аргументы командной строки;
- пользовательский ввод из текстовых полей UI.

**Примечание** — Чтение сырых байтов через `io.Reader` ради производительности возвращает `[]u8`. Декодеры, превращающие байты в строки или структуры, оборачивают свои результаты.

### 11.3.2 Проверки

*Проверка* превращает `Untrusted[T]` в осмысленный тип или ошибку.

**safe.untrusted.validator** — Стандартная библиотека предоставляет проверки для распространённых типов, например `validate.Email(u Untrusted[string]) (Email, error)` и `fs.SafePath(root Path, u Untrusted[string]) (Path, error)`.

**safe.untrusted.accept** — `untrusted.Accept(u Untrusted[T]) T` возвращает содержимое без проверки. Это единственный способ написать новую проверку. Её вызовы находятся поиском по `untrusted.Accept` и перечисляются `kern query`.

```go
func ParseAge(u Untrusted[string]) (Age, error) {
    s := untrusted.Accept(u)
    n, err := strconv.Atoi(s)
    if err != nil || n < 0 || n > 150 {
        return 0, ErrBadAge
    }
    return Age(n), nil
}
```

### 11.3.3 Приёмники

*Приёмник* — функция, аргумент которой интерпретируется как код или имя ресурса: текст SQL, путь к файлу, HTML, команда оболочки.

**safe.untrusted.sink** — Текстовый параметр приёмника имеет тип `string` (или отдельный тип, например `fs.Path` или `html.Trusted`). По **safe.types.distinct** `Untrusted[string]` передать в него нельзя, а склейка строк с операндом `Untrusted[string]` — ошибка компиляции (**safe.types.opaque**).

**safe.untrusted.params** — Параметры приёмника, которые никогда не становятся частью интерпретируемого текста, МОГУТ принимать `Untrusted[T]`: параметры SQL-запроса, значения HTML-шаблона и вектор аргументов процесса. Приёмник ДОЛЖЕН передавать такие значения отдельно от текста: как связанные параметры, экранированный текст или отдельные аргументы процесса.

**safe.untrusted.html** — Рендеринг HTML в стандартной библиотеке ДОЛЖЕН экранировать каждое подставляемое значение с учётом контекста. Вставка неэкранированной разметки требует значения типа `html.Trusted`, которое нельзя построить из `Untrusted[T]` иначе как через `untrusted.Accept`.

**safe.untrusted.shell** — Стандартная библиотека НЕ ДОЛЖНА предоставлять функцию, запускающую команду оболочки, заданную одной строкой. Процессы запускаются по пути к программе и вектору аргументов; аргументы МОГУТ быть `Untrusted[string]`, путь к программе — НЕ ДОЛЖЕН.

```go
func Search(r http.Request) (http.Response, error) {
    q := r.Query("q")                                          // Untrusted[string]

    rows, err := db.Query("SELECT title FROM docs WHERE title LIKE ?", q)   // параметр: допустимо
    // db.Query("SELECT ... '" + q + "'")                      // ошибка компиляции: + над Untrusted

    if err != nil {
        return http.Response{}, err
    }
    return html.Render(resultsPage, rows), nil                 // экранируется автоматически
}
```

**safe.untrusted.print** — Функции форматирования МОГУТ печатать значения `Untrusted[T]`. Логгеры ДОЛЖНЫ экранировать в них управляющие символы.

## 11.4 Код с постоянным временем

Ограничение `ensures secret.ConstantTime()` записывается как любое ограничение функции; механизм ограничений в `ensures` определён в [08-contracts](08-contracts.ru.md). Этот раздел определяет, чего ограничение требует.

**safe.ct.dependent** — Значение *зависит от секрета*, если оно вычислено из содержимого `Secret[T]`: результат `secret.Expose`, аргумент функции, переданной в `secret.Map`, и любое значение, вычисленное из них по потоку данных.

**safe.ct.branch** — В функции с `ensures secret.ConstantTime()` программа НЕ ДОЛЖНА ветвиться по значению, зависящему от секрета. Это касается условий `if`, `for` и `switch`, операндов `&&` и `||`, `select`, switch по типу и вызовов через функциональные значения или интерфейсы, выбранные значением, зависящим от секрета.

**safe.ct.callees** — Каждая функция, вызываемая из функции с постоянным временем с аргументом, зависящим от секрета, ДОЛЖНА удовлетворять **safe.ct.branch** для этого аргумента. Проверка транзитивна и использует всю программу (граф вызовов — см. [07-effects](07-effects.ru.md)).

**safe.ct.index** *(будущий этап)* — В функции с `ensures secret.ConstantTime()` обращение к памяти, индекс или адрес которого зависит от секрета, станет ошибкой компиляции. Реализации первого этапа НЕ ДОЛЖНЫ отвергать такие обращения; им СЛЕДУЕТ выдавать предупреждение.

**safe.ct.instructions** *(будущий этап)* — Операции, время выполнения которых на цели зависит от значений операндов (например, деление на некоторых процессорах), будут отвергаться для операндов, зависящих от секрета, по модели времени из описания архитектуры (см. [13-targets](13-targets.ru.md)).

## 11.5 Пакеты `kern/log` и `kern/html`

Этот файл задаёт поведение пакетов журналирования и HTML в части безопасности данных; их профили перечислены в [18-stdlib](18-stdlib.ru.md).

**safe.pkg.log** — `kern/log` ДОЛЖЕН форматировать аргументы по правилам `kern/fmt`, включая **safe.secret.print**. В `core` он НЕ ДОЛЖЕН выделять память (**std.core.no-hidden-alloc**).

**safe.pkg.html** — `kern/html` ДОЛЖЕН отрисовывать по **safe.untrusted.html**. `html.Trusted` — его тип для разметки, которая вставляется без экранирования.

## Открытые вопросы

1. **Какое чтение файлов даёт `Untrusted`.** *Предварительно:* текстовые и структурные декодеры оборачивают результат, чтение сырых байтов — нет (**safe.untrusted.sources**).
2. **Приёмники-оболочки.** *Предварительно:* API запуска команды оболочки одной строкой нет вовсе (**safe.untrusted.shell**).
3. **Объявление `ExposeSecret`.** `kern.md` перечисляет его среди своих эффектов. *Предварительно:* объявлен через `effect.Declare` в `kern/secret`; общий механизм — в [07-effects](07-effects.ru.md).
