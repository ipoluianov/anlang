# 10. Вычисления при компиляции

Область: `ct`.

Макросов в Anlang нет. То, что в Go делают `go generate`, рефлексия или текстовые шаблоны, в Anlang пишется на самом Anlang и выполняется компилятором:

- **вычисление при компиляции** обычных функций для получения констант;
- **рефлексия при компиляции** через пакет `an/meta`;
- циклы **`for const`**, которые компилятор разворачивает;
- **параметры `...any`** — кортежи, известные при компиляции, а не срезы интерфейсов;
- **генераторы** — программы на Anlang, которые сборка запускает с доступом только к объявленным файлам.

Ни одна конструкция этого файла не добавляет ключевых слов. `for const` — сочетание существующих ключевых слов; его синтаксис относится к [05-statements](05-statements.ru.md).

## 10.1 Функции, вычислимые при компиляции

**ct.eval.evaluable** — Вызов функции *вычислим при компиляции*, если после подстановки эффектов для точки вызова (см. [07-effects](07-effects.ru.md)) множество эффектов вызова не содержит ничего, кроме:

- `Alloc` и `StaticAlloc` — аллокация при компиляции не имеет смысла и выполняется в памяти компилятора;
- `Panic` — паника во время вычисления является ошибкой компиляции (**ct.eval.panic**);
- `ReadInput` с ограничением из **ct.eval.read-input**.

**ct.eval.no-env** — Вызов, вычисляемый при компиляции, НЕ ДОЛЖЕН иметь других эффектов. В частности, `Clock`, `Random`, `Global`, `Tasks`, `Block`, `Foreign`, любой эффект ввода-вывода и любой эффект железа делают вызов невычислимым.

**ct.eval.read-input** — При вычислении во время компиляции `ReadInput` разрешает читать только файлы внутри каталога пакета, содержащего вычисляемое объявление константы, или его подкаталогов. Путь ДОЛЖЕН быть константой. Содержимое каждого прочитанного файла входит в ключ кэша сборки (см. [22-compiler](22-compiler.ru.md)).

**Примечание** — Именно это делает возможным `svd.Load("STM32F103.svd")` в описании цели (см. [13-targets](13-targets.ru.md)).

**ct.eval.panic** — Если вычисление при компиляции паникует, программа отвергается. Диагностика ДОЛЖНА содержать сообщение паники и стек вызовов вычисления.

## 10.2 Константы, вычисленные функциями

Go ограничивает константы логическими, числовыми и строковыми значениями, заданными константными выражениями. Anlang расширяет объявления констант, не меняя их синтаксис.

**ct.const.call** — Выражение в объявлении константы МОЖЕТ содержать вызовы функций, вычислимых при компиляции, составные литералы и другие вычисляемые константы; такая константа — *вычисляемая константа*. Значение константы — результат вычисления выражения при компиляции. Выражение НЕ ДОЛЖНО использовать переменные.

**ct.const.types** — Константа МОЖЕТ иметь любой тип, значения которого состоят только из:

- логических, числовых и строковых типов, `cstring`, `dstring`;
- массивов, срезов, структур, словарей, значений `enum` и `Option` из таких типов;
- значений интерфейсов, динамическое значение которых имеет такой тип.

Константа НЕ ДОЛЖНА иметь или содержать значение типа синхронизации, функционального типа, `ffi.Handle`, `Secret[T]` или `Untrusted[T]`.

**ct.const.typed** — Константа, вычисленная вызовом функции, является *типизированной константой* типа результата. Правила нетипизированных констант из спецификации Go применяются только к константным выражениям без вызовов, ровно как в Go.

**ct.const.immutable** — Константа, вычисленная функцией, неизменяема. Она НЕ ДОЛЖНА быть операндом `inout`-доступа, присваивания элементу или полю или любого другого изменения. Чтение даёт копию, как для любого значения.

**ct.const.placement** — Реализация ДОЛЖНА размещать константу, вычисленную функцией, в памяти цели только для чтения. На целях с исполняемой незаписываемой областью памяти (flash) её СЛЕДУЕТ размещать там.

**ct.const.order** — Константы МОГУТ зависеть от других констант в любом порядке без циклов. Цикл через инициализаторы констант — ошибка компиляции.

```go
const crcTable = makeCRCTable(0xEDB88320)     // [256]u32 во flash

func makeCRCTable(poly u32) [256]u32 {
    var t [256]u32
    for i := range 256 {
        c := u32(i)
        for range 8 {
            if c&1 == 1 { c = poly ^ (c >> 1) } else { c >>= 1 }
        }
        t[i] = c
    }
    return t
}
```

## 10.3 Пределы вычислений

**ct.limit.bounded** — Реализация ДОЛЖНА ограничивать каждое вычисление при компиляции числом шагов вычисления и памятью. Пределы НЕ ДОЛЖНЫ зависеть от реального времени.

**ct.limit.deterministic** — Для данной версии компилятора и редакции языка пределы и число шагов каждого вычисления ДОЛЖНЫ быть одинаковыми на всех машинах. Компилируется ли программа, НЕ ДОЛЖНО зависеть от машины.

**ct.limit.values** — В редакции языка 1.0 одно вычисление ограничено 10 000 000 исполненных инструкций промежуточного представления ([22-compiler](22-compiler.ru.md), 22.10) и 16 777 216 значений, созданных в срезах, массивах, структурах и словарях. Пределы фиксированы для редакции; проект не может их изменить.

**ct.limit.exceeded** — При превышении предела программа отвергается. Диагностика ДОЛЖНА называть вычисляемую константу, предел и стек вызовов в точке, где предел достигнут.

**ct.eval.semantics** — Вычисление при компиляции ДОЛЖНО давать то же значение, что исполнение того же кода на цели, включая проверки переполнения целых, разрядность целых типов цели (`int`, `uint`, `usize`) и поведение дробных чисел по IEEE 754.

**Примечание** — Поскольку `int` на разных целях разный, константа, вычисленная в арифметике `int`, может отличаться между целями. Она вычисляется отдельно для каждой цели сборки.

## 10.4 Рефлексия при компиляции: пакет `an/meta`

**ct.meta.compile-time-only** — Каждая функция пакета `an/meta`, которая принимает тип или выдаёт описатель типа, вычисляется при компиляции. Её результаты — значения времени компиляции. Информации о типах во время выполнения нет (см. [19-runtime](19-runtime.ru.md)).

Минимальный API:

| Функция или метод | Результат |
| --- | --- |
| `meta.Name(T)` | `string` — имя типа, как оно записано в пакете; пусто для безымянных типов |
| `meta.Fields(T)` | последовательность времени компиляции из `meta.Field`, по одному на поле структурного типа `T`, в порядке объявления |
| `meta.Variants(E)` | последовательность времени компиляции из `meta.Variant`, по одному на вариант типа `enum` `E`, в порядке объявления |
| `f.Name` | `string` — имя поля |
| `f.Index` | `int` — позиция поля |
| `f.Exported` | `bool` |
| `f.Tag` | `string` — тег поля, как в Go |
| `f.Type` | описатель типа, пригодный везде, где ожидается аргумент-тип |
| `f.Get(v)` | значение поля `f` структурного значения `v` со статическим типом `f.Type` |
| `f.Set(v, x)` | присваивает `x` полю `f` значения `v`; `v` — `inout`-параметр |
| `x.Name`, `x.Index` | имя и позиция варианта `x` |
| `x.Fields` | последовательность времени компиляции из `meta.Field` для данных, которые несёт вариант `x` |
| `x.Is(v)` | `bool` — содержит ли значение `enum` `v` вариант `x`; вычисляется во время выполнения |
| `x.Make(...)` | строит вариант `x` из значений его полей по порядку |

**ct.meta.arg-type** — Первый аргумент `meta.Name`, `meta.Fields` и `meta.Variants` — тип, записанный так же, как аргумент-тип. `meta.Fields(T)` — ошибка компиляции, если `T` не структурный тип; `meta.Variants(E)` — ошибка компиляции, если `E` не тип `enum`.

**ct.meta.field-access** — `f.Get(v)` и `f.Set(v, x)` — ошибки компиляции, если `f` — описатель поля типа, отличного от статического типа `v`.

**ct.meta.variant-get** — В коде под проверкой `x.Is(v)` поля варианта читаются через `f.Get(v)` для `f` из `x.Fields`. Чтение поля варианта, который `v` не содержит, вызывает панику.

**ct.meta.visibility** — `meta.Fields(T)` ДОЛЖЕН включать неэкспортируемые поля только при вычислении внутри пакета, объявившего `T`. Вне его перечисляются только экспортируемые поля. `meta` никогда не даёт доступа больше, чем обычный код.

**ct.meta.opaque** — `meta.Fields` и `meta.Variants` ДОЛЖНЫ считать, что у `Secret[T]` и `Untrusted[T]` нет полей. Обобщённый код на основе `meta` не может прочитать их содержимое (см. [11-data-safety](11-data-safety.ru.md)).

```go
func Encode[T any](w inout json.Writer, v T) {
    w.BeginObject()
    for const f := range meta.Fields(T) {
        w.Key(f.Name)
        Encode(w, f.Get(v))
    }
    w.EndObject()
}
```

## 10.5 Циклы `for const`

Синтаксис `for const` *IdentifierList* `:=` `range` *Expression* *Block* определён в [05-statements](05-statements.ru.md). Этот раздел определяет его смысл.

**ct.for.sequence** — Выражение `range` в цикле `for const` ДОЛЖНО быть одним из:

1. последовательность времени компиляции из `an/meta` (`meta.Fields(T)`, `meta.Variants(E)`, `x.Fields`);
2. параметр, объявленный как `...any` (см. 10.6);
3. целая константа `n`, дающая значения `0` … `n-1`;
4. константа типа массива или среза, инициализатор которой — составной литерал из константных выражений, дающая свои элементы; `for const` разворачивается при проверке типов программы, до вычисления вычисляемых констант.

**ct.for.unroll** — Цикл разворачивается при компиляции: тело создаётся по одному экземпляру на каждый элемент последовательности, по порядку. В каждом экземпляре переменная цикла связана с этим элементом.

**ct.for.typecheck** — Каждый экземпляр тела проверяется по типам отдельно; переменная цикла имеет статический тип своего элемента. Ошибка в любом экземпляре — ошибка компиляции с указанием элемента.

**ct.for.binding** — В случаях 1, 3 и 4 переменная цикла — константа. В случае 2 это неизменяемое значение со статическим типом соответствующего аргумента.

**ct.for.control** — `continue` завершает текущий экземпляр. `break` пропускает все оставшиеся экземпляры. `return`, `goto` и помеченные операторы ведут себя как в обычном коде. `defer` в экземпляре выполняется при возврате из объемлющей функции, как в Go.

**ct.for.nesting** — Циклы `for const` МОГУТ быть вложенными. Обычные циклы МОГУТ стоять внутри `for const` и наоборот.

## 10.6 Параметры `...any`

Синтаксис вариадического параметра не меняется по сравнению с Go. Меняется смысл `...any`.

**ct.any.tuple** — Последний параметр, объявленный как `name ...any`, — *кортеж времени компиляции*. В каждой точке вызова число элементов и статический тип каждого аргумента задаются вызовом.

**ct.any.instance** — Функция с параметром `...any` получает по экземпляру на каждую различную последовательность типов аргументов в точках её вызова — так же, как обобщённая функция получает экземпляр на каждый список аргументов-типов.

**ct.instance.check** — Тело функции с параметром `...any`, а также обобщённой функции, тело которой использует `an/meta`, `for const` или `switch` по типу над значением параметра типа, проверяется по одному разу для каждого экземпляра: параметры типа обозначают аргументы-типы, а кортеж — типы аргументов; диагностика экземпляра называет его и вызов, который его породил. Экземпляр, который не порождает ни один вызов, не проверяется. В таком экземпляре, а также в экземпляре тела `for const`, оператор `if` с константным условием проверяется и компилируется только с той ветвью, которую выбирает условие.

**ct.any.use** — Внутри функции параметр-кортеж МОЖНО использовать только:

1. как выражение `range` в `for const`;
2. как последний аргумент вызова другой функции с параметром `...any`, в виде `name...`;
3. как операнд `len(name)`, который является константой.

Любое другое использование — индексация, присваивание, сохранение, преобразование в срез — ошибка компиляции.

**ct.any.no-slice** — Значение `[]T` НЕ ДОЛЖНО передаваться в параметр `...any` в виде `s...`. Каждый аргумент — отдельный элемент кортежа.

**ct.any.effects** — Эффекты вызова вычисляются для его экземпляра, поэтому каждая точка вызова получает ровно эффекты тех типов аргументов, которые она использует (см. [07-effects](07-effects.ru.md)).

### 10.6.1 Статический switch по типу

Статический тип элемента `...any` или значения, тип которого — параметр-тип, известен в каждом экземпляре. Чтобы ветвиться по нему, Anlang разрешает switch по типу для таких значений.

**ct.typeswitch.static** — Операндом switch по типу МОЖЕТ быть значение, тип которого — параметр-тип, или переменная цикла `for const` по кортежу `...any`. Такой switch по типу разрешается при компиляции в каждом экземпляре: компилируется только подходящая ветвь, и только она проверяется по типам с типом ветви. Остальные ветви для этого экземпляра по типам не проверяются.

**ct.typeswitch.binding** — В статическом switch по типу переменная, связанная в охране switch, имеет конкретный тип операнда в этом экземпляре — в том числе в ветвях, перечисляющих несколько типов, и в ветви `default`.

**ct.typeswitch.default** — Если ни одна ветвь не подходит и ветви `default` нет, экземпляр — ошибка компиляции.

```go
func writeValue[T any](b inout strings.Builder, v T) {
    switch x := v.(type) {
    case string:
        b.WriteString(x)
    case int, i64:
        b.WriteString(strconv.Itoa(int(x)))
    default:
        writeStruct(b, x)
    }
}
```

### 10.6.2 Отказ при компиляции

**ct.reject.call** — Вызов `meta.Reject(msg)`, где `msg` — строковая константа, является ошибкой компиляции, если он достижим в экземпляре после разрешения статических switch по типу, развёртывания `for const` и константных условий при компиляции. Ошибка сообщается в точке вызова, породившей экземпляр, с сообщением `msg`.

```go
func (db DB) Query(q string, args ...any) (Rows, error) {
    for const a := range args {
        switch a.(type) {
        case Secret[string], Secret[[]u8]:
            meta.Reject("sql: pass secret.Expose(x) explicitly")
        }
    }
    ...
}
```

**ct.reject.precondition** — Условие `requires` функции с параметром `...any` МОЖЕТ вызывать функции, вычислимые при компиляции, на константных аргументах и на описателях `meta` для кортежа. Если аргументы, от которых оно зависит, в точке вызова константы, условие вычисляется при компиляции; если оно ложно, вызов — ошибка компиляции. Если они не константы, условие — обычное обязательство доказательства (см. [08-contracts](08-contracts.ru.md)).

**Примечание** — Так `fmt` отвергает `%d` для строкового аргумента: у `Sprintf` есть `requires fmt.Valid(format, meta.Types(args))`. Неконстантную строку формата нельзя проверить при компиляции, поэтому предусловие не доказывается — это совпадает с советом `vet` в Go не использовать неконстантные форматы.

### 10.6.3 Размер кода *(справочный)*

Каждая различная последовательность типов аргументов создаёт экземпляр. Чтобы код оставался небольшим, тело функции с `...any` следует делать тонким: цикл `for const` должен только передавать каждый аргумент в общую необобщённую функцию-ядро. Так написаны функции стандартной библиотеки `fmt.Sprint`, `log.Info` и `sql.Query`.

## 10.7 Перекодировка строк при компиляции

Перекодировка константного текста — обычное вычисление при компиляции; у строковых литералов нет префиксов.

**ct.encoding.const** — Если аргумент функции пакета `encoding`, например `encoding.CP866`, — константа, вызов вычислим при компиляции, и его результат — константа типа `[]u8`.

**ct.encoding.unmappable** — Если константный текст содержит символ, который целевая кодировка не может представить, вычисление паникует, и программа отвергается (**ct.eval.panic**).

**ct.encoding.dstring** — Константа типа `[]u8`, не содержащая байта `'$'`, присваиваема типу `dstring`. Присваивание даёт эти байты с добавленным в конце `'$'`. Константа, содержащая `'$'`, типу `dstring` не присваиваема. Сам тип `dstring` определён в [02-types](02-types.ru.md).

```go
dos.Print(encoding.CP866("Hello from Anlang!\r\n"))    // байты CP866, '$' добавлен
```

## 10.8 Генераторы

Генератор превращает внешнее описание — SVD-файл, таблицу системных вызовов — в исходный код на Anlang во время сборки. Привязки к внешним библиотекам генераторов не используют: они объявляются вручную (см. [12-ffi](12-ffi.ru.md)).

**ct.gen.program** — Генератор — пакет `main` проекта в профиле `app`. Сборка запускает его на машине разработчика.

**ct.gen.declared** — Каждый генератор ДОЛЖЕН быть объявлен вместе со своими входными файлами и выходным пакетом директивой `generate` в `anlang.mod` (см. [20-toolchain](20-toolchain.ru.md), **tool.mod.generate**).

**ct.gen.effects** — Множество эффектов генератора НЕ ДОЛЖНО содержать эффектов ввода-вывода, кроме `ReadInput` и `WriteOutput`, и НЕ ДОЛЖНО содержать `Clock`, `Random` и `Foreign`. `ReadInput` разрешает читать только объявленные входные файлы; `WriteOutput` разрешает писать только файлы объявленного выходного пакета. Нарушения — ошибки компиляции генератора, и реализация ДОЛЖНА также обеспечивать их при запуске генератора.

**ct.gen.deterministic** — Генератор ДОЛЖЕН выдавать побайтово одинаковый результат на одинаковых входах. Реализация ДОЛЖНА перезапускать генератор только при изменении хэша его исходников, входов или версии компилятора и ДОЛЖНА иначе использовать кэшированный результат.

**ct.gen.output** — Результат генератора ДОЛЖЕН быть исходным кодом на Anlang в каноническом форматировании (см. [01-lexical](01-lexical.ru.md)). Каждый сгенерированный файл ДОЛЖЕН начинаться с комментария, называющего генератор и хэш его входов. Сгенерированные файлы — обычный исходный код: они проверяются по типам и эффектам и читаются, как любые другие файлы.

**ct.gen.cache** — Результат генератора не входит в проект и не коммитится. Сборка создаёт его в кэше сборки по ключу из хэша исходников генератора, его входов и версии компилятора (**ct.gen.deterministic**).

**ct.gen.package** — Выходной пакет импортируется по объявленному пути, как пакет проекта. `anlang gen -show <пакет>` выводит его исходный код ([20-toolchain](20-toolchain.ru.md), **tool.cmd.gen**).

**ct.gen.conflict** — Каталог проекта с путём объявленного выходного пакета — ошибка компиляции (**tool.mod.generate.unique**).
