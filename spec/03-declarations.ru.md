# 3. Пакеты и объявления

Этот файл задаёт исходные файлы, пакеты, пути импорта, объявление профиля, выбор файлов и объявления как разницу относительно спецификации Go, разделы «Declarations and scope», «Packages» и «Program initialization and execution». Структура проекта и `kern.mod` заданы в [20-toolchain](20-toolchain.ru.md).

## 3.1 Исходные файлы и пакеты

```
SourceFile    = PackageClause ";" [ ProfileClause ";" ] { ImportDecl ";" } { TopLevelDecl ";" } .   (replaces Go)
TopLevelDecl  = Declaration | FunctionDecl | MethodDecl | HandlerDecl | GpuFunctionDecl .            (replaces Go)
```

**decl.package.dir** — Пакет — множество исходных файлов одного каталога, выбранных для текущей цели (§3.4). У всех них ДОЛЖНО быть одинаковое объявление пакета.

**decl.package.name** — Имя в объявлении пакета ДОЛЖНО совпадать с последним элементом пути импорта пакета (§3.2), кроме пакета `main`.

**decl.package.main** — Программа собирается из пакета с именем `main`, который ДОЛЖЕН объявлять `func main()` без параметров и результатов, как в Go. Пакет `main` нельзя импортировать.

## 3.2 Пути импорта

**decl.import.module** — *Имя модуля* объявляется в `kern.mod` ([20-toolchain](20-toolchain.ru.md)). Оно ДОЛЖНО соответствовать `[a-z][a-z0-9_]*` и НЕ ДОЛЖНО быть `kern`.

**decl.import.paths** — Путь импорта ДОЛЖЕН иметь одну из двух форм:

1. `kern/<path>` — пакет стандартной библиотеки, поставляемой с инструментарием ([18-stdlib](18-stdlib.ru.md));
2. `<module>` или `<module>/<path>` — пакет текущего проекта, где `<module>` — имя модуля, а `<path>` — каталог относительно корня проекта.

`<path>` — последовательность элементов, разделённых `/`; каждый элемент ДОЛЖЕН соответствовать `[a-z][a-z0-9_]*`. Любой другой путь импорта, включая сетевой адрес вида `github.com/acme/jsonparse`, ДОЛЖЕН быть отвергнут.

```go
import (
    "kern/arch/i8086"
    "kern/fmt"

    "weather/server"
)
```

**decl.import.name** — Имя пакета в коде — последний элемент пути импорта (по **decl.package.name**), если не задан псевдоним: `import f "kern/fmt"`.

**decl.import.no-blank-dot** — Пустой импорт (`import _ "p"`) и импорт через точку (`import . "p"`) ДОЛЖНЫ быть отвергнуты.

**decl.import.no-cycle** — Граф импортов ДОЛЖЕН быть ациклическим, как в Go.

**decl.import.internal** — Путь импорта, содержащий элемент `internal`, может импортироваться только пакетами, лежащими внутри родителя этого элемента, как в Go. Это относится и к путям `kern/...`, и к путям проекта.

**decl.import.unsafe** — Пакет `kern/unsafe` МОЖЕТ импортировать только пакет, множество профилей которого — ровно `{core}` (§3.3). Импорт этого пакета и есть отметка небезопасного кода; блоков `unsafe` нет ([06-memory](06-memory.ru.md)).

**decl.import.arch** — Пакет команд архитектуры `kern/arch/<a>` МОЖНО импортировать только в исходных файлах с суффиксом архитектуры `<a>` (§3.4).

## 3.3 Объявление профиля

```
ProfileClause = "profile" ProfileName { "," ProfileName } .   (new)
ProfileName   = identifier .
```

```go
package crc

profile core, app, ui
```

**decl.profile.names** — Каждое `ProfileName` ДОЛЖНО быть одним из `core`, `app`, `ui` и НЕ ДОЛЖНО повторяться в объявлении.

**decl.profile.package** — Множество профилей — свойство пакета. Каждый исходный файл пакета, содержащий объявление профиля, ДОЛЖЕН перечислять одно и то же множество. Пакет, ни один файл которого не содержит объявления профиля, имеет множество профилей `{app}`.

**decl.profile.semantics** — Смысл профилей — разрешённые эффекты, правило вызова между профилями и условие объявления нескольких профилей — задан в [07-effects](07-effects.ru.md).

## 3.4 Выбор файлов

Цель сборки выбирается флагом `-target`, а не в коде ([13-targets](13-targets.ru.md)). Код, зависящий от платформы или архитектуры, лежит в файлах с суффиксами, как в Go.

**decl.file.ext** — Исходные файлы имеют расширение `.kn`. Файлы с другими расширениями в каталоге пакета исходными не являются.

**decl.file.ignored** — Файлы, имена которых начинаются с `.` или `_`, игнорируются.

**decl.file.suffix** — Разобьём имя файла без `.kn` по `_` на элементы. Тогда:

1. Если последний элемент — `test`, файл является *тестовым* и включается только при сборке тестов ([20-toolchain](20-toolchain.ru.md)). Перед следующими шагами этот элемент отбрасывается.
2. Если последний элемент — имя архитектуры, а элемент перед ним — имя платформы (`_dos_i8086`), файл включается только для целей с этими платформой и архитектурой.
3. Иначе, если последний элемент — имя архитектуры (`_i8086`) или платформы (`_linux`, `_dos`), файл включается только для целей с этой архитектурой или платформой.
4. Иначе файл включается для любой цели.

**decl.file.names** — Имена платформ и архитектур — это имена из описаний целей, известных сборке: из стандартной библиотеки и из проекта ([13-targets](13-targets.ru.md)). Имя платформы и имя архитектуры НЕ ДОЛЖНЫ совпадать.

**decl.file.profile** — Множество профилей пакета дополнительно ограничивает цели, под которые его можно собрать: пакет ДОЛЖЕН компилироваться для цели, только если цель совместима с одним из его профилей ([07-effects](07-effects.ru.md)). Программа, импортирующая пакет, несовместимый с целью, ДОЛЖНА отвергаться.

## 3.5 Объявления констант

**decl.const.go** — Объявления констант — как в Go, включая `iota`, с расширениями ниже.

**decl.const.compile-time** — Инициализатором константы МОЖЕТ быть любое выражение, которое компилятор может вычислить при компиляции, включая вызовы функций без эффектов ([10-compile-time](10-compile-time.ru.md)). Значение вычисляется один раз при компиляции.

**decl.const.types** — Константа МОЖЕТ иметь любой тип, кроме типов-дескрипторов ([02-types](02-types.ru.md) §2.10), функциональных типов и типов, которые их содержат. В частности, разрешены массивы, структуры, срезы, словари и значения enum. Константа интерфейсного типа или содержащая значения интерфейсов хранит динамические значения, удовлетворяющие тому же правилу.

```go
const crcTable = makeCRCTable(0xEDB88320)    // [256]u32, вычислено при компиляции

const Description = target.Desc{
    Arch:    arch.I8086,
    Formats: []target.Format{target.Flat{Origin: 0x100, MaxSize: 65280}},
}
```

**decl.const.immutable** — Константа составного типа неизменяема: она не адресуема, и `inout`-доступ к ней получить нельзя.

## 3.6 Объявления переменных

**decl.var.local** — Объявления переменных внутри функций — как в Go, с учётом правил о нулевых значениях из [02-types](02-types.ru.md) §2.12.

**decl.var.package-kinds** — Переменная уровня пакета ДОЛЖНА иметь один из следующих типов:

1. тип из пакета `kern/atomic`;
2. `sync.Mutex[T]` или `sync.RWMutex[T]` из пакета `kern/sync`;
3. *отображение железа*: тип значения, созданного `unsafe.Map` ([06-memory](06-memory.ru.md)), или отображение периферии, сгенерированное из описания устройства ([14-embedded](14-embedded.ru.md)). Отображения железа разрешены только в пакетах, множество профилей которых — ровно `{core}`.

Любая другая переменная уровня пакета, в том числе обычного типа или типа канала, ДОЛЖНА быть отвергнута.

```go
var ticks atomic.U32                                          // разрешено
var stats sync.Mutex[Stats]                                   // разрешено
var screen = unsafe.Map[[2000]Cell](i8086.Far(0xB800, 0))     // разрешено в core
var count int                                                 // отвергается
```

**decl.var.package-init** — Инициализатор переменной уровня пакета, если он есть, ДОЛЖЕН вычисляться при компиляции ([10-compile-time](10-compile-time.ru.md)). Без инициализатора переменная содержит нулевое значение своего типа. Порядка инициализации пакетов, который нужно было бы определять, нет.

**decl.var.global-effect** — Обращение к переменной уровня пакета даёт обращающейся функции эффект `Global` ([07-effects](07-effects.ru.md)).

## 3.7 Объявления функций

**decl.func.go** — Объявления функций и методов — как в Go, с изменениями из этого раздела и из §3.8–§3.10.

**decl.func.body** — Каждое объявление функции ДОЛЖНО иметь либо тело, либо привязку (§3.9). Объявлений без тела для реализаций на ассемблере, как в Go, нет.

**decl.func.no-init** — Функция уровня пакета с именем `init` ДОЛЖНА быть отвергнута. Побочных эффектов импорта нет.

**Примечание** — Запрет `init` вместо того, чтобы считать её обычной функцией, не даёт коду на Go, перенесённому без изменений, молча потерять свою инициализацию.

**decl.func.contracts** — Тело функции МОЖЕТ начинаться с контрактных условий (**lex.context.contract-region**, [01-lexical](01-lexical.ru.md)), заданных в [08-contracts](08-contracts.ru.md).

## 3.8 Параметры, получатели и inout

```
ParameterDecl = [ IdentifierList ] [ "inout" ] [ "..." ] Type .   (replaces Go)
Receiver      = Parameters .
```

**decl.param.inout** — Параметр с пометкой `inout` даёт функции временный исключительный изменяемый доступ к значению вызывающего. Смысл `inout` задан в [06-memory](06-memory.ru.md); требования к аргументам — в [04-expressions](04-expressions.ru.md).

**decl.param.inout-variadic** — `inout` и `...` НЕ ДОЛЖНЫ сочетаться в одном параметре.

**decl.param.inout-result** — Результаты НЕ ДОЛЖНЫ помечаться `inout`.

**decl.receiver.base** — У получателя ровно один параметр. Его тип ДОЛЖЕН быть определённым типом `T` или конкретизацией обобщённого определённого типа, объявленного в том же пакете; `T` НЕ ДОЛЖЕН быть интерфейсным типом. Получатель — либо получатель-значение, либо `inout`-получатель:

```go
func (r Range) Len() int            { return r.hi - r.lo }
func (s inout Server) Handle(r Request) { s.count++ }
```

**decl.receiver.method-set** — Набор методов `T` содержит методы и с получателями-значениями, и с `inout`-получателями. Метод с `inout`-получателем изменяет значение вызывающего и может вызываться только на адресуемом операнде ([04-expressions](04-expressions.ru.md)).

**decl.param.func-types** — `inout` МОЖЕТ встречаться в параметрах функциональных типов и функциональных литералов: `func(s inout Stats)`, итераторы, выдающие `inout`-доступ ([05-statements](05-statements.ru.md)).

## 3.9 Объявления внешних функций

```
FunctionDecl = "func" FunctionName [ TypeParameters ] Signature [ FunctionBody | Binding ] .   (replaces Go)
Binding      = "=" Expression .                                                           (new)
```

```go
func sqlite3_open(path cstring, db inout ffi.Handle) i32 = lib.Symbol("sqlite3_open", ffi.Effects{File})
```

**decl.extern.binding** — Объявление функции с `Binding` и без тела — *внешняя функция*. Выражение привязки ДОЛЖНО вычисляться при компиляции и ДОЛЖНО иметь тип привязки из пакета `kern/ffi` или `kern/js` (`lib.Symbol(...)`, `ffi.At(...)`, `js.Import(...)`), как задано в [12-ffi](12-ffi.ru.md).

**decl.extern.no-generic** — Внешняя функция НЕ ДОЛЖНА иметь параметров-типов.

**decl.extern.no-method** — Объявление метода НЕ ДОЛЖНО иметь привязки.

**decl.extern.semantics** — Допустимые типы параметров, эффекты, ограничения вызова и загрузка заданы в [12-ffi](12-ffi.ru.md).

## 3.10 Объявления обработчиков и функций для GPU

```
HandlerDecl     = ( "interrupt" | "trap" ) HandlerName Signature FunctionBody .   (new)
HandlerName     = identifier .
GpuFunctionDecl = "gpu" FunctionDecl .                                            (new)
```

```go
interrupt TIM2() {
    device.TIM2.ClearUpdateFlag()
    ticks.Add(1)
}

trap PageFault(frame inout TrapFrame, code PageFaultCode) { … }

gpu func Blur(img []simd.F32x4, out gpu.Out[simd.F32x4]) { … }
```

Распознавание `interrupt`, `trap` и `gpu` следует **lex.context.positions** ([01-lexical](01-lexical.ru.md)).

**decl.handler.name** — `HandlerName` называет вектор прерывания или исключения цели; оно не объявляется ни в одной области видимости, и его нельзя вызвать или сослаться на него. Допустимые имена и сигнатуры определяются описаниями цели и устройства.

**decl.handler.no-generic** — У объявлений обработчиков нет параметров-типов и получателя.

**decl.handler.semantics** — Семантика обработчиков `interrupt` задана в [14-embedded](14-embedded.ru.md), обработчиков `trap` — в [15-os](15-os.ru.md).

**decl.gpu.body** — `GpuFunctionDecl` ДОЛЖНО иметь тело; оно НЕ ДОЛЖНО быть методом или внешней функцией. Его семантика задана в [16-gpu](16-gpu.ru.md).

## 3.11 Видимость

**decl.visibility.go** — Экспортированные идентификаторы и правила областей видимости — как в Go. Варианты enum следуют **type.enum.variant-export** ([02-types](02-types.ru.md)).

## Открытые вопросы

1. **Каналы на уровне пакета.** Предварительно: запрещены (**decl.var.package-kinds**).
2. **Имена обработчиков.** Предварительно: не объявляются ни в одной области видимости (**decl.handler.name**).
